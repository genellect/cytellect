# 解析基盤の費用と制約

確認日: 2026-10-03 JST。比較段階であり、新規契約・課金設定・ホスト移行は行っていない。価格は米ドル表記を維持し、為替・税を固定しない。無料枠の継続や実際の請求額は保証しない。

## 現在の実装判断

低額クラウド構成の受入検証が完了していないため、利用者の指示に基づき、先にローカル実行版を実装する。UIはブラウザに統一し、後から解析先をクラウドへ移す前提を維持する。以下はクラウド移行時の比較であり、常時稼働VPSや各利用者の手動環境構築を必須化しない。

## 比較の判断軸

少人数・断続的なPoCなら、常時稼働VPSを前提にする必要はない。まず利用時だけ起動するクラウドを検討する。許容する制約は、起動待ち、同時実行1、解析量の上限、標準URL、24時間保存。原画素、統計手法、アクセス制御を費用削減の対象にはしない。

クラウドの少額従量課金も許容できない場合は、運営側の既存PCを共用解析サーバーにする案が次候補となる。利用者ごとのインストールは不要だが、運営PCの電源・回線・更新管理に依存する。各利用者へのローカル導入は、その後の選択肢とする。

## 計算料金の例

比較用の仮定は「月100回、各10分、2 vCPU相当、8 GiBメモリ」。これは実行時間を仮定した料金計算であり、100画像を必ずその時間で処理できるという測定結果ではない。再試行、起動時間、API、待機時間、DB、保存、通信は別に加算する。

| 項目 | 計算 | 無料枠適用前 | 枠が未使用の場合 |
|---|---|---:|---:|
| Cloud Run Jobs: CPU | 120,000 vCPU秒 × $0.000018 | $2.16 | 240,000 vCPU秒の枠内 |
| Cloud Run Jobs: メモリ | 480,000 GiB秒 × $0.000002 | $0.96 | 450,000 GiB秒を超える分が$0.06 |
| Modal Function: 1物理コア＋8 GiB | 60,000秒 × ($0.0000131＋8×$0.00000222) | $1.8516 | $30の計算枠内 |

Cloud Runはus-central1の基準単価で、無料枠は請求先アカウント単位。他の利用と共有され、実際のリージョンで価格が変わる。Modalは要求量と実使用量の大きい側で課金され、起動・終了前の待機も対象となる。8 GiBを仮定した料金表は、4096²画像の動作保証ではない。

この規模では計算料金そのものより、常設サービスの基本料や設計上の待機時間が費用を左右しやすい。クラウド全体を「月$0.06」と案内してはいけない。

## 総費用から外してはいけない項目

- **UI:** Vercel Hobbyは個人・非商用向け。無償PoCというだけで対象と判断しない。商用目的でVercelを継続する場合、Proは月$20からとなり、解析側が無料でも固定費が残る。低額優先ならUIとAPIを同じクラウド標準URLへ置く案、または公開入口の静的配信先を見直す案を比較する。現在のVercel公開先は変更していない。[Hobby](https://vercel.com/docs/plans/hobby)、[料金](https://vercel.com/pricing)
- **DB:** サーバーレス化しても解析版・権限・ジョブ状態は永続化する。Neonには無料Postgres枠があるが、容量だけでなく稼働時間・ポーリングの影響も確認する。画像をDBに保存しない。現時点では未導入。[無料枠の容量改定](https://neon.com/blog/neon-free-plan-1-gb-per-project)
- **画像・成果物:** 24時間保持でも一時保管・取得・削除操作は発生する。原画像を出力ZIPへ既定で含めない。Modal Volumeには無料容量枠があるが、SQLiteを置く共有ディスクとして扱わない。[Volume](https://modal.com/docs/guide/volumes)、[Cloud Storage料金](https://cloud.google.com/storage/pricing)
- **イメージ保管・ビルド:** Fiji・Java・モデルを含むコンテナの保管と更新分を数える。古いイメージを無制限に残さない。[Artifact Registry料金](https://cloud.google.com/artifact-registry/pricing)
- **転送:** アップロード量だけでなく、プレビュー・マスク・図・ZIPのダウンロードを数える。無料枠を東京でも同じと推測しない。
- **ドメイン:** 標準HTTPS URLなら新規ドメイン購入を省ける。別々のVercel/解析基盤の標準ドメインでは現在のStrict Cookie認証は成立しない。同一オリジン配置か、同じ管理ドメイン配下を用意する。第三者Cookieへの切り替えを安易な解決策にしない。

## 低料金化とデータ保護の整合

ModalのFunctions/Web Functionsは入力・出力を最大7日保持する。通常のASGI Functionへ研究画像を直接送る案は、24時間削除と両立したことにならない。別のServers方式はHTTPペイロードを保存しない仕様だが、起動直後の503と再試行、料金枠、永続化を別途検証する。Functionワーカーを使う場合も、引数・戻り値は内部IDと状態に限定し、研究内容を関数結果へ返さない。[セキュリティ](https://modal.com/docs/guide/security)、[Servers](https://modal.com/docs/guide/servers)

Cloud Storageを使う場合、標準のsoft deleteは7日である。専用の一時研究データ用バケットを、最初のアップロード前からsoft delete無効・世代管理無効・保持ロックなしで設定する必要がある。期限時のアクセス遮断と明示的削除を実装し、日次ライフサイクルだけを24時間削除の根拠にしない。[soft delete](https://docs.cloud.google.com/storage/docs/soft-delete)

予算上限と削除は別の仕組みが必要になる。上限で全処理を止め、削除処理まで止まる設計にしない。課金上限は通知だけか実停止かを確認し、報告遅延による超過も扱う。Cloud RunにはPreviewの停止付き予算があるが、超過額が完全にゼロになる保証ではなく、関連サービス全部も停止しない。[予算と上限](https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps)、[Modal課金](https://modal.com/docs/guide/billing)

## 現在の性能と許容する制限

[実測](resource-benchmark.md)では公開NCL画像1536×1739 pxの処理が52.620秒、Python＋Javaの最大RSS合計が1.716 GiBだった。ローカルWindowsでの観測であり、クラウドの所要時間ではない。4096²の容量試験は2 GiB・4 GiBのJavaヒープ双方で失敗した。大きいVMを契約するだけでこの問題が解消すると案内しない。

低予算PoCでは自動検出の受付サイズ、直列処理、月間計算枠を明示する。上限超過時は理由を示し、黙って縮小・画素変換・対象除外をしない。画像サイズ制限と、研究者が定義した標本の統計的な採否は別である。

## 次の実装順

1. 計算値・図・アクセス制御・Fijiの検証を維持し、サイズ超過を実行前に検出する。
2. Cloud Runを第一の低額クラウド検証候補、Modalを保持仕様確認付きの比較候補とする。料金計算にAPI・DB・一時保存・通信・レジストリを加える。
3. 24時間削除、計算中断、再試行、所有権、通信制限を満たす永続化・実行方式を用意する。現在のSQLiteを共有ネットワークディスクへそのまま移さない。
4. 公開画像だけで実ホストの時間・課金対象量・削除・ブラウザ操作を確認してから、非公開画像の受付を開く。
5. 費用上限や稼働制約が合わない場合は、既存PC1台の共用サーバー案と比較する。各利用者へのローカル導入は必須化しない。
