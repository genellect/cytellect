# 公開画像での検証：核ごとの画素の信号の指標

genellect/cytellect#257（E-7、RP-01・RP-02）の実装案（[implementation.md](drafts/nucleolar-measurement/implementation.md)）の PR 6 と決定 23。核ごとの画素の変動係数（CV）と陽性面積率を、製品の共通実装（`cytellect_analysis.nuclear_features`、nuclear-features/1.0.0）で計算し、統計の指標として出せるかを、値を見る前に決めた規則で確かめた。集計は [tuning.json](../fixtures/public/nuclear-signal/tuning.json) と [evaluation.json](../fixtures/public/nuclear-signal/evaluation.json) にある。

## 結論

| 指標 | 核染色（NucBlue） | NPM1 | FBL | 5-EU | 製品 |
|---|---|---|---|---|---|
| 画素の CV（背景補正） | 不合格 | 不合格 | 不合格 | 不合格 | 出さない |
| 陽性面積率 | 不合格 | 不合格 | 不合格 | 不合格 | 出さない |

- 8 組すべてで、評価用（DS6b 4 時間）の測定可能率が決定 4 の形の基準（すべての条件で 80% 以上、条件間の差 10 ポイント以内）を満たさなかった。最も低い条件は 48〜75%、条件間の差は 10〜41 ポイント。
- 調整用の段階でも、CV（NucBlue、FBL）は条件差の大きさ、陽性面積率（5-EU）は順位の保ち方で、規則の下限を下回った。
- 2 × 2 のビニングでは、評価用の核の順位はよく保たれ（条件ごとの視野の中央値で ρ 0.85〜1.00）、評価した条件差の符号は 42 件すべてで保たれた。不合格の主な理由は、ビニングではなく、測れない核の割合が条件で違うこと。
- NCL の陽性面積率は、処理と対照のそろった公開素材がないため検証していない（決定 23）。

## 素材と規則

素材は [核小体の形の検証](public-nucleolar-shape-validation.md) で登録した DS6b の全 360 視野（30 分・2 時間＝調整用 239 視野、4 時間＝評価用 121 視野）。核は製品の検出（StarDist、自動の縮小）を元の解像度と 2 × 2 でまとめた画像に当てた。処理に失敗した視野はない。ただし、#272 と同じ調整用の 11 視野（30 分シスプラチン 100 µM が 6、2 時間オキサリプラチン 10 µM が 3、2 時間シスプラチン 10 µM と 2 時間未処理（5-EU なし）が各 1）で、推定した核の直径が 150 px を超え、核の検出が壊れていた。規則 1 のとおり除かず数えた（その視野の核はほぼ端にかかり、測れない核になる）。評価用の 121 視野には同じ異常はない。

規則は [スクリプト](../scripts/validate_nuclear_signal_public.py) の冒頭にあり、指標の値を計算する前のコミット 7727bf3ee で固定した。調整用の値はコミット dfee664bc、評価用の結果はコミット 63f9b668c で記録した。スクリプトの規則と計算は、この 3 つのコミットの間で変えていない。

| 項目 | 規則 |
|---|---|
| 判定の単位 | 指標 × 染色 |
| 測れない核 | 背景が確立しない、画像の端にかかる、飽和した画素がある、補正後の平均が 0 以下、補正後の平均が背景のばらつきの R 倍未満（Signal QC 1.0.0 の比） |
| R | 調整用の 2 時間の 5-EU で、5-EU なしの対照の 95% 以上を除き、5-EU ありの対照を 20% 以下しか除かない最小の候補（1、2、3、5、10）。なければ 1 |
| 陽性面積率の閾値 | 時点（1 つの実験回として扱う）ごとに、測れる核の補正後の画素をまとめた Otsu |
| 測定可能率 | 評価用で、分母は検出したすべての核（端にかかる核を含む）。すべての条件で 80% 以上、差 10 ポイント以内。5-EU では 5-EU なしの対照を比べない |
| 2 × 2 のビニング | 同じ核を間引いて対応させる。視野ごとの ρ（核 10 個以上）の条件の中央値が、調整用で決めた下限以上。対照との差（視野の中央値の平均）が 2 SE を超える条件で、符号が保たれ、比が調整用で決めた範囲に入る |
| 製品に出す条件 | すべての染色で合格 |

## 結果

### R（信号と背景のばらつきの比の下限）

調整用の 2 時間、5-EU の核で、比が候補未満の割合。

| R | 5-EU なし | 5-EU あり |
|---|---|---|
| 1 | 9.8% | 4.2% |
| 2 | 21.4% | 10.1% |
| 3 | 35.9% | 16.9% |
| 5 | 65.5% | 33.7% |
| 10 | 94.5% | 69.2% |

5-EU なしの対照を分けられる候補はなく、規則どおり R = 1 にした。核の 5-EU の信号は核小体に比べて弱く、R はほぼ背景の水準の核を除くだけになる。

### 評価用の測定可能率（DS6b 4 時間）

| 染色 | 測定可能率（条件の範囲） | 端にかからない核での範囲 | 主な理由 |
|---|---|---|---|
| NucBlue | 72〜88% | 82〜98% | 端 973 核、飽和 561 核（5-EU ありの対照で 180 核） |
| NPM1 | 48〜89% | 55〜100% | 飽和 1,514 核。シスプラチン 100 µM 439、オキサリプラチン 100 µM 374、10 µM 278、ActD 1 µM 258 |
| FBL | 75〜89% | 84〜98% | 端、背景のばらつき未満 251 核 |
| 5-EU（5-EU なしを除く） | 75〜85% | 77〜96% | 端、背景のばらつき未満 520 核、補正後の平均 0 以下 258 核 |

- NPM1 は、処理で核小体に集まった NPM1 が 16 ビットの上限で飽和する核が多く、処理の条件ほど測れない。飽和した画素を含む核の CV は信号の偏りを過小に示すため、値にしない規則は変えていない。
- 端にかかる核（全体の 12%）は、どの染色でも測れない。端を分母から除いても、4 つの染色のどれも条件間の差 10 ポイント以内を満たさない（NucBlue 82〜98%、NPM1 55〜100%、FBL 84〜98%、5-EU 77〜96%）。

### 2 × 2 のビニング（評価用）

| 指標 | 染色 | ρ の最小（条件の中央値） | 評価した条件差 | 符号 | 比 q の範囲 |
|---|---|---|---|---|---|
| CV | NucBlue | 0.973 | 4 | すべて保持 | 0.73〜0.90 |
| CV | NPM1 | 0.996 | 3 | すべて保持 | 0.84〜0.96 |
| CV | FBL | 0.972 | 5 | すべて保持 | 0.62〜1.16 |
| CV | 5-EU | 0.931 | 7 | すべて保持 | 0.87〜1.05 |
| 陽性面積率 | NucBlue | 0.983 | 7 | すべて保持 | 1.00〜1.12 |
| 陽性面積率 | NPM1 | 0.977 | 7 | すべて保持 | 0.87〜1.09 |
| 陽性面積率 | FBL | 0.922 | 3 | すべて保持 | 0.71〜1.02（シスプラチン 100 µM が調整用の範囲の外） |
| 陽性面積率 | 5-EU | 0.846 | 6 | すべて保持 | 0.97〜1.08 |

- CV は 2 × 2 でまとめると画素の雑音が平均されて下がり、条件差も小さくなる（q < 1）。調整用では、NucBlue と FBL の CV の q が 0.37〜0.45 まで下がり、規則の範囲 [0.5, 2.0] を外れた。
- 検出し直した核（事実として記録）でも、順位の ρ は 0.77〜0.99 だった。

## 失敗・未検証の範囲

- 判定は DS6b の 1 研究・1 撮影日・U2OS のノックイン細胞だけ。別施設・別の細胞株・抗体染色では確かめていない。
- 時点を実験回として扱ったが、撮影日は同じで、実験回のばらつきは測っていない。
- 独立に手で描いた核の輪郭はなく、核の検出の正しさは評価していない。
- 共通実装の値と、この検証で書いた独立の計算（NumPy の CV、別に書いた Otsu）の一致は、登録済みの BBBC039 の視野で確かめた（tests/test_nuclear_features.py）。DS6b の値はスクリプトが共通実装の関数で計算したもので、床と時点ごとの集め方が `compute_features` と同じ値になることも BBBC039 で確かめた（tests/test_nuclear_signal_validation.py）。

評価用の結果を記録した後、共通実装の `nuclear_signal` と `nuclear_shapes` に、疎で大きいラベル ID を詰めてから領域を探す変更を入れた（レビューの指摘）。値は変わらない（tests/test_nuclear_features.py が、ID を付け替えたラベルで同じ値になることを確かめる）。評価は再実行していない。

## オーナーに確認したいこと

1. **飽和の扱い。** NPM1 を測れない主な理由は飽和で、撮影条件による。飽和した核を除く規則を保つか（現状）、飽和した画素を含めて値にして、飽和の割合を並べて示すか。
2. **端にかかる核。** 決定 4 の形の分母は端にかかる核を含む。核ごとの指標では、端にかかる核は形・信号ともに測れない。分母から除く形に改めるか。
3. **染色ごとの提供。** 規則 8 は、製品が染色を区別できないことから、1 つの染色の不合格で指標全体を出さない。検証できた染色だけで出す道を開くか。

## 再現

```bash
uv run python -I scripts/validate_nuclear_signal_public.py detect --data-dir ~/public-nucleolar-shape/data \
  --work ~/public-nuclear-signal/work --fiji "$CYTELLECT_FIJI_EXECUTABLE" --workers 3
uv run python -I scripts/validate_nuclear_signal_public.py tune --data-dir ~/public-nucleolar-shape/data \
  --work ~/public-nuclear-signal/work --workers 3
uv run python -I scripts/validate_nuclear_signal_public.py evaluate --data-dir ~/public-nucleolar-shape/data \
  --work ~/public-nuclear-signal/work --workers 3
```

`evaluate` は、tuning.json がコミットされて変更がなく、製品の R が調整用の選択と同じときだけ動く。2026-11-21 の実行では、`detect` が 4 コアで約 3 時間（同じ機械のほかの作業と並行）、`tune` と `evaluate` がそれぞれ約 30 分かかった。
