# LP の美術方針：サイエンスと世界観を世界一流の表現にする

状態：オーナー承認済み（2026-10-23）。LP の見た目と素材に関する正本。[interface-design.md](interface-design.md)、[開発の原則](development-principles.md)、[lp-optical-preview.md](lp-optical-preview.md) と食い違う場合は、この文書に従う。

この文書は、人とエージェント（Claude Code、Codex）が同じ前提で作業するための引き継ぎも兼ねる。作業を始める前に全体を読むこと。

## 1. 目的

| 層 | 内容 |
|---|---|
| 使命 | 画像解析を、一部の専門家の技術から、すべての生命科学研究者が使える研究基盤に変える |
| プロダクト | 画像解析に詳しくない Wet 研究者が、何を対象に何を測っているかを理解し、明確な導線のもとで迷わず修正と判断を行い、統計と編集可能な論文の図まで同じ作業の中で完了できる |
| 事業 | オープンソースで信頼を得て、研究室単位のクラウドで収益を得る |
| LP | 画像を扱う研究者全体に、自分の研究を論文に届ける志と、科学の未来に参加したいという感情を起こし、デモと導入へつなぐ |

LP の第一の仕事は、製品の説明ではなく、**サイエンスと世界観を世界一流の水準で感じさせること**である。LP は控えめな説明より、強く言い切る宣伝の文章でよい（例：「画像をアップロードするだけで」）。製品の実態は、LP の要所の証拠と、本番と同じ画面の公開デモが担う。チームの紹介は載せない。

## 3. 原則

1. **サイエンスは、実写級の映像で象徴する。** カメラで科学の現場を撮ったように見えること。手作りのオブジェ、汎用の装飾、科学データの可視化では象徴できない。
2. **判定は素材の種類ではなく結果で行う。** 実写級であること、心を動かすこと、雰囲気が合っていることを満たせば、実写素材、Blender の描画、合成を組み合わせてよい（2026-10-23 オーナー指示）。逆に、実写素材でも条件を外せば使わない。
3. **製品の実態に寄せすぎない。** 細胞写真、顕微鏡、論文の図解、分子の可視化を、雰囲気の主役にしない。
4. **素材を並べるのではなく、作品として設計する。** 物語、ショット、光、カメラ、色、文字組みを一つの方向で決める。
5. **過去の決定は理由から引き継ぐ。** 明るく読みやすいこと、1 色の文字、見出しのない語り、4 項目のナビゲーション。オーナーの物語は公開サイトに置かない（開発者個人の文脈は About the Developer が担う）。
6. **実装の前に、実物の映像で判断する。** 言葉の合意だけで実装しない。静止画の比較とプレビューでオーナーが判定する。

## 5. 世界観と章立て

**主役は、実験室と科学機器の現場を撮った実写級の映像。雰囲気は、光・ガラス・液体の抽象的な実写級の映像で添える。**

| 章 | 読者の感情 | 主役の素材 |
|---|---|---|
| 1. 驚き（ヒーロー） | 最先端の科学の現場に引き込まれる | ヒーロー映像（[§8](#8-ヒーロー映像)） |
| 2. 使命 | 研究の価値と、Cytellect の志に共感する | 大きな文字の 2 文。背景に光・ガラス・液体 |
| 3. 研究の営み | 自分の研究の現実と重なる | 実験室の実写（手元、機器、光） |
| 4. 製品の証拠 | 本当にできると納得する | 実際の製品画面と出力（短く、要所だけ） |
| 5. 信頼 | 安心して任せられる | 検証の記録、データの扱い、オープンソース |
| 6. 誘い | 触ってみたい、導入したい | デモと Windows 版への導線 |

**本文の実装（2026-10-23、承認）**

最初の版（大きな決め台詞と全面の写真）は、オーナーに「世界観は良いが、内容がいかにも AI の広告で、結局何ができるのかが分からない」と判定された。文言、文字の大きさ、配置も不適切とされた。オーナーが示したプロダクト紹介の資料（本質を端的に捉えた見本）を受け、世界観（映像・写真・余白・1 色の文字）は残し、中身を「短い具体的な主張 1 文と、その証拠になる本物の画面か画像」に組み直した。

| 場面 | 主張 | 証拠 |
|---|---|---|
| 使命 | 画像解析を、すべての生命科学研究者が使える研究基盤に。Cytellect が何をするソフトかを 1 文で | 文字のみ |
| 作業の短縮 | 手作業で数週間かかっていた解析を、一つの画面で数分に | 解析例の画面 |
| 核小体の検出 | 汎用のモデルでは見つからない核小体を、追加学習で検出 | 0% → 90%（分母付き）、核の F1 0.92、解析例の蛍光画像と検出輪郭 |
| AI の設定支援 | やりたい解析を一文で書くと、設定に分解して提案 | 解析例で AI に指示した画面。AI に送るのは入力文だけと明記 |
| 統計と図 | n は細胞の数ではなく、独立した実験の数として検定 | 解析例の統計画面と、反復ごとに結んだ図。反復の独立性が出典にない点も明記 |
| 意義 | 核・細胞質・核小体の指標と、がん・ALS・認知症・老化の研究 | 写真。細胞質の検出は開発中と明記 |
| 誘い | 研究画像は PC の外に出ない。Windows 版は無料 | ダウンロード、24 時間での削除、導入の案内 |

続く判定（内容はかなり良くなったが、長すぎる）を受け、作業の短縮・核小体の検出・AI の設定支援・統計と図の 4 つは、一つの節の中のタブに分け、一度に一つだけ表示する。

**患者へつながる将来性のカード（レビュー案）**

「研究の先に、待っている患者さんがいる。」の見出しと既存の深緑の面を保ち、特定の構造や病名の列挙から、研究が目指す未来を伝える構成にする。「病気のしくみを解き明かす → 新しい薬の可能性を見つける → 患者へ届ける」を、個別の枠を作らず、細く始まり終点へ向かって太くなる 1 本の線でつなぐ。線は中央に置き、PC では横、スマートフォンでは縦に流す。終点は培地の淡い桃色の点と大きい文字で強調する。写真・アイコン・動画は追加しない。

下部は罫線で区切り、「画像解析を、すべての研究者へ。」「ライフサイエンスの根幹を支え、新しい治療につながる研究を後押しする。」を置く。研究が患者へつながる将来像として示し、治療や創薬の達成実績としては扱わない。この節と「その未来を、あなたの研究から。」は、どちらも主役である。2 枚の同じカードを並べず、画面幅いっぱいの 1 つの深緑の舞台に置き、2 つの見出しを同じ大きさ・左揃えでそろえる。オーナーによる画面の判定は未完了。

数値には、何を何個で測ったかを本文に添える。画像の真下に置くと、その画像で測った数値に見えるため、数値と画像は分けて置く。研究室の利用者の声は、氏名を含む参加者情報なので、本人の公開の承認があるまで載せない。

## 6. 「生命科学の最前線」と「清潔感」の基準

素材の選定、編集、描画、グレーディングは、すべてこの基準で判定する。

**生命科学の最前線**

- 生命を扱っていることが一目で分かる：淡い培地の色、培養フラスコ、マルチウェルプレート、透明な液体、液滴、手袋をした手の精密な動き、ピペット、白い安全キャビネット。
- 人の手を超える精密さ：静かで正確な自動化（例：分注ヘッドがプレートへ一斉に下りる）。
- 新しさ：整理された、現代的な研究空間。

**清潔感**

- 自然光か、柔らかく拡散した白い光。硬い影と黒つぶれを作らない。
- 白、淡い灰、ガラスの透明感を基調に、アクセントは 1 色だけ（培地の淡い桃色。ブランドの深緑と競合する色は使わない）。
- 情報量が少ない：ケーブル、ラベル、警告表示、ロゴ、文字、散らかりが写らない。
- 遅く滑らかなカメラ（固定、スライダー、ジンバル）。手持ちの揺れを使わない。浅い被写界深度で主題に焦点を合わせる。
- 人物は手元、背中、ぼけた姿だけ。顔が特定できる映像と、笑顔のストック的な演出を使わない。

**使わないもの**

産業用・黄色のロボットアーム、臨床検査装置、暗い機械内部、紫や青の発光、星や粒子、入れ子の球、細胞・顕微鏡画像・分子の可視化を主役にした映像、手作りの有機的な形状、出所の不明な AI 生成映像。

## 8. ヒーロー映像

**現在の版（2026-10-23 承認）**

- 構成：[`scripts/lp_film/cuts.json`](../scripts/lp_film/cuts.json) の 4 カット（培養プレート → 自動分注 → 手元 → 研究室の遠景）を 0.7 秒のクロスフェードでつなぎ、最初のカットへ戻る約 10 秒のループ。最も強いカットから始め、代表フレームもそこから取る。
- 色調：素材本来のコントラストと透明感を残し、わずかに暗く締める。黒は潰さない。アクセントは培地の桃色。
- 文字との重なり：見出しと行動は白。左（モバイルは上）から薄い暗部のグラデーションを重ねて読みやすくする。映像を白く霞ませるベールは使わない。
- 書き出し：1920×1080、25 fps、音声なし。WebM（VP9）を先に、H.264 の MP4 を次に置く。代表フレームの WebP を最初に表示し、省モーション設定と読み込み失敗では静止画のまま、画面外とタブの非表示では停止する（[`HeroFilm`](../apps/web/src/components/HeroFilm.tsx)）。
- LP から 3D の背景（`OpticalHero`）を外した。部品と素材は、オーナーの判定後に削除する。

**オーナーの判定の記録**

| 日付 | 版 | 判定 |
|---|---|---|
| 2026-10-23 | 淡い色調、白いベール、手元のカットから開始 | 不合格。動画自体は悪くないが、背景を霞ませるベールで雰囲気が台無し。第一印象のインパクトが足りない |
| 2026-10-23 | ベールを外し、色調を戻し、自動分注から開始、白い見出し | 前半（自動分注・培養・手元）は良い。水滴のカットは却下 |
| 2026-10-23 | 水滴のカットを外した版 | ウェルプレートの動画は満点。水滴以降（光とガラスの写真）は良くない。ウェルとは別パターンの雰囲気が欲しい。NASA の宇宙映像は雰囲気が変わるので不可、ラボ風景を最優先 |
| 2026-10-23 | 終盤を明るい研究室の遠景（Pexels 9573740）に差し替えた版 | 素材は良い。最初のカットは 2 枚目のウェル（培養プレート）にする |
| 2026-10-23 | 培養プレートから始め、代表フレームも培養プレートにした版 | 承認（本文と合わせて承認） |

## 9. ヒーロー映像の制作（Codex が担当）

ヒーロー映像は、素材探しから編集、描画、合成、色調、書き出しまで、Codex が一貫して担当する。Codex の強み（ローカルでの Blender と重い描画、長い自律作業、多数の試作）を生かすため、手段は指定しない。以下の目標と制約の中で、最もよい映像を作ること。

**目標**

- 研究者がページを開いた瞬間に、「生命科学の最前線」に引き込まれ、心が動くこと。第一印象のインパクト（最初の 1 秒と代表フレーム）を最優先にする。
- 実写級であること、心を動かすこと、雰囲気が合っていること（[§3](#3-原則) の 2）。参照先の水準（[§4](#4-世界一流の基準参照サイト)）と並べて見劣りしないこと。
- [§6](#6-生命科学の最前線と清潔感の基準) の基準と「使わないもの」を守ること。

**使ってよい手段**（組み合わせてよい）

- 無料素材の追加の探索と差し替え（[§7](#7-採用アセット) の調査結果と除外した配布元を参照。ライセンスの条件は同じ）。
- Blender（Cycles）による写実的なカットの制作、実写素材への CG の合成、カメラの動きの統一。
- 編集の作り直し：カットの選択、順序、長さ、速度、つなぎ方、色調。`scripts/lp_film/` のスクリプトと編集リストは、Codex が自由に作り直してよい。
- 安定化、解像度の改善、フレーム補間などの処理。生成 AI の映像は、オーナーがサービスを指定するまで使わない。

**守ること**

- すべての素材の出典、ライセンス、加工内容、SHA-256 を `scripts/lp_film/sources.json` と `apps/web/public/marketing/hero-film-provenance.json` に記録し、公開資産の許可リストに登録する。第三者の原本と `.blend` はコミットせず、取得と描画のスクリプトで再現できるようにする。
- 研究の記録や製品の実績を装う映像にしない。人物の顔、ロゴ、文字を写さない。
- 書き出しの約束（LP の部品が依存する）：`apps/web/public/marketing/hero-film.webm`（VP9）、`hero-film.mp4`（H.264、faststart）、`hero-film-poster.webp`（代表フレーム）。1920×1080、音声なし、継ぎ目のないループ、2 本の合計は 4 MB 程度まで。見出しは画面の左（モバイルは上）に白で重なるので、その範囲に強い明部や細かい情報を置かない。約束を変えたい場合は PR の説明で提案する。
- 判定はオーナーが行う。大きく方向を変える前に、代表フレームと数枚の静止画、または短い試写を見せて判定を受ける。判定は §8 の記録に追記する。

## 10. 分担とファイルの境界

並行作業でコンフリクトを起こさないため、担当するファイルを分ける。境界は「映像」と「ページ」である。

| 担当 | ブランチ | 変更してよいファイル |
|---|---|---|
| Codex（映像） | `feat/lp-film-blender`（下のブランチの最新から作り、定期的に取り込む） | `scripts/lp_film/**`、`apps/web/public/marketing/hero-film*`、許可リストのそれらの項目、この文書の §8・§9 |
| Claude Code（ページとデモ） | `claude/optimistic-davinci-oz7zzc` | `apps/web/**`（上記の映像ファイルを除く）、`docs/**`（この文書の §8・§9 を除く）、デモ一式 |
| オーナー | — | 判定、素材の権利の判断、撮影 |

- Codex の PR は `claude/optimistic-davinci-oz7zzc` に向けて作る。そのブランチが先に `main` へマージされた場合は、`main` に向け直す。
- Claude Code は、Codex の担当範囲が始まってからは映像ファイルと `scripts/lp_film/` を変更しない。ページ側から映像に求めることは、Codex の PR か、オーナー経由で伝える。
- 許可リスト（`fixtures/public/allowlist.json`）でコンフリクトした場合は、両方の項目を残し、映像ファイルの SHA-256 を実物から計算し直してから `python scripts/check_public_tree.py` を実行する。

## 11. 判定の基準

- 参照サイトの画面と並べたとき、同じ水準に見えること。CG の模型に見えないこと。
- 文字と映像の重なりが読みやすく、ファーストビューで約束と行動が分かること。
- 画面上のすべての素材について、出典と加工内容を説明できること。
- 判定は、実際に描画した映像と Vercel のプレビューで、オーナーが行う。エージェントの確認やテストの合格は判定の代わりにしない。

**本文の文言について、オーナーが下した判定（2026-10-23）**

文案は、直前の指摘だけでなく、次のすべてに照らしてから示す。一つを直して別の判定を壊すことが、繰り返し失敗した原因である。

| 判定 | 内容 |
|---|---|
| 形式 | 場面ごとに、短く言い切る主張 1 文と、その証拠になる本物の画面か画像。説明のカードを同じ形で並べない |
| 読者 | 蛍光顕微鏡で細胞を撮る、すべての生命科学研究者。研究者には利用価値が、エンジニアには技術の深さが伝わる |
| 研究者が求めるもの | 主語は研究者の利用価値。技術の名前や仕組みの説明から入らない |
| 測れるもの | 特定の構造（核・核小体・細胞質）に固定しない。固定すると、ほかの解析ができない製品に見える |
| 具体性 | 抽象的なカテゴリの羅列は伝わらない。ただし、具体例を並べれば解決するわけでもない |
| 自動であること | 研究者が輪郭を直す必要があるように見せない。修正は研究者の作業として描かない |
| 検出モデル | 価値は独自の深層学習モデルであること。「AI」と書くと LLM を想起させ、検出と LLM の設定提案が混ざって見える |
| 追加学習 | 追加学習そのものを売りにしない。研究者にとっては懸念材料になる。他の研究者の輪郭で学習する前提も誤り |

| 否定と言い訳 | LP は否定・言い訳・防御的な注記の場ではない。「〜ではありません」で誤解を打ち消さない |
| 開発中の表示 | 細胞質を開発中とする記述など、未完成を断る文を置かない |
| 要件との整合 | 核は公開モデル（StarDist）で検出する。LLM の設定提案は製品の機能である。これらと矛盾する主張をしない |

| 作業 | 指示にない検証や測定を行わない。測定条件の異なるデータは LP の根拠にならない |
