# LP の美術方針：サイエンスと世界観を世界一流の表現にする

状態：オーナー承認済み（2026-10-23）。LP の見た目と素材に関する正本。[interface-design.md](interface-design.md)、[development-standards.md](development-standards.md)、[lp-optical-preview.md](lp-optical-preview.md) と食い違う場合は、この文書に従う。

この文書は、人とエージェント（Claude Code、Codex）が同じ前提で作業するための引き継ぎも兼ねる。作業を始める前に全体を読むこと。

## 1. 目的

| 層 | 内容 |
|---|---|
| 使命 | 画像解析を、一部の専門家の技術から、すべての生命科学研究者が使える研究基盤に変える |
| 製品 | 画像解析に詳しくない Wet 研究者が、何を対象に何を測っているかを理解し、修正と判断を行い、統計と編集可能な論文の図まで同じ作業の中で完了できる |
| 事業 | オープンソースで信頼を得て、研究室単位のクラウドで収益を得る |
| LP | 画像を扱う研究者全体に、自分の研究を論文に届ける志と、科学の未来に参加したいという感情を起こし、デモと導入へつなぐ |

LP の第一の仕事は、製品の説明ではなく、**サイエンスと世界観を世界一流の水準で感じさせること**である。LP は控えめな説明より、強く言い切る宣伝の文章でよい（例：「画像をアップロードするだけで」）。製品の実態は、LP の要所の証拠と、本番と同じ画面の[公開デモ](showcase.md)が担う。チームの紹介は載せない。

| 2026-10-22 | 節のテンプレート、写真の削除、製品の説明に寄せた再構成 | 過去の決定を読まずに作り、世界観を失った。取り消し済み |

| 2026-10-23 | 無料素材の網羅的な調査（約 1,000 件） | 清潔感と生命科学らしさを満たす素材はある。ただし質の高いストックの域で、Lila と並ぶ差別化はできない。条件を満たす 4K 動画は 2 本だけ（[§7](#7-採用アセット)） |

## 3. 原則

1. **サイエンスは、実写級の映像で象徴する。** カメラで科学の現場を撮ったように見えること。手作りのオブジェ、汎用の装飾、科学データの可視化では象徴できない。
2. **判定は素材の種類ではなく結果で行う。** 実写級であること、心を動かすこと、雰囲気が合っていることを満たせば、実写素材、Blender の描画、合成を組み合わせてよい（2026-10-23 オーナー指示）。逆に、実写素材でも条件を外せば使わない。
3. **製品の実態に寄せすぎない。** 細胞写真、顕微鏡、論文の図解、分子の可視化を、雰囲気の主役にしない。
4. **素材を並べるのではなく、作品として設計する。** 物語、ショット、光、カメラ、色、文字組みを一つの方向で決める。
5. **過去の決定は理由から引き継ぐ。** 明るく読みやすいこと、1 色の文字、見出しのない語り、オーナーの物語、4 項目のナビゲーション。
6. **実装の前に、実物の映像で判断する。** 言葉の合意だけで実装しない。静止画の比較とプレビューでオーナーが判定する。

## 5. 世界観と章立て

**主役は、実験室と科学機器の現場を撮った実写級の映像。雰囲気は、光・ガラス・液体の抽象的な実写級の映像で添える。**

| 章 | 読者の感情 | 主役の素材 |
|---|---|---|
| 1. 驚き（ヒーロー） | 最先端の科学の現場に引き込まれる | ヒーロー映像（[§8](#8-ヒーロー映像)） |
| 2. 使命 | 研究の価値と、Cytellect の志に共感する | 大きな文字の 2 文と、オーナーの物語への入口。背景に光・ガラス・液体 |
| 3. 研究の営み | 自分の研究の現実と重なる | 実験室の実写（手元、機器、光） |
| 4. 製品の証拠 | 本当にできると納得する | 実際の製品画面と出力（短く、要所だけ） |
| 5. 信頼 | 安心して任せられる | 検証の記録、データの扱い、オープンソース |
| 6. 誘い | 触ってみたい、導入したい | デモと Windows 版への導線 |

## 6. 「生命科学の最前線」と「清潔感」の基準

素材の選定、編集、描画、グレーディングは、すべてこの基準で判定する。

**生命科学の最前線**

- 生命を扱っていることが一目で分かる：淡い培地の色、培養フラスコ、マルチウェルプレート、透明な液体、液滴、手袋をした手の精密な動き、ピペット、白い安全キャビネット。
- 人の手を超える精密さ：静かで正確な自動化（例：分注ヘッドがプレートへ一斉に下りる）。
- 新しさ：整理された、現代的な研究空間。

**清潔感**

- 自然光か、柔らかく拡散した白い光。硬い影と黒つぶれを作らない。
- 白、淡い灰、ガラスの透明感を基調に、アクセントは 1 色だけ（培地の淡い桃色。ブランドの深緑と競合する色は使わない）。
- 情報量が少ない：ケーブル、ラベル、警告表示、ロゴ、文字、散らかりが写らない。
- 遅く滑らかなカメラ（固定、スライダー、ジンバル）。手持ちの揺れを使わない。浅い被写界深度で主題に焦点を合わせる。
- 人物は手元、背中、ぼけた姿だけ。顔が特定できる映像と、笑顔のストック的な演出を使わない。

**使わないもの**

産業用・黄色のロボットアーム、臨床検査装置、暗い機械内部、紫や青の発光、星や粒子、入れ子の球、細胞・顕微鏡画像・分子の可視化を主役にした映像、手作りの有機的な形状、出所の不明な AI 生成映像。

## 8. ヒーロー映像

- **構成**：[`scripts/lp_film/cuts.json`](../scripts/lp_film/cuts.json) の 5 カット（手元 → 自動化 → 培養 → 液滴 → 光とガラス）を 0.8 秒のクロスフェードでつなぎ、最初のカットへ戻る約 12 秒のループにする。
- **色調**：白に近い明るさ、低いコントラスト、持ち上げた黒、抑えた彩度。アクセントは培地の淡い桃色。共通の補正は `cuts.json` の `grade`、カットごとの補正は `adjust` に置く。
- **文字との重なり**：映像は明るさと情報量を抑え、左側の文字の下は承認済みの `.heroShade`（淡い暖色のベール）で整える。見出しは LP の 1 色の文字のまま。
- **書き出し**：1920×1080、25 fps、H.264、音声なし、4 MB 以下を目安。代表フレームを WebP の静止画にし、省モーション設定・読み込み失敗・画面外では静止画を表示する（[`HeroFilm`](../apps/web/src/components/HeroFilm.tsx)）。
- **生成**：`python scripts/lp_film/build_film.py` が映像、静止画、`hero-film-provenance.json` を書き出し、公開資産の許可リストに登録する。`--preview <path>` は追跡対象のファイルに触れずに試写だけを書き出す。
- **組み込み**：ヒーローの背景を映像に置き換える。ヒーロー以降の背景（`OpticalHero`）を残すかは、プレビューで判断する。
- **本番の主役**：研究室での撮影が可能になれば、同じ編集リストのカットを撮影素材で差し替える。

## 9. Blender のカット（Codex が担当）

無料素材で埋まらない 2 カットを、撮影と見分けがつかない質で作る。素材の種類ではなく結果で判定する（[§3](#3-原則) の 2）。

| カット | 内容 | 現在の代替 |
|---|---|---|
| `droplet` | ピペットの先端に透明な液滴がふくらみ、離れて落ちる。白に近い背景、または淡い培地のウェルへ。マクロレンズ（85〜100 mm 相当）、浅い焦点 | `px-p-18959104` |
| `glass` | 柔らかな昼光が実験用ガラスと液体を通り、屈折とコースティクスがゆっくり動く | `us-6Uu8CSP38AI` |

**作り方の条件**

- 形状は実物の寸法から作る（例：ANSI/SLAS の 96 穴プレート 127.76 × 85.48 mm、200 µL チップ）。手作りの有機的な形状は使わない。
- 材質は実測の屈折率を使う（ポリスチレン 1.59、ポリプロピレン 1.49、ホウケイ酸ガラス 1.47、水 1.333）。HDRI とテクスチャは CC0（Poly Haven、ambientCG）に限る。
- Cycles、実カメラの被写界深度とモーションブラー、AgX の表示変換。液体は流体シミュレーション、または表面張力の形を再現したアニメーション。
- 描画は中立の色で書き出し、色調は `build_film.py` の共通の補正に任せる。
- 出力：1920×1080、25 fps、各カットの `duration` 以上の長さ（3.2 秒なら 80 フレーム以上）、H.264（CRF 12 前後、yuv420p、音声なし）。ファイルは `scripts/lp_film/renders/<カット>.mp4`。置けば `build_film.py` が代替より優先して使う。
- シーンは `scripts/lp_film/blender/` の Python スクリプトから再現できるようにする。`.blend` と外部素材はコミットせず、取得スクリプトと SHA-256 で再現する。

**手順**

1. 各カットの静止画を 3 枚ずつ描画し、採用済みの実写カットの静止画と並べてオーナーに見せる。
2. オーナーが合格としたカットだけを本描画する。不合格なら理由を記録して作り直す。
3. `python scripts/lp_film/build_film.py --preview .cache/lp_film/preview.mp4` で、映像全体の中で浮かないことを確認する。

## 10. 分担とファイルの境界

並行作業でコンフリクトを起こさないため、担当するファイルを分ける。

| 担当 | ブランチ | 変更してよいファイル |
|---|---|---|
| Claude Code（クラウド） | `claude/optimistic-davinci-oz7zzc` | `apps/web/**`（LP の部品、CSS、`hero-film.*`、来歴）、`scripts/lp_film/{sources.json,cuts.json,fetch_sources.py,build_film.py}`、`docs/**` |
| Codex（ローカルの Blender） | `feat/lp-film-blender`（上のブランチの最新から作る） | `scripts/lp_film/blender/**`、`scripts/lp_film/renders/**`、許可リストの `scripts/lp_film/renders/` の項目だけ |
| オーナー | — | 静止画とプレビューの判定、素材の権利の判断、撮影 |

- Codex は `apps/web/**`、`cuts.json`、`sources.json`、`build_film.py`、`docs/**` を変更しない。変更が必要なら PR の説明に提案として書く。`build_film.py` の出力（`hero-film.*`）はコミットしない。
- Codex の PR は `claude/optimistic-davinci-oz7zzc` に向けて作る。そのブランチが先に `main` へマージされた場合は、`main` に向け直す。
- 許可リスト（`fixtures/public/allowlist.json`）でコンフリクトした場合は、両方の項目を残してから `python scripts/check_public_tree.py` を実行する。
- 描画が LP に入る順序：Codex の PR をマージ → Claude Code が `build_film.py` を実行して `hero-film.*` を更新 → プレビューでオーナーが判定。

## 11. 判定の基準

- 参照サイトの画面と並べたとき、同じ水準に見えること。CG の模型に見えないこと。
- 文字と映像の重なりが読みやすく、ファーストビューで約束と行動が分かること。
- 画面上のすべての素材について、出典と加工内容を説明できること。
- 判定は、実際に描画した映像と Vercel のプレビューで、オーナーが行う。エージェントの確認やテストの合格は判定の代わりにしない。

## 12. 未決事項

- 研究室での撮影の可否と、ショットリスト。
- AI の補助に使うサービス（素材の統一、延長、解像度の改善だけに使う。研究の記録や製品の実績を装う生成はしない）。
- NCATS の写真の権利の確認（使う場合のみ）。
- 核小体検出の成果（0%→90%）を LP に載せる場合の、評価記録の公開方法。
