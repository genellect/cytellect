# LP の美術方針（案）：サイエンスと世界観を世界一流の表現にする

状態：オーナー承認前の案（2026-10-22）。承認後に [interface-design.md](interface-design.md) と [lp-optical-preview.md](lp-optical-preview.md) へ反映し、この文書を正本にする。

## 1. 目的

| 層 | 内容 |
|---|---|
| 使命 | 画像解析を、一部の専門家の技術から、すべての生命科学研究者が使える研究基盤に変える |
| 製品 | 画像解析に詳しくない Wet 研究者が、何を対象に何を測っているかを理解し、修正と判断を行い、統計と編集可能な論文の図まで同じ作業の中で完了できる |
| 事業 | オープンソースで信頼を得て、研究室単位のクラウドで収益を得る |
| LP | 画像を扱う研究者全体に、自分の研究を論文に届ける志と、科学の未来に参加したいという感情を起こし、デモと導入へつなぐ |

LP の第一の仕事は、製品の説明ではなく、**サイエンスと世界観を世界一流の水準で感じさせること**である。製品の実態は、LP の要所の証拠と、本番と同じ画面のデモが担う。

## 2. これまでの試みと、届かなかった理由

| 時期 | 試み | 結果と理由 |
|---|---|---|
| #22–#25 | Dark/Blue、Blender で手作りした細胞の造形、実験室の写真 | 造形が CG のオブジェに見え、サイエンスを象徴できなかった。手作りの形状と質感では、実写の光、被写界深度、質感、揺らぎが出ない |
| #51・#52 | オーナーの物語、見出しのない1列の本文、1色の文字 | 読みやすさと語り口は前進した。この原則は維持する |
| #59 | 明るい光学空間（ガラス・金属・床の 3D） | 明るさと読みやすさは承認された。主役が手作りのオブジェである点は #22 と同じ前提で、サイエンスの象徴にはならない |
| 2026-10-22 の再構成 | 節のテンプレート、写真の削除、製品の説明に寄せた構成 | 過去の決定を読まずに作り、世界観を失った。取り消し対象 |
| 同日の検討 | 細胞画像を主役にする案、無料素材を組み合わせる案 | 製品の実態に寄せすぎた。素材の寄せ集めは世界観にならない |
| 同日の試作 | 実際の構造データ（PDB 4V6X のリボソーム）を Blender で写実的に描画 | 科学データの可視化であって、実写ではない。カメラで現場を撮ったように見える映像が求められている |

導かれる原則は次のとおり。

1. **サイエンスは、実写で象徴する。** カメラで科学の現場を撮ったように見える映像である。手作りのオブジェ、汎用の装飾、科学データの可視化では象徴できない。
2. **製品の実態に寄せすぎない。** 細胞写真、顕微鏡、論文の図解を、雰囲気の主役にしない。
3. **素材を並べるのではなく、作品として設計する。** 物語、ショット、光、カメラ、色、文字組みを一つの方向で決める。
4. **過去の決定は理由から引き継ぐ。** 明るく読みやすいこと、1色の文字、見出しのない語り、オーナーの物語。
5. **実装の前に、実物の映像で判断する。** 言葉の合意だけで実装しない。

## 3. 世界一流の基準：参照サイトの観察（2026-10-22 撮影）

| サイト | サイエンスの象徴 | 取り入れること |
|---|---|---|
| [Lila Sciences](https://www.lila.ai/) | 自社の自律型ラボの実写映像。使命の2文を巨大な文字で置き、抽象的な線の場、仕組みの図、応用領域の写真を組み合わせる | 実写の説得力、文字の少なさと大きさ、映像と余白の間合い |
| [Isomorphic Labs](https://www.isomorphiclabs.com/) | 実際のタンパク質構造を、半透明の上質な質感で写実的に描画。明るい淡色の背景と細い線の枠 | 明るいトーンのまま、実データを上質な物体として見せる方法 |
| [AlphaFold](https://deepmind.google/science/alphafold/) | 実際の構造データのリボンを、被写界深度付きで描画。白地に大きな名前 | 実データの美しさを主役にし、背景は静かに保つ |
| [Altos Labs](https://www.altoslabs.com/) | 流体のマクロ撮影（実写の抽象）。使命を大きな文字で置く | 実写でありながら抽象的な質感 |
| [Arc Institute](https://arcinstitute.org/) | DNA を点と線で描く図像、セリフ体の見出し | 図像の抑制と、知的な文字組み |
| [Recursion](https://www.recursion.com/) | 色の場に、実験データや図を淡く重ねる | 科学の痕跡を雰囲気として使う |

共通点は、**実データか実写を、上質な光と質感で一つの方向に仕上げ、少ない言葉の大きな文字と組み合わせる**ことである。手作りの装飾、汎用のアイコン、密集した製品画面は、どのサイトでも主役になっていない。

## 4. Cytellect の世界観（案）

**主役は、実験室の自動化と科学機器の現場を撮った実写映像。雰囲気は、光・ガラス・液体の抽象的な実写で添える。**（2026-10-22 オーナー指示）

| 章 | 読者の感情 | 主役の素材 |
|---|---|---|
| 1. 驚き（ヒーロー） | 最先端の科学の現場に引き込まれる | 液体を扱うロボット、マイクロプレート、ピペットのヘッド、機器の精密な動きを、浅い被写界深度と自然光で撮った映像 |
| 2. 使命 | 研究の価値と、Cytellect の志に共感する | 大きな文字の2文と、オーナーの物語への入口。背景に光・ガラス・液体の抽象的な実写 |
| 3. 研究の営み | 自分の研究の現実と重なる | 実験室の実写（手元、機器、光） |
| 4. 製品の証拠 | 本当にできると納得する | 実際の製品画面と出力（短く、要所だけ） |
| 5. 信頼 | 安心して任せられる | 検証の記録、データの扱い、オープンソース |
| 6. 誘い | 触ってみたい、導入したい | デモと Windows 版への導線 |

細胞写真、顕微鏡画像、分子の可視化は雰囲気の主役にしない。トーンは承認済みの明るい方向を基本にし、映像の色と光を一つの方向に揃える（グレーディング）。紫や青の発光、星や粒子、入れ子の球は使わない。

## 5. 素材と制作方法

| 素材 | 出典と条件 | 制作方法 |
|---|---|---|
| 実験室の自動化・機器の実写映像（主役） | 出典表示や商用利用・改変の条件を確認した無料素材（Pexels、Pixabay、Mixkit、Coverr、Wikimedia Commons、政府機関や研究機関の公有・CC BY 素材）。顔が特定できる映像や機器のロゴは避けるか切り抜く | 一本の作品として編集する。カット割り、速度、色と光の統一（グレーディング）、ループのつなぎを設計する |
| 光・ガラス・液体の抽象的な実写（雰囲気） | 同上 | 章の背景や転換に使う。主役の映像と同じ色調に揃える |
| ローカルの Blender | 実物のスキャン素材と実在の照明（CC0）だけを使う | 実写素材で埋まらない場面に限り、撮影と見分けがつかない質で作る。手作りの形状は使わない |
| AI の補助 | オーナーが指定するサービスに限る | 素材の統一、延長、解像度の改善だけに使う。研究の記録や製品の実績を装う生成はしない |
| リアルタイム 3D | Three.js | 主役にはしない |

すべての素材は、出典、ライセンス、取得日、加工内容、SHA-256 を `apps/web/public/marketing/provenance.json` と公開資産の許可リストに記録する。

## 6. ヒーロー映像の仕様（案）

- 長さ 8〜15 秒のループ。3〜5 カットで構成し、最初と最後がつながること。
- カットの例：ピペットのヘッドが一斉に下りる／ロボットアームがプレートを運ぶ／チューブの列を浅い焦点で流す／ガラス越しの光と液体。
- 書き出し：1920×1080、H.264（目安 4 MB 以下）。代表フレームを静止画として用意し、省モーション設定と読み込み失敗時に表示する。
- 文字：見出し「Get your microscopy publication-ready.」と日本語の約束を、映像の上に読める位置で重ねる。

## 7. 判定の基準

- 参照サイトの画面と並べたとき、同じ水準に見えること。実写や実データの質感があり、CG の模型に見えないこと。
- 文字と映像の重なりが読みやすく、ファーストビューで約束と行動が分かること。
- 画面上のすべての素材について、出典と加工内容を説明できること。
- 判定は、実際に描画した映像と Vercel のプレビューで、オーナーが行う。私の確認やテストの合格は判定の代わりにしない。

## 8. 制作の分担と手順

1. この環境で、素材の候補（構造データ、HDRI、実写素材）を出典付きで確定し、Blender のシーン構成とショット仕様を書く。
2. オーナーの承認を得る。
3. 描画はローカルの Blender で行う（ローカルのタスクまたは Codex に依頼する）。
4. 描画した映像を、この文書の基準でオーナーと判定する。不合格なら、理由を記録して作り直す。
5. 合格した映像を LP に組み込み、Vercel のプレビューで最終確認する。

## 9. 未決事項

- ヒーローに使う実写素材の選定。
- 研究の営みの実写素材の候補と、研究室での撮影の可否。
- AI の補助に使うサービス。
- 核小体検出の成果（0%→90%）を LP に載せる場合の、評価記録の公開方法。
