# 承認済み全面修正計画と実装の対応

10月8日の接続・受入・反映の最新状況は[統合ワークスペース反映記録](workspace-integration-release-2026-10-08.md)を参照。以下の「統合中」「未確認」は10月7日の中断時点の台帳として保持する。

基準は、所有者が承認した「Cytellect：研究者の操作と解析結果を一致させる全面修正計画」。この文書は仕様の変更案ではなく、その項目番号に対応する実装・未達・受入の台帳である。10月6日の仕様書や初期の部分修正案で、後の承認済み計画を置き換えない。

## 後続指示による実行上の制約

- 実際に報告された不具合について、該当する承認済み要件、入力・実行条件・保存結果・表示のどこで外れるか、必要な変更、同じ操作での確認を対応付けてから修正する。静的に見つけた懸念だけを、報告された失敗の原因と扱わない。
- この作業の画像受入には所有者の指定したBiology実画像を使用する。人工・生成画像のテストを新設・実行せず、過去の人工画像での成功を今回の捕捉確認の代わりにしない。非公開の入力・結果・詳細な確認記録はチェックアウト外に置く。
- 実行経路が成功したこと、原画素からの測定が一致したこと、生物学的な対象を適切に捉えたことは、それぞれ別に判定する。
- 報告された失敗を理由に、検出方式・既定閾値・対象の定義・実装範囲を独自に変更しない。承認済み仕様で決まっている事項を再設計せず、その接続と実行を修正する。
- Dockerへの一括反映と所有者による操作確認という完了単位を維持する。原因の切り分けは、この完了単位を部分機能の公開へ変更する理由にしない。

## 公開と完了の扱い

- 所有者は全機能の接続とDockerへの一括反映を承認済み。追加のUI承認待ちを設けない。
- ソースの実装、単体確認、Docker反映、実ブラウザ確認、所有者による捕捉確認は別の状態として報告する。
- 現在の `/workspace-review` の稼働画面は更新前。下記のソース変更を反映済みと表現しない。
- Dockerは途中で置き換えず、アップロードから保存までを接続して一括更新する。既存の非公開データ・採用版・端末認証を保全する。
- LP、認証方式、保存期限、月額5ドル上限は変更しない。新規foci/dotレシピや探索的クラスタ回帰を追加しない。
