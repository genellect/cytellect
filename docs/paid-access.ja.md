# 有料機能の利用コード

クラウド GPU での自動検出（Cellpose）と解析案の補助（OpenAI）は、オーナーの有料契約で動きます。この 2 つは、オーナーが発行する**利用コード**を入力した PC だけで使えます。アプリをインストールしただけでは使えません。

## 仕組み

```text
オーナー ──利用コード（1回限り・期限付き）──▶ 研究者
研究者のPC ──利用コード──▶ 利用コードのサービス（Cloudflare Worker）──▶ このPC専用の端末トークン
研究者のPC ──端末トークン＋検出用の画像──▶ Worker ──Modal の鍵──▶ GPU（Modal）
研究者のPC ──端末トークン＋解析の目的など──▶ Worker ──OpenAI の鍵──▶ OpenAI
```

- **鍵の置き場所**：Modal と OpenAI の鍵は、Worker の秘密の値にだけ置きます。研究者の PC には置きません。
- **端末トークン**：PC ごとに 1 つ発行されます。Windows では、その PC のそのユーザーだけが読めるように暗号化（DPAPI）して保存します。保存先は Cytellect の `settings\paid-access.json` です。利用コード自体は保存しません。
- **月の上限**：Worker は、PC ごとと全体で月の上限を数えます。Cellpose は結果を返した視野だけを数え、解析案は回数と費用の上限を数えます。
- **PC ごとの停止**：オーナーは 1 台ずつ止められます。止めた PC では両方の機能が使えなくなります。
- **送信元ごとの回数制限**：Worker は、送信元の IP ごとに回数の上限をかけます。
- **最後の安全装置**：Modal の Spend limit 0 ドルと OpenAI 側の使用上限は、そのまま残します。Worker が乗っ取られても、自己負担は発生しません。

## 送られるデータ

- **Cellpose**：検出に使う 1 チャンネルの画像、核小体の検出では採用済みの核のマスク、検出条件だけを送ります。Worker はこれを保存も記録もせず、そのまま Modal に渡します。Worker のログ記録（observability）は無効です。
- **解析案**：[解析提案の説明](proposal-service.md)のとおりです。
- **送らないもの**：ファイル名、作業名、実験条件、ほかのチャンネル、パスです。
- **Worker が保存するもの**：端末トークンの暗号学的な要約（ハッシュ）、PC の呼び名、月ごとの回数だけです。

## オーナーの準備（最初の 1 回）

Worker のデプロイ手順は [proposal-deployment.md](proposal-deployment.md) に従います。デプロイと秘密の値の設定は、オーナーが明示的に指示して行います。

1. D1 に `migrations/0004_access_codes.sql` を適用する（`pnpm cf d1 migrations apply …`）。
2. Worker の秘密の値に `CELLPOSE_UPSTREAM_TOKEN` を加える。値は Modal の proxy token を `wk-….ws-…` の形でつないだものです。
3. Worker の変数を設定する。

   | 変数 | 意味 | 例 |
   | --- | --- | --- |
   | `CELLPOSE_UPSTREAM_URL` | Modal の GPU サーバーの URL | `https://….modal.direct` |
   | `DEVICE_MONTHLY_CELLPOSE_FIELDS` | 1 台あたり月の視野数の上限 | `300` |
   | `MONTHLY_CELLPOSE_FIELDS` | 全体の月の視野数の上限 | `3000` |

   どれかが空のときは、Cellpose の中継は無効になります。研究者の画面には「現在提供されていません」と出ます。
4. 送信元ごとの回数制限（`[[ratelimits]]`、`wrangler.toml.example`）を有効にする。
5. Worker の URL を `packages/analysis/src/cytellect_analysis/paid_access.py` の `SERVICE_URL` に書いて、配布物に含める。この URL は秘密の値ではありません。

**上限の目安**：[実測](cloud-gpu.ja.md#実測2026-10-23)では、起動済みの GPU で 1 視野 6〜11 秒（約 0.003 ドル）でした。停止状態からの起動は約 3 分かかり、1 回あたり 0.02〜0.06 ドルです。全体で月 3,000 視野なら、起動の回数にもよりますが、おおよそ 10〜20 ドルです。Modal の無料枠（月 30 ドル）に収まるように決めてください。

## 利用コードを発行する

オーナーの PC で実行します。管理者トークンは環境変数 `CYTELLECT_ADMIN_TOKEN` から読みます。設定していなければ、入力を求められます（画面には表示されません）。

```sh
python scripts/paid_access_admin.py issue --label "研究室PC-1"
```

- 表示された利用コードを、研究者に渡します。メールとは別の経路（研究室のチャットなど）で、本人に直接渡すのが安全です。
- コードは 1 回だけ使えます。既定の有効時間は 24 時間です（`--hours` で 1〜168 時間に変えられます）。
- `--label` には PC の呼び名を入れます。研究者の氏名や、画像・実験の内容は入れません。

## 研究者の操作

1. Cytellect を開き、作業一覧の「**有料機能**」に利用コードを貼り付けて、「有効にする」を押します。
2. 「クラウドGPU（Cellpose）：利用できます（今月の残り ○ 視野）」と表示されれば完了です。再起動は要りません。
3. 「このPCの利用は管理者によって停止されています」と表示された場合は、オーナーに新しい利用コードを依頼します。

## PC を確認する・止める

```sh
python scripts/paid_access_admin.py list
python scripts/paid_access_admin.py revoke <PCのID>
```

- `list` は、PC の ID、呼び名、登録日時、状態、今月の Cellpose の視野数と解析案の回数を表示します。
- 止めた PC は元に戻せません。続けて使う場合は、新しい利用コードを発行します。

次のときは止めてください。

- PC の紛失・譲渡・廃棄
- 研究者が研究室を離れたとき
- 端末トークンや利用コードが漏れた疑いがあるとき
- 1 台の利用数が想定より大きく増えたとき

## 残る危険と対策

| 危険 | 対策 |
| --- | --- |
| 利用コードが渡す途中で盗まれる | 1 回限りで有効期限が短い。先に使われると研究者が「使用済み」に気づくので、その PC を止めて再発行する |
| PC から端末トークンがコピーされる | DPAPI で暗号化しているので、別の PC や別のユーザーでは読めない。被害はその 1 台の月の上限まで。その PC を止める |
| Cloudflare のアカウントや管理者トークンの乗っ取り | Cloudflare の 2 段階認証。管理者トークンはオーナーの PC だけに置き、定期的に更新する。Modal と OpenAI の支出上限は残す |
| 画像が Cloudflare を通る | Worker は保存も記録もしない（試験で固定）。Worker のコードを書き換えられると記録されるおそれがあり、Modal の乗っ取りと同じ種類の危険になる |
| 不正な要求の大量送信 | 鍵のない要求は、Modal・OpenAI の手前で拒否する。送信元ごとの回数制限をかける |
