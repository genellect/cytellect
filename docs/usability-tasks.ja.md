# Wet研究者による操作評価課題

**未実施の評価計画・評価担当者向けです。** 公開済みのWindows版 0.1.0-local.11を対象にします。実施するPCで事前に起動・動作を確認してください。配布版の自動検証と、研究者による操作評価は別です。

[クイックスタート](quickstart.ja.md)は操作を学ぶための資料です。自力操作を評価する場合は、課題を行う前に渡さないでください。各課題の準備・成功条件も参加者には見せず、引用枠の文章だけを伝えます。

## 評価することと実施条件

目的は「画像解析や統計用コードを書かない研究者が、目的を定め、原画像を確認し、実験単位を保った図を作れるか」。自動ブラウザ試験の成功や見た目の改善を、人による使いやすさの証拠には数えない。

- できれば異なる研究室の3名以上。Fijiを日常使用／時々使用／未経験を記録する。各課題は独立した開始状態を用意し、前課題の失敗が後課題を妨げないようにする。
- デスクトップで主操作を行う。390px相当では、完了した結果と元画像を探す課題だけを追加観察できる。スマートフォンでの精密輪郭編集を必須成功条件にしない。
- 読み上げるのは各節の「参加者への課題」だけ。ボタン名、タブ順、正しい設定値は教えない。沈黙した場合の中立的な問いは「今、何を確かめようとしていますか」。操作箇所を教えたら支援ありとして記録する。
- 記録は所要時間、停滞箇所、誤操作、やり直し回数、支援内容、本人の説明。初回は時間を合否基準にしない。目安時間を超えたら一度状態を記録し、継続／中止を参加者が選ぶ。
- 各課題を **自力完了／説明支援で完了／操作支援で完了／未完了／安全上重要な誤解** に分ける。たとえば未確認の染色や独立実験単位を推測して埋めた場合、図が出ても自力完了としない。
- 公開実画像は記録済みの出典・染色・利用条件を同梱する。BBBC013の核染色はDRAQ、蛍光はFKHR-EGFP。歴史的ファイル名の `dapi` を実際の染色名として説明しない。合成数値画像は操作・統計構造の練習用であると明示する。
- 研究者本人の未公開画像はこの評価へ混ぜない。記録やスクリーンショットには参加者の研究テーマ・実験条件・認証情報を残さない。

## 1．測りたいことを、実画像で確認する解析へ引き継ぐ

**参加者への課題**

> 共同研究者から、画像中の指定された場所の蛍光の平均を測ってほしいと頼まれました。まず、どのような解析を行うかを整理してください。その内容を新しい作業へ引き継ぎ、提供した画像で測る対象と値を決めてください。分からない条件は、分からないまま扱って構いません。

**観察者の準備**：実行可能な候補版の `/plan` から開始。公開BBBC013 A01のFKHR-EGFP 2DグレースケールTIFF、出典、撮影記録で分かること／不明なこと、対象位置の参照図を渡す。手動領域を用いる課題とし、細胞全体の自動検出は求めない。参照図の領域は操作練習用であり細胞境界の正解と呼ばない。

**自力完了の観察条件**

- 意図に合う実行候補を本人が選び、新しい作業へ引き継ぐ。計画の選択が画像確認の代わりにはならないと理解する。
- 実際のチャンネル名と画像の対応を確認し、平均の原値／背景補正値のどちらを測るかを区別して選ぶ。
- 背景を画像上で確認する必要に気づく。撮影記録にない染色、校正、独立性を推測で「確認済み」にしない。

**失敗・重要な誤解**：計画で「ある」と答えたため実画像も確認済みだと思う／平均ではなく先頭の面積や積算を意図せず採用する／候補がないまま架空の条件を入力して進める。

**追加観察（別参加者に割当可）**：公開Webで保存した計画メモを実行環境へ持ち込む。同一画面内の引継ぎとJSON取込を1回の成功として合算しない。旧形式のメモから実行できない場合、内容を見直す必要を理解できれば適切な停止である。

実装・自動検証：[計画画面](../apps/web/src/components/AnalysisPlanner.tsx)、[画像側の採用](../apps/web/src/components/PlanResolutionPanel.tsx)、[引継ぎ試験](../apps/web/tests/plan-batch-workflow.spec.ts)。

## 2．複数視野を、取り違えずに登録する

**参加者への課題**

> 2視野を2つのチャンネルで撮影した画像一式と、記録表を受け取りました。各視野の画像が正しく組になるよう登録し、画像を確認できるところまで進めてください。分からない実験情報を補う必要はありません。

**観察者の準備**：出典付きBBBC013 A01/A06のDRAQ/FKHR-EGFP、2視野×2チャンネルを用意する。ファイル末尾とチャンネルの関係は撮影記録に記載し、ファイル名自体は独立実験単位を表さない。別コピーでは1枚不足した状態から始め、本人が不足を認識した後に残りを渡す。ネットワーク障害を入れる場合は公開・練習データだけの専用環境で、サーバー受領後の応答喪失1回に限定する。

**自力完了の観察条件**

- 対応表で2視野×2チャンネルを確認し、不足・重複を解消してから送信する。
- 共通情報と視野固有の情報を区別し、不明な独立実験単位を空欄のまま残す。
- 失敗があれば未登録分を再試行し、最終の視野数が2であることを確認する。
- 登録後に画像へ進める。登録表を再び開いて確認できる。

**失敗・重要な誤解**：取り違えた組合せを送信する／ファイル数・視野数を独立反復数にする／エラー後に全画像を別作業へ登録し直して二重化する／登録成功後に次の操作を発見できない。

**追加観察**：同じ画素サイズを値の候補として残した次の画像群でも、撮影記録の再確認が必要と理解できるか。校正が不明ならµmを作らずpxで進められるか。

実装・自動検証：[一括登録](../apps/web/src/components/RegionBatchUploadPanel.tsx)、[対応と再試行の試験](../apps/web/tests/plan-batch-workflow.spec.ts)。

## 3．代表視野で直した領域を、残りの解析に残す

**参加者への課題**

> 登録済み画像で、核の中にある蛍光を測りたいと考えています。まず1視野で領域が妥当かを確かめてください。対象として残したくない領域が1つあります。その扱いを決め、残りの視野も同じ方針で測定してください。先ほどの判断が最終結果にも残っていることを示してください。

**観察者の準備**：上記の公開2視野を登録済み・未解析の状態にする。核染色がDRAQであることを記録として渡す。除く領域は「操作課題として対象外に指定した場所」と明示し、生物学的な検出誤りと断定しない。2視野の関係は未知のままにする。背景候補も生物学的にcell-freeと保証せず、課題中の判断理由を観察する。

**自力完了の観察条件**

- 自動検出に使う実チャンネルを選び、核染色であることを実資料から確認する。
- 代表視野だけで試し、対象外の領域について削除または理由付き除外を選ぶ。本人の選択理由を記録する。
- 条件を変えずに残りを測定し、最初に変更した領域／採否が保たれたことを元画像と表で確認する。
- 核全体が細胞全体を表すわけではないと区別できる。

**失敗・重要な誤解**：全視野を無確認で再検出し修正を失う／表示ゲインで測定値も変わると思う／核染色から得た領域を細胞境界と解釈する。

**境界**：任意構造や細胞全体の自動検出は対象外。検出条件を変更した場合は再検出範囲の明示確認が必要で、以前の修正を自動的に意味保存したとは扱わない。公開画像で領域を操作できたことは検出精度の人による評価とは別。

実装・自動検証：[領域の解析画面](../apps/web/src/components/GenericWorkbench.tsx)、[核検出と修正保持の試験](../apps/web/tests/nuclear-region-comparison.spec.ts)。

## 4．反復情報が不明でも分布を示し、元画像まで戻る

**参加者への課題**

> まだ独立した反復実験かどうかを確認できていません。打合せ用に、今測れた値の分布を示す図を作って保存してください。図を見た共同研究者から「この点はどの画像の、どの領域に由来しますか」と聞かれたとして、根拠を示してください。

**観察者の準備**：領域・背景・採否が確認済みの作業を用意する。独立実験単位は未設定。対象チャンネルと指標を依頼カードに明記する。計画採用済み版を使う場合、保存済み計画のチャンネル・指標と一致することも観察する。

**自力完了の観察条件**

- 独立性が不明でも記述用の分布図と元の測定表を保存する。p値や独立反復数を要求するために情報を捏造しない。
- 図のチャンネル、原値／補正値、単位、元の解析版を説明できる。
- 元画像へ戻る導線と測定表を組み合わせ、少なくとも1つの値の視野と領域IDをたどれる。
- 保存パッケージに条件と測定値が含まれ、原画像を含めるかは別の選択だと理解する。

**失敗・重要な誤解**：細胞数を独立nと説明する／保存済みの旧条件の図を現在の指標で作った図だと思う／SVGの見た目が整っていれば科学的妥当性も保証されたと思う。

**未対応の操作を成功条件にしない**：現在の静的な図で点をクリックして画像の対応領域を自動選択する機能はない。図→視野のリンク、測定CSV、領域IDを使う。GUIだけでZIP再実行する仕組みや図内要素の自由な直接編集も今回の課題外。

実装・自動検証：[記述図](../apps/web/src/components/DescriptivePanel.tsx)、[元画像・保存の試験](../apps/web/tests/generic-workspace.spec.ts)。

## 5．実験記録に従って群を比較し、何をnと数えたか説明する

**参加者への課題**

> 提供した練習用の実験記録に従って、対照と処置の差を図と表で示してください。共同研究者へ、何を1回の独立した実験として数えたか、どの試料を比較したかを説明してください。記録が足りなければ、そのまま進めず、何が不足しているかを伝えてください。

**観察者の準備**：既知画素の数値検証画像6視野と確認済みマスクを使う。これは人工的な記録・画像であり実研究結果ではないと明記。独立群版はControl/Treatmentそれぞれ3単位、各視野と試料・単位の対応、同一尺度の取得条件を記録カードで渡す。別版は対応3ペアの根拠を渡す。両方を1人へ連続実施するより参加者間で割り当てる。欠測版では1単位の記録を意図的に不足させる。

依頼カードには「検証信号の領域内平均（背景補正）を比較する」と記し、測定目的を明確にする。画面のボタン名や操作順は示さない。

独立性の理解を評価するには、少なくとも1単位に複数視野を含め、視野数と独立単位数が異なる人工画像・記録の別版を事前に準備する必要がある。現在の6視野版は1視野につき1単位であるため、この版だけで視野数と独立反復数の取り違えを検証済みとしない。別版の準備・実施は未完了である。

**自力完了の観察条件**

- 記録に従って条件・試料・実験単位を設定し、独立群／対応ありを明示的に選ぶ。
- 記録にない対応関係を作らない。必要な情報が不足する版では比較を止め、不足項目を特定する。
- 完全な記録の版では、条件ごとの独立単位数または完全ペア数が各3で、領域数・視野数とは別であると説明する。
- 差の向き、未補正pとHolm補正p、95%区間の扱いを画面から区別できる。説明に専門家の補助が必要なら、その箇所を記録する。
- SVG/PDFと比較表を保存し、対象の解析版・条件へ戻れる。

**失敗・重要な誤解**：視野や領域を新しい独立単位として増やす／対応の根拠がないのに対応ありへ切替える／有意になるまで比較集合や対象を変える／欠測を黙って除く。

**境界**：この課題は実験デザインの理解と現UIの到達性を評価する。正しいp値の再計算は既存の独立数値検証で扱い、人の操作試験へ重複させない。一般マーカーの回帰・自動バッチ補正・混合効果モデルは提供しない。

実装・自動検証：[群間比較](../apps/web/src/components/RegionComparisonPanel.tsx)、[既知画素の比較試験](../apps/web/tests/nuclear-region-comparison.spec.ts)。人工画像は値 [40,50,65] / [55,75,95]、背景10を用いる。各群3という人工設計を公開画像の生物学的反復に転用しない。

## 対応範囲・実施前の確認

現在のルートは `/`（公開LPまたは実行環境のワークスペース）、`/plan`、`/demo`。解析工程は `/` 内の画面状態で切り替わり、URLに研究内容・計画・認証情報を入れない。

- 本案は計画引継ぎ・一括登録を含むWindows版 0.1.0-local.11の人による評価用。**実施する版のソースSHA・配布物SHA・起動確認を別途記録してから募集する。** 古い配布版と混同しない。公開Webに解析APIがなければ、そこで私有画像を測る課題を行わない。
- 新規セットアップのしやすさは別のオンボーディング課題。今回、インストール済みの環境から開始するときは、インストール成功率を報告しない。
- 汎用入力の初期UIは1〜3チャンネルの別々の2DグレースケールTIFF。一括登録は同じチャンネル構成で利用する。Z/T、任意構造の自動検出、LLMの提案、未知の染色判定は対象外。
- 計画は同一runtime内ならメモリで引き継ぐ。公開Webとローカル版の間は明示したJSONファイルで移す。自動クラウド同期や再読込み後のフォーム保持を期待させない。
- 保存期限は明示操作から24時間。ローカルアプリ終了中に期限を迎えたファイルの物理削除は次回起動時。長期保存先として渡さず、必要な成果物を本人が保存する。
- 以上は文献と現実装に基づく仮説を検証する課題であり、研究者の需要・理解・継続利用を既に確認したという意味ではない。

## 記録用の項目

| 項目 | 記録する内容 |
|---|---|
| 実施環境 | 実施日、配布版、PC、画面幅 |
| 参加者 | 匿名ID、Fiji経験。研究テーマや所属の詳細は不要 |
| 課題結果 | 自力完了／説明支援／操作支援／未完了／重要な誤解 |
| 操作 | 時間、停滞、やり直し、与えた支援 |
| 理解 | 領域、指標、独立単位、図と元画像の対応についての本人の説明 |
| 継続利用 | 別の実験でも使いたいか、妨げになる点 |
