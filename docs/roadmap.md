# ロードマップ

この文書は、目的、現在の実装、PR依存関係、残タスクの参照先です。PR状況は2026年10月22日確認時点であり、着手時にリンク先の状態と対象commitを再確認します。MVP期の機能実装の完了は、追加学習モデルの科学的採用や研究室向け固定Docker版の配布完了を意味しません。[MVP期の記録](archive/roadmap-mvp.md)は経緯として保持し、現在の作業指示には使いません。

## 目的と優先順位

Cytellectは、顕微鏡画像の検出・修正・測定・統計・論文用作図をつなぎ、結果を原画像まで遡って確認できる研究用製品です。今回の成果は、**実画像で核小体・細胞質を正確に捕捉し、定量誤差と手修正の負担を減らすこと**です。教師数、学習更新数、コードや検査の件数は成果の代用にしません。

1. 既存の学習・参照裁定・評価結果を保持し、確認済みの検出誤りと輪郭・定量の悪化を改善する。
2. 現行ローカル製品で、B0に戻せる明示選択式のNCL候補と、その結果来歴を実装・検証する。
3. レビュー後、範囲を限定した本番環境PoCへ進む。自動でPoCを開始したり、既定を変更したりしない。
4. 科学的検証と並行して研究室PC向けDocker配布を準備し、合意した実装を新規環境で確認してから配布可能とする。
5. 細胞質専用の検出・定量を残る目標として進める。NPM1専用の追加学習は現在保留する。

核モデルの追加学習は対象外です。NCLとNPM1の共局在は適用可能性を調べる理由であり、染色条件ごとの性能が等しい証明ではありません。既存の細胞ROIは細胞質そのものではありません。細胞質では適切な全細胞領域から対応する核を除外し、領域・測定・表示を一貫させる必要があります。

重みは選択候補のlockにある固定revision・SHA-256・サイズで取得・照合します。可変の `latest` で置き換えず、必要なローカルcache・再開状態も保持します。取得成功は既定モデルへの採用許可ではありません。

## 実装PRと依存関係

以下はすべて未マージのDraftです。短縮SHAは確認時のheadの識別用で、取得・検証では完全なSHAを使います。Gitの比較baseと、機能を成立させる統合依存は別です。

| PR / head | 実装単位 | 比較baseと統合依存 | 残る受入 |
|---|---|---|---|
| [61](https://github.com/genellect/cytellect/pull/61) / `e5202a96d505` | 固定NCL候補の明示選択、取得・来歴、B0への復帰 | `main` | 実環境で選択・推論・保存・復帰を確認し、科学採用は別判断 |
| [62](https://github.com/genellect/cytellect/pull/62) / `2d080c59c1c3` | 除外された候補を確認履歴として残す | `main`。学習候補との利用は61との統合確認が必要 | 実ブラウザで保存・再読込・修正・Undoを確認。候補履歴は自動採用領域ではない |
| [63](https://github.com/genellect/cytellect/pull/63) / `139498cc897b` | 研究室データのmanual保持 | `main` | API/workerがともに保持し、明示削除・所有権が維持される実環境確認 |
| [64](https://github.com/genellect/cytellect/pull/64) / `6d526d119e92` | 固定版Docker起動とインストール単位の永続領域 | `main`。実配布には63のmanual能力と選択モデルの統合が必要 | 統合イメージ・manifest、新規インストール、保存・再起動の受入 |
| [65](https://github.com/genellect/cytellect/pull/65) / `491c7e4f97d8` | 選択式のNCL輪郭補完と確認証跡 | `review/ncl-envelope-dependencies`。61と62を合わせた比較base | 保存済み出力の再評価と実エンジン実行は別。実エンジン確認はメモリ待ち |
| [66](https://github.com/genellect/cytellect/pull/66) / `b25a8ee72bda` | 固定ソースからAPI/worker/Webのlabイメージを作る経路 | `feat/lab-release-start`（64）。63と選択モデルは自動統合しない | 実ビルド、実内容・モデル同一性、新規環境の受入。build receiptは配布承認ではない |

コード比較の順序は **61・62 → 65** と **64 → 66** です。配布にはさらに63の保持能力が必要です。候補を含む版では61を含む統合と評価、輪郭補完を含む版では62・65も必要です。66は基準モデルのみの明示指定にも対応する設計で、候補検証の失敗を基準版へ自動で置き換えません。これらの依存関係はマージ許可や無検証で統合できる保証ではありません。統合後のcommit・設定・モデルに対して検証とレビューを確認します。

## 残タスクと再開位置

| 工程 | 次に行うこと・完了条件 |
|---|---|
| 保存済み検証から再開 | 固定750と承認済み参照を維持し、メモリ条件を満たした時に準備済み実エンジン検証を実行。入力・重み・条件・生出力・製品出力を固定記録と照合。相違は保存して調査し、結果を合わせるため再調整しない |
| 既知の誤りを改善 | 親核判定での消失、部分的な過小領域、輪郭悪化を処理段階ごとに確認。全参照の検出・定量誤差と悪化を報告し、A/Bレビューを受ける |
| 製品統合と限定PoC | 必要なPRを統合候補で確認し、選択・保存・修正・復帰と来歴を検証。オーナーが範囲を承認したPoCで操作・解析・修正負担を確認。既定切替は別判断 |
| 独立最終評価 | 候補と方法を固定し、未使用実験群、モデル出力から独立した人の参照、許容誤差を整える。条件別・実験群別の評価を終え、限界を含めて採用判断する |
| Docker実ビルド | 63の保持能力等を含む固定統合ソースとモデルで66の経路を検証。実image ID・依存物・モデル・Web origin・保持機能を確認。ビルド完了と配布受入を分ける |
| Docker新規導入 | 未使用のインストール領域で起動し、実画像の保存・修正・再読込・再起動・B0復帰を確認。原画像・結果を永続保持し、対象PCのCPU/GPU・RAM・容量に適合することを確認 |
| 更新・復元 | 全writer停止下でDBとartifactを一体バックアップし、別の空領域へ互換復元。実ホスト保存先と容量の確認を解決して更新・rollbackを実証する。確認前に既存ボリュームへ旧版を接続しない |
| 細胞質 | 適切な実画像・参照と全細胞／核の対応から、専用領域・定量・UIを実装。B0比較と独立評価で捕捉・測定・修正負担を確認し、NCL候補の成功で代用しない |

保存済み出力の比較とソースの独立レビューは進んでいますが、新処理の実エンジン確認、ブラウザ受入、固定配布版の実ビルド・新規導入・復元は未完了です。メタデータ検査、モデル公開、PR作成、プレビュー成功はこれらの成功を意味しません。必須CIも未充足で、禁止された画像検査を省略したことをCI合格と扱いません。

今回の継続作業では画面自動操作を行わず、メモリ不足の検証だけを保留し、独立レビュー・Draft PR・配布準備まで一緒に止めません。これはブラウザ受入の免除ではありません。取得可能な利用枠がいずれか残り5%以下の時は保存して停止し、購入・リセットを行いません。これらは今回のエージェント作業条件で、製品の恒久的な動作仕様ではありません。

## 他エージェントへの引き継ぎと非公開資料

公開側の入口は [AGENTS.md](../AGENTS.md)、[チーム開発ルール](team-development.md)、この文書、対象PRです。Claude Codeは [CLAUDE.md](../CLAUDE.md) から同じ指示を読みます。各PRの差分・head・未完了項目を確認し、別PRのコードが既にmainへ入っていると推定しません。現在の依頼で認められた範囲を優先し、古い記録の停止条件や採用済みという記述を流用しません。

非公開の原画像、参照マスク、実験対応、個別測定値、ローカルのパスはGit・PR・CI・配布物に含めません。詳細な承認・拒否履歴、実行状態、入力とモデルのhash、比較結果、A/Bレビュー、準備済み実行手順は、管理者が保持する既存の研究用記録を参照します。Gitだけではこれらの科学的根拠を再現できません。

Claudeへの資料参照が依頼されても、参照先環境・資料範囲・権限が確定するまで外部へ自動送信しません。同じPCなら許可されたローカル資料の所在を渡し、クラウドへ渡す場合は対象を選別して承認範囲内で共有します。これは[研究データの扱い](team-development.md#6-研究データの扱い)を一般的に緩和するものではありません。

参照できない根拠は「未取得」と明記し、承認や実行成功を推測で補いません。承認済みの事項を再質問する前に既存の裁定記録を確認します。公開用の進捗はこの文書とPRへ更新し、セッション別の引き継ぎ文書を増やしません。非公開資料の参照一覧は既存の研究用実行状態に保持します。

## 今後の計画

### 1. 自研究室での実証

研究室の実画像で、検出精度・操作性・解析時間を評価し、核小体・細胞質のモデルを改良します。

- 既存の承認済み教師、750候補の選定履歴、B0比較を保持します。学習や棚卸しを最初からやり直しません。次の教師・方法・更新数は残る誤りから決め、前景・背景、flowの学習範囲、曖昧境界と損失への影響をレビューしてから変更します。
- 教師は対象染色が明瞭な実画像とし、確認済みの後半取得日のEVを優先します。染色・実験条件・除外歴・重複を確認し、不明瞭な像を輪郭描画や穴埋めで適格化しません。核モデルの追加学習や、NPM1専用学習の自動再開は行いません。
- 参照の採否・境界・不確実領域は人が裁定します。AI下書きや閾値マスクだけを独立した正解としません。最終評価では、2名の研究者による独立参照と一致度・注釈の完全性を確認し、未確認の条件を完了扱いにしません。
- 分割は独立した培養・処理等の実験群を基礎とし、同じ試料由来の切出し・撮影・染色が学習と試験に漏れないようにします。撮影日だけで独立性を推定しません。
- **既存の開発評価と未使用の最終試験を分けます。** 使用済みdevは改善の診断として保持し、未使用実験群による一般化の実証は未達と記録します。候補・条件・許容誤差を固定してから最終評価します。
- モデル、前後処理、製品の領域採否を分け、B0と候補を同じ入力・参照・条件で比較します。輪郭補完の改善を追加学習の成果に合算しません。
- 再現率・適合率・F1（IoU ≥ 0.5）、見逃し・誤検出・融合・分裂、境界、全参照の個別面積誤差と欠損を評価します。PQを使う場合はIoU > 0.5の対応規約を明記します。平均値だけで悪化対象や未対応対象を隠しません。
- 原画素と参照が対応する範囲で輝度・積分強度の誤差を測り、条件別悪化と手修正時間を確認します。実験群単位の不確実性を示し、少数の対象を独立実験数に数えません。
- NCL染色の2D観測領域を対象とし、構造全体の真の体積や全染色条件へ無条件に一般化しません。NPM1や細胞質の性能は別途検証します。

**この精度改善タスクでは、合成画像を学習・推論・画像検査に使わず、合成画像で更新した重みも使用しません。** 実行前に入力とcheckpointの来歴を確認します。既存の汎用テスト群を無条件に実行せず、画像を使わないメタデータ検査と実画像評価を区別します。取り消した旧スクリプトの再実行で過去の主張を復活させません。

実装担当と別のAが製品目的・優先順位、Bが教師・学習・評価の数学的／生物学的妥当性を審査します。両者に同じ確定方針・差分を渡し、教師・方法変更前、候補比較後、採用前にレビューします。未解決のP0/P1は該当工程を止め、訂正を確認したレビュー担当が閉じます。エージェントのレビューは人の参照裁定や科学的な最終評価を代行しません。

### 2. 北里大学の他研究室での実証

研究対象や撮影条件の異なる画像で検証します。あわせて、解析基盤を AWS などのクラウドへ移します。移行先の選定と費用はオーナーが判断します（[比較資料](hosting-costs.ja.md)）。

### 3. 他の研究機関への公開

解析コードは誰でも使える形で公開を続けます。クラウド実行・共同利用・運用支援を、有料提供の候補とします。

### 評価する項目

モデルの検出精度、面積・輝度の測定誤差、手補正にかかる時間。
