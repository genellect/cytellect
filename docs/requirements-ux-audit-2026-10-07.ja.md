## 監査対象と判定方法

- 対象ソース：`00b9e3e` を基点とする `codex/workspace-integration-repair` の未コミット変更を含む作業ツリー。
- 実画面：このPCのDocker版をEdgeで確認。通常の約1272×503〜554、および1920×1080。開始画面、個別画像、同じ視野のチャンネル比較、解析目的の切替、統計、グラフ、測定表を確認した。
- 今回は新しい解析・AI送信・設定保存・画像取り込みを実行していない。タブと表示モードのみ操作した。研究画像、名前、ワークスペースID、測定数値、スクリーンショットは本書に転載しない。
- 「実画面」は今回観察した動作。「コード」は分岐・呼出先から確認した事実。「未確認」は今回再現していない事項。コードが存在するだけで利用可能・科学的に妥当とは判定しない。
- 既存要件、10月6日の仕様書、以後のユーザー訂正を照合。最新の指示を優先し、旧文書のUIへ戻すことを解決策にしない。文献の再調査・アルゴリズムの再選定は行っていない。
- 実装・公開停止は継続。本書の作成以外にソースを変更していない。

## 1. 上位目標

**画像解析に詳しくないWet研究者が、自分の画像について、何を対象に何を測定しているかを理解し、必要な修正と判断を行い、統計と編集可能な論文用グラフまで同じ作業の中で完了できること。**

| 目標 | 必要な具体的要件 | 現状の主要な未達 |
|---|---|---|
| G1 自分の画像を迷わず扱える | 一括取り込み、視野・染色の対応、同一対象を再開後も追跡 | 表示名・染色名の参照元が分散。過去の誤分類は表示修正だけでは解消しない |
| G2 生物学的な対象を検出・修正できる | 核を親とした核小体、GFPの対象選別、別種の手動ROI、原座標での編集 | 汎用画素抽出がGFP/NCLの主要操作として露出。細胞ROIと核編集が未分離 |
| G3 何をしているか操作から分かる | 目的・画像・領域・結果の一致、十分な表示面積、必要な操作への到達 | 選んだ目的と旧結果が同居。表示モードの変更が他の操作と連動しない |
| G4 AIが同じ解析を支援する | 指示を構造化設定へ変換し、同じ領域・指標・比較へ反映 | detectorの接続はあるが、指標・統計・図は表示と実行が別 |
| G5 定量から統計・図まで完了する | 背景補正、実験単位、対象選別、図編集、元画像への追跡 | 補正値の下流未接続。比較図と図編集が別。核小体数比較に操作上の行き止まり |
| G6 結果を再現して渡せる | 採用版・対象・条件の保持、編集可能な図と再実行パッケージ | 核小体要約／GFP選別／自動背景を含む一部出力が再実行パッケージに未対応 |

## 2. 研究者UI：実ブラウザで確認した問題

### UX-01 選んだ解析と、画面に残る結果が一致しない【最優先】

- 要件：U04/U05、最新の「何のために何を解析しているか分かる」。
- 再現：保存済みの汎用領域を表示した状態から「核小体と核質の分布」を選択。右側は核小体の説明に変わるが、画像には前の汎用領域マスクが残る。測定値へ移動すると、その前の領域の表が表示される。
- コード：`ApiWorkspace.tsx:774–778` は該当結果がない場合に解析目的だけ変更。`:888` のタブは表示モードのみ変更。`:893–894` は現在の `item.result` を利用。
- 影響：研究者は核小体の結果を見ていると誤解しうる。数値計算の正しさ以前に対象選択の不具合。
- 合格条件：未実行の目的を選んだ場合、その目的の未実行状態と旧結果の位置づけが明確。別対象の結果を、そのまま選択目的の統計・図として扱えない。

### UX-02 統計の「画像を見る」が画像を開かない【最優先】

- 要件：S11/S12、画像・領域・表・図の相互確認。
- 再現：統計タブの「画像を見る」をクリックしても統計タブに留まり、画像領域は非表示のまま。今回実画面で確認。
- コード：`WorkspaceComparison.tsx:83,120` → `ApiWorkspace.tsx:893` は視野選択のみ。CSS `:501–502` は統計モードの画像を非表示にする。
- 影響：統計の出典をその場で確認できない。集中表示の局所修正で既存導線を壊した回帰。
- 合格条件：保存された比較の正しい視野・領域・測定チャンネルへ戻り、画像が表示される。

### UX-03 大きなDesktopでも画像の比較に画面を使えていない

- 要件：最新の「必要な画像数を適切なサイズで俯瞰」「固定の2枚/4枚切替ではない」。
- 実画面：1920×1080で4チャンネルが横一列、各画像は約322px四方。各枠の下に大きな暗い空白。通常幅では3枚＋1枚になり、表示サイズも揃わない場面があった。
- コード：CSS `:342` の横幅基準の自動列数と伸長する行高。`ApiWorkspace.tsx:883` のタイル構成。
- 影響：画面が大きくても輪郭の確認に使える面積が増えず、比較しづらい。
- 合格条件：対象画像数・画像比率・利用可能な縦横領域に対応し、比較対象の拡大率と表示範囲を把握できる。特定の固定枚数を新たに仕様化しない。

### UX-04 初期設定欄が視野一覧を押し下げる

- 要件：画像の俯瞰と個別確認を主役にする。全画面に同じ設定を並べない。
- 実画面：幅148pxの左列に画像追加、フォルダ追加、全チャンネルの染色編集を常設。通常高さでは視野一覧の大部分が下へ押し出される。統計・グラフでも同じ欄が残る。
- コード：`ApiWorkspace.tsx:877`、CSS `:482`。
- 影響：作業対象を探す場所と、全体に効く設定を変更する場所が競合する。
- 合格条件：染色対応を簡単に確認・訂正できることと、視野一覧を十分に見渡せることが両立する。

### UX-05 未入力のAI欄が、必要な解析操作を押し出す

- 要件：AIは常に使いやすく、画像・統計・図を妨げない。
- 実画面：通常の554px高で、右側505pxのうちAI領域が179pxを占有。解析方法の内容は704pxあり、下の核小体等の操作はスクロールしないと見えない。
- 影響：「AIを見つけやすくする」という修正が、今確認したい画像と条件の操作領域を奪っている。
- 合格条件：AIへのアクセスを保ちつつ、会話していないときも大きな空欄を常設する設計を避ける。会話中の扱いは別に設計する。

### UX-06 タブ変更後の開始位置が不自然

- 実画面：統計内で下方へ移動した後にグラフへ切り替えると、グラフの見出し・測定項目が画面外にある位置から始まる。
- コード：`ApiWorkspace.tsx:888–894` の同じスクロール領域に `hidden` で各内容を切替。
- 影響：どの画面に来たか、何を編集しているか判断しにくい。
- 合格条件：モードごとの開始位置と再訪時の位置保持が意図された動作になっている。

### UX-07 「完了」が何の完了か分からない

- 実画面：視野に「完了」、核は完了、核小体は未実行という状態が同居。測定表は「領域」の番号だけで、目的・構造・染色を表見出しから確認できない。
- コード：`ApiWorkspace.tsx:30,410,883,894`。
- 影響：画像の登録、核検出、核小体検出、測定のどこまで終わったかを別々の文章から推測する必要がある。
- 合格条件：現在の対象と、その対象について終わっている処理が矛盾なく分かる。状態文章を増やすだけでは合格にしない。

### UX-08 目的・設定・操作・説明の階層が混在

- 実画面：「核ごとの輝度」「陽性領域」「核小体と核質」「手で囲む」が同列。測定目的、検出処理、手動操作を同じ選択肢として選ばせている。さらに「手法・条件」「検出設定」「測定条件」「表示と検出の設定」が別々に存在。
- コード：`ApiWorkspace.tsx:35–39,678,780,888`。
- 影響：何を選べば自分の研究目的に進めるか分からない。操作名の言い換えだけでは解消しない。
- 合格条件：研究目的、対象領域、必要な調整の関係が一貫する。主画面には現在の判断に必要なものを出す。

### UX-09 画像比較と描画修正が接続していない

- コード：`ApiWorkspace.tsx:883` の比較タイルには描画保存callbackがなく、個別表示にはある。図の点から元領域へ戻るcallbackも `WorkspaceFigureEditor.tsx:9–12` にない。
- 判定：部分実装。比較表示、個別編集、表から画像への選択は存在するが、それぞれの機能の連続操作は未達。
- 合格条件：俯瞰→対象の選択→修正→元の比較へ戻る、図→元領域の確認が迷わず完了する。

### UX-10 図を作る画面なのに、図より入力フォームが主役

- 実画面：グラフタブは測定項目・軸名・幅・高さ・文字サイズが大きな縦フォームとして並ぶ。開始時に何の図を作るか、元の比較結果との関係が分からない。
- コード：`WorkspaceFigureEditor.tsx:55–84`。軸・寸法の編集機能自体は存在する。
- 合格条件：現在編集している図と元データが明確で、必要な設定を変更して成果物を確認できる。「機能がない」として作り直すのではなく、既存機能の配置と接続を対象にする。

- 染色割当の永続化、所有権・競合確認は実装されている（`channel_assignments.py:82–103`）。ただしsidebarとgridで名称の参照元が異なる（`ApiWorkspace.tsx:877,883`）。割当を直した後の全表示一致は未確認。
- 復元時に視野の表示名を「視野n」へ作り直す（`ApiWorkspace.tsx:222,229`）。初回取り込み時と再開後の同一対象の追跡が弱い。
- 核編集で子領域を無効化し、核小体編集で核質を無効化する主要処理は存在する（`ApiWorkspace.tsx:479–498`）。これを「未実装」として再作成しない。
- 同一upload keyの再試行と別キーの同一画像を区別する処理、原画素とsnapshotの保護も存在する（`regions.py:202–308,383–409`）。今回は破壊試験をしていない。
- 表示・解析・採用・結果が `analysisChoice / displayTarget / channel / item.recipe / item.result` 等に分散。単にstate数が多いことではなく、UX-01のように一致しない状態へ到達できることが問題。

## 6. ソフトウェア開発の進め方で欠けていたもの

1. **要件の正本と優先順位。** `requirements.md:A02` は更新済みだが、`workspace-redesign.md` の検出説明は旧NCL Otsu中心。P05のマーカー範囲なども更新の整合が不十分。最新指示より古い文書を優先する危険がある。
2. **利用者の操作を単位にした受入条件。** 部品・API・数値テストは存在するが、目的を変えて表・統計・図へ移った際の対象一致、図から画像へ戻る操作が合格条件として十分に覆われていない。
3. **テスト対象の正しさ。** `workspace-api.spec.ts:62–75` は現在の汎用陽性メニューの存在と切替を確認している。テスト成功は、そのメニューが要求に合うことの証明ではない。
4. **変更の影響範囲。** 集中表示で画像を隠した際に「画像を見る」を合わせて変更していない。AIのdetector追加で一括実行を合わせて確認していない。
5. **出荷の単位。** 表示、検出、補正、比較、保存の個別成功を一巡の完成として扱った。未対応の下流が残る状態で、新しい主導線を完了扱いにすべきでなかった。

## 7. 承認前に確定すべき修正範囲

新しい文献探索や機能追加ではなく、次の境界がレビュー対象になる。

| 優先 | 修正対象のまとまり | 合格条件の例 |
|---|---|---|
| 1 | 目的・対象領域・測定値・表示結果の一致 | 目的変更後に旧結果を新目的の結果として扱わない。染色と測定単位を常に追える |
| 2 | 研究者の一連の画面操作 | 俯瞰、個別修正、統計、図編集、元画像確認が途切れない。通常幅と1920幅の両方で必要な対象が読める |
| 3 | 既存核／核小体／GFP処理への正しい接続 | 合意済み手法を使用し、対象構造に合わない汎用画素抽出へ黙って置換しない |
| 4 | 手動設定・AI設定・一括実行の一致 | 採用した条件が代表視野と全視野、指標・選別・比較・図に同じ意味で反映される |
| 5 | 補正・統計・編集・再現出力の完結 | 主研究用途の条件を変えずに比較・図・再実行パッケージまで到達できる |

この表は着手承認ではない。次段階は、上記不整合に対応する操作設計と変更範囲のレビュー。承認前に実装・Docker更新・本番公開へ進まない。

## 8. 今回の監査で確認していないこと

- 新版での再取り込み、Fiji再実行、手動ROI保存、数値再計算、AI実呼出、統計実行、ダウンロードの新規受入。
- 実画像に対する核小体・GFP検出精度の再評価。
