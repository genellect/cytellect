# Docker Desktop で使う

Windows に Python や Fiji を入れずに、Docker Desktop の Linux コンテナで Cytellect を動かす手順です。Web 画面、API、解析ワーカーの 3 つのコンテナを起動し、この PC のブラウザーから使います。操作はすべてリポジトリの [`scripts/docker-desktop.ps1`](../scripts/docker-desktop.ps1) で行います。

## 必要なもの

- Linux コンテナで動作している Docker Desktop（Docker Compose 2.24.4 以降）
- このリポジトリを置いたフォルダー
- 初回ビルド用のインターネット接続と、数 GB 以上の空き容量。解析ワーカーのイメージには、Linux 版 Fiji と Cellpose の実行環境・モデル（約 1.2 GB）が入ります。
- 解析ワーカーに割り当てられるメモリー（上限 5 GiB）

Fiji と Cellpose はビルド中に自動で取得されます。Windows 版や Linux 版の Fiji を別途インストールする必要はありません。

## はじめて使う

1. リポジトリのフォルダーで PowerShell を開き、ビルドと起動を行います。

   ```powershell
   .\scripts\docker-desktop.ps1 Start
   ```

   初回は Fiji と Cellpose の取得を含むため時間がかかります。すべてのサービスが準備できると `Cytellect: http://127.0.0.1:3087/` と表示されます。

2. ブラウザーで [http://127.0.0.1:3087/](http://127.0.0.1:3087/) を開きます。招待コードやパスワードの入力は不要で、この PC の所有者として自動でワークスペースに接続します。

3. [はじめての画像解析](quickstart.ja.md)の「用意するもの」で練習画像を入手し、「1．測ることを決める」から進めます。インストールに関する記述は Windows 版のものなので読み飛ばしてください。公開練習画像 BBBC013 の核染色は DRAQ、蛍光標識は FKHR-EGFP です。この画像の視野を、独立した実験の繰り返しとして扱わないでください。

## 日常の操作

| 操作 | コマンド | 内容 |
|---|---|---|
| 起動して開く | `.\scripts\docker-desktop.ps1 Open` | ビルド済みのイメージで起動し、ブラウザーを開く |
| 更新して起動 | `.\scripts\docker-desktop.ps1 Start` | 現在のソースからビルドし直して起動する |
| 状態の確認 | `.\scripts\docker-desktop.ps1 Status` | 各サービスの状態を表示する |
| 停止 | `.\scripts\docker-desktop.ps1 Stop` | サービスを停止する。画像・解析結果・イメージは残る |

`Stop` で止めていない場合、サービスは Docker Desktop の起動とともに自動で再開します。

### 新しい版に更新する

```powershell
git pull
.\scripts\docker-desktop.ps1 Start
```

`Start` は変更のない依存関係と Fiji・Cellpose のレイヤーを再利用し、変更された部分だけをビルドし直します。保存データはそのまま引き継がれます。更新のために `docker compose down -v`、Docker の prune、Docker Desktop の初期化を行わないでください。保存データが失われます。

## データの保存と保存期限

- 画像と解析結果は、Docker が管理する専用ボリューム `cytellect-human-e2e_research` に保存されます。Git の作業フォルダーや Windows 版の保存先とは別です。
- 作業データは、最後に明示的な操作をしてから 24 時間で削除されます。停止中に期限を過ぎたデータは、次に起動したときに削除されます。必要な結果は期限内に書き出してください。
- ボリュームを削除すると、作業データと、この PC の所有者としての接続情報がすべて失われます。

期限なしで保持したい研究室は、[研究室で作業データを手動保持する](#研究室で作業データを手動保持する)を参照してください。

## 通信と安全性

- Web（3087）と API（8001）は `127.0.0.1` にだけ公開され、この PC からのみ接続できます。招待コードなしで接続できるのは、この公開範囲が前提です。ポートを `0.0.0.0` で公開したり、外部のプロキシの背後に置いたりしないでください。
- ブラウザーのログイン状態は 7 日間有効で、期限が切れても画面を開き直せば同じ所有者として再接続します。
- 解析ワーカーはネットワークなし（`network_mode: none`）、非 root ユーザー、読み取り専用のルートファイルシステム、メモリー上限 5 GiB で動作します。
- API コンテナは Docker Desktop のポート転送のためにブリッジネットワークにも接続するため、API 自体の外向き通信が遮断される保証はありません。
- このローカル解析画面は GA4 を読み込みません。

## 困ったとき

- **`Start Docker Desktop and wait until its Linux engine is running.` と表示される:** Docker Desktop を起動し、Linux エンジンの準備が終わってから再実行してください。Docker Desktop 自体がエラーを表示している場合は、Cytellect を入れ直しても解決しません。
- **3087 または 8001 ポートが使用中:** そのポートを使っているアプリを確認し、ポートを空けてください。自動接続は `127.0.0.1:3087`（Web）と `127.0.0.1:8001`（API）に固定されているため、Compose のポートを変更すると接続できなくなります。
- **Windows で `dockerInference` ソケットのエラー 1920 が出る:** 原因を確認する前に Factory Reset や WSL の削除を行わないでください。保存データが失われます。
- **起動後に画面が「接続を確認しています」から進まない、またはエラーになる:** `Status` で全サービスが起動しているか確認し、「再接続」を押してください。

この手順での動作確認は Docker 版の確認です。Windows ネイティブ版のインストール確認や、利用者による使いやすさの評価とは別に記録します。

## 研究室で作業データを手動保持する

研究室向けの任意設定 [`infra/compose.lab.yaml`](../infra/compose.lab.yaml) を使うと、作業データを 24 時間で削除せず、利用者がアプリ内で削除するまで保持できます（保存方式 `manual`）。PC の停止や再起動でも期限切れになりません。画面には手動保持であることが表示され、期限延長の操作は表示されません。ログイン状態の有効期限、所有権の確認、ジョブの停止・取消、明示的な削除は通常どおり働きます。

この設定は実装済みですが、配布物としての受入確認はまだです。固定版イメージの配布や、検証済みのバックアップ手段は含みません。

### 研究室用インストールを起動する

手動保持は、通常のインストールとは別名の、研究室用インストールにだけ適用します。通常の設定に重ねたり、稼働中のインストールを切り替えたりしないでください。

1. 通常のインストールを停止します。研究室用も同じポートを使うため、同時には起動できません。

   ```powershell
   .\scripts\docker-desktop.ps1 Stop
   ```

2. 研究室用インストールをビルドして起動します。データは別のボリューム `cytellect-lab_research` に保存されます。

   ```powershell
   $env:CYTELLECT_RUNTIME_DIR = '/unused'
   docker compose --project-name cytellect-lab -f compose.yaml -f infra\compose.desktop.yaml -f infra\compose.lab.yaml up -d --build --wait --wait-timeout 180
   ```

   `CYTELLECT_RUNTIME_DIR` は Compose の必須変数を満たすための値で、実際の保存先は上記のボリュームです。

3. ブラウザーで [http://127.0.0.1:3087/](http://127.0.0.1:3087/) を開きます。停止・状態確認は、手順 2 と同じ `--project-name` と `-f` の指定で `stop`・`ps` を実行します。`docker-desktop.ps1` は通常のインストールを操作するため、研究室用には使いません。

### 保存方式の切り替えに関する制約

手動保持にしたボリュームには、空の `.manual-workspace-retention` マーカーが置かれます。

- バックアップ・復元では、データベース・成果物と一緒にマーカーも保持してください。
- マーカーのあるボリュームを期限付き保存（TTL）で起動すると、データベースを開く前に停止します。稼働中にマーカーを削除したり、保存方式を切り替えたりしないでください。
- 手動保持から TTL への切り替えには対応していません。保存済みの期限によってデータがすぐに削除される可能性があるためです。
- TTL から手動保持へ切り替えるときは、書き込みを行うすべてのサービスを先に停止してください。古いプロセスで進行中の削除処理は、マーカーでは止められません。
- 手動保持に対応していない古い版で、手動保持のボリュームを開かないでください。戻す必要がある場合は、記録された保存方式に対応するバックアップを復元してください。
- マーカーの作成時は書き込みを同期しますが、停電後の復旧は検証していません。クラッシュに耐えるバックアップを保証するものではありません。

### 手動保持中のデータ管理

手動保持では古いデータが自動で削除されません。研究室で空き容量を監視し、不要な作業をアプリから削除し、必要な結果を書き出してください。名前付きボリュームだけではバックアップになりません。データは別の媒体にもバックアップしてください。データベースと成果物をまとめたバックアップ・復元・ロールバックの検証は、配布の要件として別途残っています。

## 開発者・運用者向け

### 解析結果に記録されるコミット

`docker-desktop.ps1` は、作業フォルダーに未コミットの変更がないとき、現在の Git コミット ID（40 桁）を `CYTELLECT_CODE_REVISION` として API とワーカーに渡し、解析結果の環境記録に残します。未コミットの変更がある場合は空にし、変更を含むビルドをそのコミットとして記録しません。

### 数値と再実行の受入検査

[`scripts/verify_docker_regions.py`](../scripts/verify_docker_regions.py) は、生成したテスト画像を登録し、独立・対応ありの比較、順位検定、相関、出力 ZIP のハッシュ、再計算結果との一致を確認します。研究データの入っていない受入用のインストールを、未コミットの変更がない状態で `Start` してから、[開発環境](../CONTRIBUTING.md)のリポジトリで実行します。出力先はリポジトリの外の、まだ存在しないフォルダーを指定します。

```powershell
uv run python scripts/verify_docker_regions.py --docker docker --container cytellect-human-e2e-api-1 --api-origin http://127.0.0.1:8001 --web-origin http://127.0.0.1:3087 --expected-source (git rev-parse HEAD) --output <リポジトリ外の新しいフォルダー>
```

この検査は Docker の招待認証を使い、Windows 版のインストール確認には数えません。生物学的な妥当性を確認するものでもありません。

### 解析提案の中継

運用者は `-ProposalConfig` で、承認済みの解析提案の中継を有効にできます。設定ファイルの形式と制約は[ローカル版の説明](local.md#workspace-entry-and-desktop-acceptance-2026-10-06)を参照してください。

### 招待コード

`.\scripts\docker-desktop.ps1 Invite` は、24 時間有効で一度だけ使える招待コードを発行します。Docker Desktop 版は招待コードなしで接続するため、通常の利用では使いません。発行する場合は自分だけが見られる端末で行い、Issue、チャット、共有ログに貼り付けないでください。
