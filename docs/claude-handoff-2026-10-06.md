## ユーザーの目的と優先順位

Wet研究者が、多数の2D蛍光画像を一括で取り込み、解析方法を組み立て、領域検出・修正、面積／輝度定量、統計解析、編集可能な論文図の保存まで、一つのワークスペースで進める製品。対象を特定の染色・一研究室のファイル名へ固定しない。最初の実用ワークフローは核、GFP、NCL核小体の解析である。

優先順位は、(1)研究者が実際に操作できる統合UIと入力→正しい領域→測定の接続、(2)核内GFP・核小体と手描画、(3)意図して選べる統計・図編集、(4)再現性・回帰チェック・Git反映と公開。ユーザーの目視確認用Dockerを更新してすぐ見せ、長い検証が終わるまで可視改善を隠さない。ただしビルド成功を正しい検出やUI合格と呼ばない。

### 最新のUX要件 — ここを取り違えない

1. **画像だけを中央に置く画面ではない。** 画像一覧、選択画像とマスク、解析操作、測定値、統計、図編集、AIがつながった統合画面にする。
2. 個別画像の輪郭修正と、必要な複数画像の並列比較を両立する。全体一覧を消さない。固定2枚／4枚、全チャンネル強制表示、別ページへの分断は不要。
3. 作業に応じて画像／統計／グラフの使う面積を変えてよいが、画像・領域・測定結果の文脈と採用版を失わない。単に4つの独立画面を作る案は撤回されている。
4. 原画像の縦横比を保つ。横長の枠の中に小さい正方形画像を置いて大量の横余白を作らない。原寸・拡大・パン・輪郭表示を操作できる。縮小率やCSSが合っていても読めなければ未達。
5. Desktop全画面で主要作業を完結させる。外側ページを何度も上下移動させない。詳細リスト内スクロールは必要に応じて使う。

9. アプリ文言は明快な操作名と対象。感情的コピー、AI的な曖昧な日本語、「測りたいことから、解析を選ぶ」「解析案の補助」などは不採用。単に文言だけ差し替えて情報設計を放置しない。

11. AIは小さな補足欄ではなく、同じ解析設定につながる明確な入口。複数行を書ける幅・高さと会話／提案の領域を確保する。ChatGPTのような簡潔さを参考にするが、画像・解析操作をチャットへ追い出さない。

## 画像・検出・測定の要件

- フォルダ／複数ファイルを一括追加できる。ファイル名変更、一枚ずつのアップロード、研究固有の命名規則は要求しない。単染色の独立視野と、視野ごとのチャンネル分割画像を扱う。対応付け・欠落・重複・部分失敗を黙って捨てない。
- チャンネル名から染色を決めつけない。DAPI／GFP／NCLの役割はメタデータと利用者選択を記録する。特定のc番号を一般ユーザーの既定にしない。
- 元画像を保持し、表示・検出前処理・測定を分離する。グレースケールを勝手にRGB合成しない。元がRGB表示TIFFの場合は元RGBを表示し、`max(R,G,B)`の表示コード測定という互換仕様を区別する。カメラ原輝度を復元したとは言わない。
- Fiji / StarDist 2Dの固定版・モデルを使う。核を認識し、その輪郭を**測定・統計を進める前に**目視できることが重要。核用モデルを核小体モデルとして扱わない。
- 検出の縮小座標と表示座標を検証し、原画像座標の整数マスクを正本にする。核変更で依存GFP／核小体／核質と統計・図を旧版にする。
- 核内GFP高輝度画素領域とGFP陽性核／細胞の選別は別。高輝度画素の存在だけで親核を陽性としない。核だけから細胞全体境界を推定しない。核外・細胞全体は手動ROIを使う。
- 核小体は採用済み核内のNCL濃縮候補。ストレスによる再分布を考慮し、Otsu／手動しきい値、平滑化・面積条件等を調整して輪郭を見られること。NCLから領域を作る循環性はMethodsに記録する。候補なし／判定困難／失敗を区別し、無理に核全体や上位画素を候補へ置換しない。
- **利用者が自分で描画する**機能が必要。「自分で癖」は誤入力で「描画」と訂正された。追加・輪郭修正・削除・結合・分割、Undo/Redo、保存後の原画素再測定が目標。現行新UIは追加・置換・削除・除外・Undo/Redoまでの接続で、結合／分割は未接続。
- 核質は採用した核から、採用した核小体和集合を引く。手修正した核小体を捨てて再閾値処理した核質を黙って出してはいけない。親ID・欠測を維持する。
- 画素サイズ不明時はpx。背景は確認した背景ROI中央値、核外全体を背景にしない。原値／補正値を併記し負値を通常解析で切り詰めない。無効な比に任意epsilonを足さない。既存再現レシピのepsilon等は別版。
- UBF、3D、時系列、FISH、FRAP等は初期対象外。RNA/DNA等の既測定CSV比較は要件に残る。

## 統計・図・再現性

- 細胞数・視野数・独立実験単位数を分ける。独立反復を細胞数で置き換えない。対応関係、対照、群と撮影日の交絡、欠測、失敗視野、少数クラスタ、推定不能を扱う。
- 既存の共通統計実装と `docs/common-statistics.md` を使う。Welch／対応あり、事前比較集合のHolm、関連・回帰、リピート長等の計画を保持する。EVを自動GFP陰性や長さ0としない。未確認反復は記述統計として扱う。
- 研究者が測定項目、図の構成、軸、範囲・目盛、群・点表示を編集できること。「書き出し図」の大量一覧やファイル形式の選択を要求しない。
- **一つの保存操作**で、画面で編集したものと同じ編集可能SVG/PDF・元測定値・設定を出す。現在はZIP一本にまとめる実装。別レンダラーで適当なプレビューを作らない。
- Publication-readyは雑誌掲載保証ではなく、編集可能性、明示条件、追跡可能数値、再実行可能性。実画像評価、参照計算、統計妥当性、図の可読性を別々に確認する。
- 公開論文・公開生画像を複数分野の手法と突き合わせる。合成画像だけを研究者向け実証の代用にしない。一方、既知画素・統計の数値試験には合成を使う。画像／モデルの出典と利用条件は記録する。

### 標準コマンド

Node24、pnpmはpackageManagerの固定版、Python/uvはlockfileとCIに従う。

```sh
uv sync --locked --dev
pnpm install --frozen-lockfile
uv run pytest tests -m "not fiji"
uv run ruff check .
uv run mypy packages/analysis/src services
pnpm check
pnpm test
pnpm build
```

OpenAPI生成は`CYTELLECT_DATA_DIR`にrepo外の専用一時runtimeを設定してから:

```sh
uv run cytellect openapi --output packages/contracts/openapi.json --recipe-defaults apps/web/src/lib/recipe-defaults.json
pnpm contracts
```

Dockerは `compose.yaml`＋`infra/compose.desktop.yaml`、必要時だけ`infra/compose.proposal.yaml`を使用する。private runtime/secretファイルの設定は各文書に従う。クラウドの架空パスを作って認証成功と扱わない。研究volumeに対して`down -v`、prune、再初期化を行わない。
