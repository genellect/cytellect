# CI の構成

CI は、品質を落とさずにマージまでの待ちを短くするため、検査を 3 つの段階に分ける。

| 段階 | 実行するジョブ | 役割 |
|---|---|---|
| PR | 変更したファイルに関係するジョブ（統合試験を除く） | 速く問題を返す |
| マージ前の一括検証 | すべてのジョブ（統合試験を含む） | `main` に入る組み合わせをそのまま確かめる |
| `main` | すべてのジョブ | 配布するコミットの根拠を残す |

手元では `python3 scripts/dev.py check` で、PR の `python` と `web` のジョブと同じ検査を実行できる（[CONTRIBUTING](../CONTRIBUTING.md)）。

## ジョブ

| ジョブ | 確かめること | PR で実行する条件 |
|---|---|---|
| `python` | Linux でのテスト一式、lint と型、公開デモの実行環境と解析ソースの一致、依存の監査、シークレット走査 | 常に（テスト一式は Python に関わる変更のとき） |
| `web` | Web のビルドと試験、API 契約、公開サイトのブラウザ試験、ローカル版の Web 出力と配布物の境界 | Web・API に関わる変更 |
| `lp` | LP のビルドとブラウザ試験 | LP だけの変更 |
| `local-windows` | Windows のセットアップとランチャー | Windows 版に関わる変更 |
| `python-windows-314` | Windows・Python 3.14 でのテスト一式 | Windows 版に関わる変更 |
| `fiji-browser` | 実際の Fiji、API とブラウザの連携、本番のコンテナ | 実行しない |
| `cellpose-gpu-image` | GPU 推論のイメージが CPU 版と同じラベルを返すこと | 実行しない |
| `windows-installed` | 配布 ZIP の新規導入と、前の版からの更新 | 実行しない |

CI 1 回の待ちは、最も長い `python-windows-314`（約 34 分）で決まる。分割に向けて、遅いテスト 40 件の時間を記録している。

## PR で実行するジョブの選び方

`scripts/ci_changes.py` が、変更したファイルからジョブを選ぶ。規則の正本はこのスクリプトで、試験は `tests/test_ci_changes.py` にある。

- 文書だけの変更（`docs/**`、ルートの Markdown、PR・Issue のテンプレート、`LICENSE`、`NOTICE`）では、重いジョブを実行しない。
- LP だけの変更では `lp` だけを実行する。LP の素材は Windows 版にも含まれるため、`python` も実行する。
- workflow、lockfile、パッケージの定義、規則にないパスでは、すべてのジョブを実行する。トップレベルのディレクトリを追加するときは、規則と試験も更新する。

公開ツリー・文書のリンク・シークレット走査は、どの変更でも実行する。実行しなかったジョブは、ブランチ保護には成功として報告される。

## マージ前に境界を確かめる

統合試験は PR では実行しない。そこで、統合試験で初めて見つかっていた失敗のうち、数十秒で確かめられるものは PR のジョブで確かめる。

- **ローカル版の Web 出力**（`web`）：生成するファイルが配布物の許可リストに収まるか。例：`sitemap.xml` を加えたとき。
- **公開デモの実行環境**（`python`）：ブラウザで動かす Cytellect のホイールが、解析のソースと一致するか。Python を変えたら、同じ PR で作り直す（[公開デモ](showcase.md)）。

どちらも、検査する側のスクリプトと検査される側のファイルの、どちらを変えても実行される。

## マージ

マージはオーナーが行う。マージする PR をまとめて最新の `main` に取り込み、すべてのジョブを 1 回だけ実行してからマージする。手順は[チーム開発ルール](team-development.md)の「開発の流れ」の手順 6 にある。待ちは PR の本数によらず CI 1 回分で、`main` に入る組み合わせそのものを統合試験まで確かめられる。このリポジトリは個人アカウントの所有でマージキューを使えないため、この手順で代える。

## 配布の条件

Windows 版は、配布する `main` のコミットで次の 7 つのジョブがすべて成功している場合にだけ配布する（`.github/workflows/local-release.yml` が確かめる）。

`python`、`web`、`fiji-browser`、`cellpose-gpu-image`、`local-windows`、`windows-installed`、`python-windows-314`

`main` で失敗した場合は、次の配布までに修正するか取り消す。

## 依存パッケージの記録とシークレット走査

シークレット走査は、固定版の gitleaks を検証してから、Git の全履歴と追跡中のファイルを調べる。そのため CI は `fetch-depth: 0` で checkout し、保存するのは件数と規則 ID だけ。

依存パッケージの記録は、Python パッケージのライセンスの根拠や、Web の直接依存のライセンス本文が欠けていると失敗する。この分類と表示の収集は根拠の確認であって、法的な適合性の判断ではない。範囲は [OSS の管理](oss.md) を参照する。依存の記録とシークレット走査の要約は 7 日で消える。生の検出結果、ログ、研究データを、成果物のアップロード対象に加えない。

## 日本語フォントの導入

図の描画に使う日本語フォント（`fonts-noto-cjk`、約 61 MB）は、Linux のジョブで `scripts/install_figure_font.sh` が導入する。遅いミラーで `python` ジョブが 30 分の上限に達したことがあるため、取得が 20 秒続けて遅いミラーは打ち切り、別の公式ミラーで続きから取得する。導入するのは、apt の署名済みの索引にある SHA-256 と一致したファイルだけで、`dpkg` で直接導入する（`apt-get` は同じ版を遅いミラーから取り直すことがある）。
