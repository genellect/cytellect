label regions by the analysis package and fresh Docker execution. Independent
area, mean, median and integrated values from unchanged original pixels matched
the saved measurements. Adopted StarDist labels, parent review states and the
adoption ledger were unchanged. No masks were automatically adopted.

and matching measurement table after the normal Docker build. AI-panel navigation
returned to the same analysis settings and result without sending a proposal.

overflow or captured browser errors. The canonical Vercel deployment identity
was verified independently of the local Docker identity.

old/current client-contract probes. One public method-only live call through
the existing local API relay client returned detector protocol 4.3.0 and passed
local semantic validation. No private specimen data, paths, values, images or
credentials were transmitted. The existing monthly USD 5 budget remains in
effect; no OpenAI production credential was copied or rotated.

A read-only post-call D1 check found no outstanding reservations or unresolved
budget incidents. It made no database changes.

Private labels, specimens, numerical results, paths and browser screenshots
remain outside Git/CI. These checks establish reproduction of the reviewed
specimen partition and the data path, not general biological sensitivity or
ground-truth accuracy on unseen images.

The hosted Web distributes the interface and download guidance. Scientific
image execution remains in the local installation/Docker; the public Vercel
`/workspace` route has no configured hosted analysis API. This release does not
add a cloud scientific server or expose local research data over the Internet.

Windows installed-package acceptance and publication must be recorded separately;
the ordinary release browser suite does not establish the optional Cellpose
runtime. No operating-system application-control policy may be weakened.

## Windows release preparation: retained failure and focused repair

Run `37897607783`, from merged main `e0caeeb7a6468166ed96d2c6db72b46da9575a37`,
passed signed installation, repeat setup and 25 of 26 installed browser cases.
The registered BBBC007 workspace case timed out waiting for its import POST.
Numerical replay was not run, the launcher stopped successfully, and no draft
release or source tag was created. The failed attempt is retained as evidence;
it was not retried unchanged or accepted as a pass.

Source inspection found that the hidden file/folder inputs could accept files
before initial workspace loading completed. The runtime rejects imports during
that exclusive operation and the input then resets. The captured failure log
does not distinguish this load race from an earlier hydration race, so the
repair covers both: all existing intake controls are disabled until workspace
data exist and initialization is no longer busy.

The real BBBC007 browser case holds the first actual workspace-list response,
checks that both inputs remain disabled, releases the unchanged response, waits
for enabled intake, and uploads the registered original files. The separate
comparison case also waits for enabled intake. Case count, timeouts, scientific
algorithms, original pixels and numerical expectations remain unchanged.

Repair CI run `37903837591` passed the actual BBBC007 initialization, import,
Fiji, measurement, correction and export case. A different invitation-entry
UI test failed because its mock returned 404 for the required workspace-list
read after a successful mock login. That fixture now returns an empty owned
list only after authentication, so the test waits for a genuinely initialized
workspace instead of relying on prematurely enabled controls. No production
authentication, timeout, calculation or accepted-result expectation changed.
