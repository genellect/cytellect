# クラウド開発環境：実装計画（案）

作成：2026-10-27。状態：オーナーの承認待ち。

クラウド開発環境の既定の要件を満たし、あわせて人が手元のブラウザで画面を確認できるようにするための計画です。現在の手順は [CONTRIBUTING](../../../CONTRIBUTING.md#クラウド開発) にあり、[チーム開発ルール](../../team-development.md)と [AGENTS.md](../../../AGENTS.md) を前提とします。これらと食い違う場合は、そちらに従います。

## 1. 要件と現状

| 番号 | 要件 | 現状（2026-10-27） |
|---|---|---|
| R1 | 新しい環境を、CONTRIBUTING の手順だけで再現できる | 未確認。セットアップスクリプトが、環境の設定の Default とリポジトリの 2 か所にある |
| R2 | 核の検出（Fiji、StarDist）が配布版と同じに動く | 達成。実際の Fiji での試験と、画面の通しの試験に合格 |
| R3 | GPU 推論（Modal 上の Cellpose-SAM）が動く | 未達成。接続キーは通るが、GPU の割り当て待ちで 503 |
| R4 | 解析提案（Worker 経由の LLM）が画面上で最後まで動く | 未達成。提案に測定指標が含まれないと、画面が `TypeError` で表示できなくなる |
| R5 | 人が手元のブラウザで、配布版と同じ画面を操作できる | 未達成。画面は環境の中の Playwright でしか確認できない |
| R6 | 研究データと認証情報を環境に入れない、出さない | 運用ルールで守っている。技術的には保証していない |

## 2. 方針

- **配布版と同じ部品から作る。** ロックファイル、Fiji の固定版、デプロイ済みの GPU サーバーと Worker を使います。開発環境だけの代わりの部品は作りません。機能が増えても、手順は変わりません。
- **本番の安全設計を緩めない。** Cookie（`SameSite=Strict`）、Origin の照合、招待コードは本番と同じに保ちます。共有のための防御は、その外側に重ねます。
- **正本は一か所。** セットアップの正本はリポジトリのスクリプトです。ツールの版は、リポジトリの固定ファイルを正本とします。

## 3. 共有の構成（R5、R6）

```
手元のブラウザ
  → Cloudflare Access        許可したメールアドレスの人だけを通す
  → Cloudflare Tunnel        環境から外へ向かう接続だけ。受け付け用のポートは開けない
  → Caddy                    1 つのオリジン：/v1 は API へ、それ以外は Web へ
  → dev.py serve             本番と同じ設定。HTTPS なので Secure の Cookie（__Host-）も本番と同じ
```

Web と API を同じオリジンにまとめるのは、Cookie と Origin の照合を緩めずに済ませるためです。Vercel のプレビューに API をつなぐ案は、Cookie を別のサイトに送る設定が必要になるため採りません。共有の URL は HTTPS なので、Secure の Cookie を使えます。この点では、`localhost` での起動よりも本番に近くなります。

| 防御の層 | 内容 |
|---|---|
| 本人確認 | Cloudflare Access で、許可したメールアドレスだけを通す |
| 外への出口だけ | Tunnel は、環境から外へ向かう接続だけで動く |
| 本番と同じ認証 | 招待コード、Cookie、Origin の照合。招待コードは共有の期限と同じ長さにする |
| 公開画像だけ | 共有の間は、登録済みの公開画像のハッシュと一致しない画像の登録を、API が拒否する（WP5） |
| 期限 | 共有は既定で 2 時間後に自動で止まり、Tunnel も一緒に終了する |
| 認証情報 | Tunnel のトークンは環境の設定にだけ置く。解析提案の端末トークンは環境ごとに発行し、個別に失効させられる |

## 4. 作業

| WP | 内容 | 主な変更 | 完了の条件 | 依存 |
|---|---|---|---|---|
| WP1 | 提案に測定指標が含まれないとき、画面が落ちないようにする（R4） | `apps/web` の提案の反映と指標の選択（`ConnectedWorkspace.tsx`、`metric-catalog.ts`） | 指標のない提案を反映しても、画面が表示されたまま指標の選択を求める。単体の試験とブラウザの試験を加える | なし |
| WP2 | GPU 推論を通しで確認する（R3） | 確認だけ（`doctor --live`、`scripts/cellpose_remote_check.py`）。コードは変えない | 公開画像で 200 が返り、検出結果が記録と一致する。結果を roadmap に記録する | Modal の GPU の割り当て |
| WP3 | セットアップの正本を一本化する（R1） | 環境の設定は `bash .claude/cloud-setup.sh` だけにする（オーナーの作業）。CI の uv の版を一か所にまとめる（`.github/workflows`） | 新しい環境で、CONTRIBUTING の手順だけを使い、`doctor` がすべて `[ok]` になる。接続先の一覧を、その結果で確定する | オーナーの作業 |
| WP4 | `dev.py serve --share`（R5） | `scripts/dev.py`。Caddy と cloudflared の固定版をチェックサムを照合して導入する（`.claude/cloud-setup.sh`）。Caddy の設定ファイル | 許可した人だけが、手元のブラウザで招待コードを入れて画面を操作できる。期限が来ると、共有と Tunnel が止まる | WP3、オーナーの作業 |
| WP5 | 公開画像だけを受け付けるモード（R6） | `services/api` の `upload_guard.py` と設定。受け付けるハッシュの一覧は、登録済みの準備スクリプトの出力から作る | 一覧にない画像の登録は 403 になる。本番の既定では無効。試験を加える | なし |
| WP6 | 文書 | CONTRIBUTING の「クラウド開発」の節に共有の手順を短く加える。`docs/security.md` に共有の防御を書く | 文書の検査に合格する。手順は機能名ではなく部品の名前で書く | WP4、WP5 |

## 5. オーナーにお願いすること

| 作業 | 内容 | 費用 |
|---|---|---|
| 接続の確認の承認 | この環境から Cloudflare Tunnel に接続できるかの確認は、セッションの安全機構に止められた。確認してよいかの判断と、必要ならネットワークの設定の変更 | なし |
| ドメイン | 名前付きの Tunnel と Access には、Cloudflare で管理するドメインが必要。既存のドメインを使うか、新しく取得するか | 新しく取得する場合は年額の費用がかかる |
| Cloudflare Zero Trust | Tunnel と、Access のポリシー（許可するメールアドレス）を作る | 無料枠の範囲 |
| 環境の設定 | セットアップスクリプトを `bash .claude/cloud-setup.sh` だけにする。Tunnel のトークンを環境変数に登録する | なし |
| GPU の確認 | Modal の画面で、GPU の割り当てが戻ったかを確認する | 確認の推論は数秒分の課金 |

## 6. 検証

- 各 WP の PR で、[CONTRIBUTING](../../../CONTRIBUTING.md#pr-を出す前に) の検査を行う。
- WP4 と WP5：許可していないアカウントで画面に届かないこと、一覧にない画像の登録が拒否されること、期限で止まることを、公開画像で確かめる。
- 最後に、新しいクラウド環境で、手順書だけを使って R1〜R6 を通しで確かめ、結果を roadmap に記録する。

## 7. 危険と対策

| 危険 | 対策 |
|---|---|
| 許可した人のアカウントが乗っ取られる | 招待コードと公開画像だけの制限で影響を限る。共有は期限付き |
| 共有を止め忘れる | 既定の期限で自動停止する。`doctor` で共有中かどうかを示す |
| 研究画像が誤って登録される | WP5 でハッシュが一致しない画像を拒否する |
| 環境の外向きの接続が制限され、Tunnel が使えない | 最初に接続を確認する（5 の 1 行目）。使えない場合は、代わりの方法をあらためて相談する |
| 開発環境だけの作りが増え、本番との差が広がる | 共有のための部品（Caddy と Tunnel）は API と Web の外側に置き、製品のコードは WP5 の設定 1 つだけにする |

## 8. 進め方

WP1 と WP5 はオーナーの作業を待たずに始められます。先に、それぞれ別の PR で進めます。WP3 と WP4 は、5 の作業が済んでから進めます。WP2 は、GPU の割り当てが戻り次第、確認します。PR は WP ごとに分け、マージはオーナーの指示があったときだけ行います。

## 9. 未確定の点

- 公開画像の準備スクリプトが、毎回同じバイト列の画像を出力するか。出力が変わる場合は、WP5 のハッシュの一覧の作り方を見直す。
- Caddy と cloudflared の固定版の入手先と、チェックサムの確認方法。
