# 核・核小体の測定と比較：実装案（練り直し）

作成：2026-11-21。genellect/cytellect#257 の実装案。オーナーの承認前の案で、承認までは実装しない。

最初の実装（genellect/cytellect#258）は、2026-11-21 にオーナーが画面の変更を却下に等しいと判断し、保留になった。この文書は、その指摘と Issue を読み直して、何を・どの順で・どう確かめて作るかを決め直す。#258 の独立レビュー（別のエージェント）は実行中で、届いたら [§7](#7-258-の変更の扱い) とこの文書に反映する。

## 1. 目的

Issue の最終目標は変えない。画像解析に詳しくない Wet 研究者が、「画像」「実験」「統計」「グラフ」のどの画面でも、次の 3 つを**説明なしに**分かること。

1. 何を対象に、何を測っているか
2. プロダクトが何をしているか、次にどの操作をすればよいか
3. 選んだ指標の結果とグラフが、いま画面に出ているものと一致していること

そのうえで、指標を研究水準へ広げる。指標は、実際の核小体の画像で成り立つことを確かめたものだけを画面に出す。

## 3. 作り直しの原則

1. **`main` の画面が基準。** 配置・密度・図の大きさを保ち、足すものは最小にする。変更前より文字が増える画面は作らない。
2. **文章で説明しない。** 対象・状態・次の一手は、配置・図・色と形・状態の表示で示す。常に出ている説明の段落は足さない。補足は「使い方」と、項目に付く開閉・ツールチップに置く。
3. **結果が主役。** 条件を選んだら結果が出る。確認や設定は、結果の場所を埋めない。
4. **画面の案を先に見せる。** 実装の前に、`main` と同じ場面・同じ条件で並べた画面の案（画像）をオーナーに見せ、合意した案だけを実装する。実装の後にも、同じ条件の変更前後を並べて確かめる。
5. **指標は、実際の核小体の画像で成り立つものだけを出す。** 許容差と判定の規則は、値を見る前に決める（[§5](#5-指標の追加と公開実画像での検証)）。
6. **PR を小さく分ける。** 1 つの PR は 1 つの画面か 1 つの計算。デモの再記録は、画面が固まってから 1 回だけ行う。
7. **合否は目的で決める。** 完了要件の試験に加えて、「`main` と並べて、説明なしに良くなったと分かるか」を画面ごとに確かめる。

## 4. 画面の案

下の図は配置の説明で、見た目の案ではない。見た目は、実装の前に画像で示す（原則 4）。

### 4.1 統計（Issue の D）

**`main` の問題**：左で指標・領域・染色を変えても、結果とグラフは前の指標のまま。「計算」は右の欄の最下部にあり、確認欄が最大 3 つ要る。

**案**

- **保存した結果がある条件**：選んだらすぐ、その結果と図を出す。画面は `main` の結果の表示と同じ。
- **結果がない条件**：結果のカードと図の枠を同じ位置に残し、カードには条件の名前と「計算」だけを置く。文は足さない。

  ```
  ┌ 核小体の平均輝度（NPM1）───────┐  ┌───────────────┐
  │                                │  │                │
  │           [ 計算 ]             │  │  （図の枠）    │
  │                                │  │                │
  └────────────────────────────────┘  └───────────────┘
  ```

- **確認が足りないとき**：確認欄は `main` と同じ右の欄に置いたままにする。「計算」を押すと、足りない確認欄へ移動して強調する。欠測の一覧は「核小体を確定できない核 2 / 151」の 1 行にし、表は開いたときに出す。
- **確認を覚える**：測定領域と視野の確認は領域の組ごとに 1 回、欠測の確認は同じ一覧に 1 回、設計の確認は指標や領域を変えても外さない（D-3）。確認が済んでいれば、条件を選ぶだけで記述（実験回ごとの値と差）を計算する（D-5、2026-11-21 のオーナーの判断）。検定は「計算」を押したときだけ行う。この規則を説明する文は画面に出さない。
- **デモ**：公開データの確認は記録の時点で済んでいるので、訪問者に確認を求めない。条件を選ぶと結果が出る（判断 2）。
- **右の欄**：`main` の配置のまま。実験デザインを宣言している場合だけ、入力欄 2 つ（独立実験単位、対応の根拠）を 1 行の表示に替える（D-6、2026-11-21 のオーナーの判断）。

  ```
  実験回 3 ・ 対応あり ・ 独立性 未確認      実験 ↗
  ```

- **ラベル**：保存した比較のボタン・結果の見出し・現在の条件・保存した図の名前を、「対象の指標（染色名）」にそろえる（B-3）。チャネル ID は出さない。
- **解析が自動で切り替わるとき**：「解析」の欄の下に、理由を 1 行で出す（SR-04）。
- **図**：`main` と同じ体裁・大きさで出す。変更前後で図の画素の大きさが変わらないことを確かめる。

### 4.2 指標の選択（Issue の B）

**`main` の問題**：対象の違う 17 指標が 1 列に並び、対象を決める「領域」が指標の下にある。観測の単位は説明文の途中にしかない。

**案**

- 選ぶ順を「対象 → 指標 → 染色」にする（判断 1）。対象を選ぶと、その対象の指標だけが出る。
- **対象は、文字ではなく絵で選ぶ。** 核の輪郭の中で、測る部分（核全体・核小体・核質）を塗った 3 つの絵のボタンにする。画像の画面の「領域」も同じ絵にそろえる。

  ```
  対象   [ ◯ 核 ] [ ◉ 核小体 ] [ ◐ 核質 ]
  指標   [ 離心率            ▾ ]
  染色   [ NPM1              ▾ ]
  1 点 = 核
  ```

- 観測の単位は「1 点 = 核」「1 点 = 核小体」「1 点 = 視野」の短い表示にする。図の 1 点と同じ言い方にそろえる。指標の定義の文は `main` と同じ場所・同じ量にとどめる。

### 4.3 「実験」（Issue の C）

**`main` の問題**：群と実験回の表が出るだけで、実験回の意味、次の操作、状態が読み取れない。デモではすべての欄が灰色の入力欄で、直せない赤字の警告がある。

**案**

- 見出しを目的で書く（1 行）。段落は置かない。
- **状態は、文ではなく印で出す**（C-2）。そろっているものと足りないものを、色と形で分ける。次へ進むボタンを 1 つ、見出しの右に置く（C-3）。

  ```
  対照と処理を実験回ごとに比べる                         [ 統計で比べる → ]
  ● 実験回 3   ● 群 2   ● 視野 18   ▲ 独立性 未確認（記述のみ）
  ```

- **実験回の意味とまとめ方は、小さな図 1 つで示す**（C-1）。核の点 → 視野 → 実験回 → 回ごとの差を絵で描き、n が実験回の数であることを図の中で示す。文字を矢印でつないだ列にはしない。図の案は、実装の前に画像で示す。
- 表は、行が実験回、列が群。同じ行の対照と処理が対になることを、行の中の線で示す。
- デモ：入力欄をやめて文字で表示する（C-4）。公開データで変更できないことは、表の隅の印で示す。独立性が未確認の理由（出典に記載がない）は、「独立性 未確認」の印を開くと読める。空の日付は出さない。
- 呼び名を「実験回」にそろえる（C-5）。
- 主要指標は、ここに段落を足さない（[§4.5](#45-主要指標)）。

### 4.4 画像の表（Issue の A）

**`main` の問題**：領域を核小体にしても、核小体の数・総面積・面積割合・最大の割合・離心率は、領域が核のときの表にしか出ない。

**案**

- 領域が核小体・核質のとき、「核ごと」の表の**先頭の列**を核小体のまとめ（数・総面積・面積割合・最大の割合・離心率）にする。核染色の列はその後ろに置く。最初の表示域で、`main` との違いが見える。
- 「核ごと」と「核小体ごと」を表の上で切り替える。切り替えの名前が、そのまま観測の単位を表す。
- 表の下の次の一手を、いま表に出ている値に合わせる（A-2）。
- 核小体 1 個ごとの形の列（A-4）は、[§5](#5-指標の追加と公開実画像での検証) の検証を通った指標だけを足す。

### 4.5 主要指標

結果を見る前に主要指標を宣言し、ほかを探索と示す（Issue の E、判断 6）。

- 宣言は、指標の選択欄の横の印（☆ → ★）で行う。宣言した日時はサーバーが記録する（#258 の計算側を使う）。
- 結果の見出しと保存した比較のボタンに、「主要」の小さな印を付ける。文は足さない。
- 「核小体ストレス」の指標の一覧（NS-01）は、[§5](#5-指標の追加と公開実画像での検証) の検証の後に、画面の案を別に示す。

### 4.6 アクセシビリティ

オーナーの指摘は、`main` を基準に、アクセシビリティが明らかに良くなること。

1. 実装の前に、`main` の 4 画面を WCAG 2.1 AA で調べ、基準の値を記録する（文字と背景のコントラスト、キーボードだけでの操作と順序、フォーカスの見え方、読み上げの名前、押せる範囲の大きさ、色だけに頼る表示）。

## 5. 指標の追加と公開実画像での検証

### 5.1 現状（数えた事実）

公開デモの採用済みの核小体マスクを、形の最小面積 96 px で数えた（2026-11-21）。

| 場面 | 核小体の数 | 面積の中央値 | 96 px 以上の割合 |
|---|---|---|---|
| オキサリプラチン | 179 | 91 px | 48.6% |
| シスプラチン | 372 | 111 px | 51.1% |
| ActD | 307 | 14 px | 17.6% |

- 96 px は、JUMP の核のマスクを間引いて決め、DS6a の核で確かめた値で、核小体では測っていない。
- 核小体ごとの形の値は、半分から 8 割が欠測になる。残るのは大きい核小体で、処理で核小体が小さくなる条件ほど多く欠ける。この偏りが比較に与える影響は測っていない。
- 核小体の場面は 3 つとも同じ研究（DS6a）の U2OS で、1 場面は 18 視野、核は 65〜81 個。デモは公開ファイルを小さくするため、各視野から 640 × 640 画素の窓を 1 つ切り出している。検証には、切り出す前の視野を使える。
- 面積の画素数は解像度で変わる。DS6a と DS1 は 0.1625 µm/px、DS6b は 0.325 µm/px で、同じ核小体の画素数は 4 倍違う。96 px は DS6a で約 2.5 µm²、DS6b で約 10 µm² に当たる。最小面積は、画素数だけでなく解像度と合わせて決める必要がある。
- CV と陽性面積率は、DS6a の核の領域と OpenCell の NCL 画像 1 枚で、独立の計算と一致した。これは式の照合で、核小体で使えることの検証ではない。

### 5.3 手順と、値を見る前に決めること

1. **検出の設定を固定する。** 製品の現行の設定（核は StarDist、核小体は定義マーカーの相対しきい値）をそのまま使い、この検証のために調整しない。
2. **調整用と評価用を、値を見る前に分ける。** 視野の単位で分ける。案：DS6b の 30 分と 2 時間を調整用、DS6b の 4 時間と DS1 を評価用にする。デモで使った DS6a の視野は、評価に入れない。
3. **測るもの**
   - 核小体の面積の分布（px、µm²）。条件・細胞株ごと。
   - 指標ごとの測定可能率（最小面積の候補ごと）。条件ごと。
   - 形の誤差：実際の核小体で、元の解像度の値と、間引いた同じ輪郭の値を比べる。核を間引いた前回の方法を、核小体そのものでやり直す。DS1（0.1625 µm/px）を 2 × 2 でまとめて 0.325 µm/px にし、同じ核小体を 2 つの解像度で測ると、DS6b の解像度での誤差が分かる。
   - 独立実装（scikit-image の `regionprops`）との一致。
   - 欠測の偏り：最小面積で除く前と後で、条件間の差がどれだけ変わるか。
4. **許容差**は前回と同じにする（90 パーセンタイルで |Δソリディティ| ≤ 0.05、|Δ長短軸比| ÷ 長短軸比 ≤ 0.10、|Δ離心率| ≤ 0.05）。
5. **結果は、失敗・欠測・未検証の範囲も含めて報告する。** 論文と同じ向きの差が出ることは、合格の条件にしない。

### 5.4 結果による分岐（判断 4）

値を見る前に決める規則の案。

- 核小体ごとの形の指標は、評価用の素材で、**すべての条件で測定可能率が 80% 以上**、かつ**条件間の測定可能率の差が 10 ポイント以内**のときだけ、核小体の指標として画面に出す。
- 満たさない指標は、核小体では出さない（核では出す）。核小体の形は、既存の核ごとのまとめ（面積で重みづけた離心率、数、総面積、最大の割合）で読む。
- 最小面積は指標ごとに決める。1 つの指標の欠測を、同じ核小体のほかの値に広げない。

## 6. PR の分け方と順序

各 PR は、最新の `main` から作る。画面の PR は、画面の案の合意（原則 4）の後に始める。

| 順 | PR | 内容 | 始める条件 |
