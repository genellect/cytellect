# LP の刷新：実装方針と実装

作成：2026-11-13。状態：実装済み、オーナーの判定待ち。2026-11-13 の議論で積み上げた決定と、オーナーが承認した実装方針、それに沿った実装をまとめる。LP の見た目と素材の正本は [LP の美術方針](../../lp-art-direction.md)で、この刷新で加わった判定はその §11 に記録した。

判定は、Vercel のプレビューでオーナーが行う。マージと本番への反映は、オーナーが指示した場合だけ行う。

## 1. 目的

cytellect.app の LP を、今のページを土台に、世界一流の水準のプロダクト LP へ刷新する。

| 番号 | オーナーが示した課題 |
|---|---|
| (1) | 新機能との乖離。解析結果の要約や考察まで含めた、研究者 UX に特化した機能を訴求できていない。測れるパラメータが限定的に見える |
| (2) | 掲載画像が古い。現行の UI のスクリーンショットではない |
| (その他) | デザインが世界一流の LP の水準に届いていない |

## 2. 積み上げた決定

**範囲**

1. 今のページを土台にする。ゼロから作らない。部分の差し替えで終わらせない。
2. プロダクトの LP である。会社の LP とは目的が違う。
3. 美術方針は議論の集積で、固定の要件ではない。制約を自分で置かない。

**内容**

4. 基準は、研究者が欲しいと思うかどうか。書き出しの形式や n の扱いのような細目は主張にしない。
5. 要約と考察まで含めた研究者 UX を訴求する。考察は価値が高いので、最も良い場所に置く。
6. 測る構造を限定しない。パラメータは並べる。「0% → 90%」「92%」と核ごとの表は、一例として載せる。
7. できる前提で言い切る。留保と注記は置かない。
8. 文は、短い主張 1 文と証拠。主語は研究者の価値。
9. プロダクトの中身は、現行デモの UI と解析結果から取る。顕微鏡画像を素材にしない。デモは作り直さない。UI はそのまま貼らず、見せ方を選ぶ（グラフを大きく見せない）。

**デザイン**

10. 色、タイポグラフィ、レイアウト、見せ方、3D、グラデーション、実写素材を組み合わせて、ページ全体で設計する。
11. 素材とは、デザインの技術と素材のこと。その選び方が最も重要。実写素材、WebGL、Three.js など、使えるものはすべて候補にする。
12. 参照サイトから倣うのは、デザインの水準と作り方。内容と文章は倣わない。同じ絵を作るのでもない。
13. HTML と CSS だけで絵を作らない。
14. 文字を大きくするのは理由があるときだけ。役割を説明できない画像は足さない。

参照 5 サイトは、いずれも絵を制作物（撮影・描画した映像）として作り、動きを演出として設計し、書体を選び抜いている（2026-11-13 に実物で確認）。HTML はそれを載せる器である。

## 3. 現行の課題

| 課題 | 現行 |
|---|---|
| (1) | 結果を読む機能がどこにもない。到達点が「図」で止まる。構造名でプロダクトを語り、見える指標が 2 列 |
| (2) | 現行 UI の画面が 1 枚もない |
| (その他) | 世界観が最初の画面で終わる。以降は無地に文字と箱。プロダクトが小さな貼り付けで、世界の外にある。どの節も同じ組み方。絵と動きが作られたものではない |

## 4. ページの構成

実験台の映像から、画像がプロダクトに入り、測定、結論、考察、論文の図へ進み、その先の患者へ届くまでを、一続きで見せる。

| 場面 | 内容 | デザイン |
|---|---|---|
| 最初の画面 | 見出しは現行のまま。「蛍光顕微鏡の画像をアップロードするだけで、測定・統計から、結論と考察、論文の図まで。」を添える。解析の結論を 1 枚浮かべ、画像から論文の図までの線を引く | 実写映像は現行のまま。見出しを英字のセリフ体に。浮いた丸いヘッダー、丸いボタン、ガラスの結論のカード |
| 使命 | 現行の 2 文だけ | 光と培地の色がゆっくり流れる地（WebGL のシェーダー、`LightField`）。文がスクロールで現れる |
| プロダクトの体験 | 「手作業で数週間かかっていた解析を、一つの画面で数分に。」から 4 つの章へ。タブはやめた | Three.js の 3D 空間に現行デモの画面をガラスの板として置き、スクロールでカメラが進む（`experience-scene.ts`）。文は左に留まる |
| 01 AIによる設定 | やりたいことを一文で。解析の設定は、AIが組み立てます。 | AI の画面へ寄り、指示の一文と応答が手前に浮く |
| 02 検出と測定 | 測りたい値が、細胞ひとつひとつに並びます。測れる値を 6 種並べ、一例として核小体の数値 | 核ごとの表が横へ流れる（カメラが 2 か所で止まる） |
| 03 要約と考察 | 結果を読み解く時間を、次の実験を考える時間に。 | 頂点。最も長く留まり、結論の一文と考察を正面から読ませる。統計の画面は奥に下がり、光が培地の色に暖まる |
| 04 統計と論文の図 | 統計の検定も、論文に載せる図も、クリックだけで。 | 図の設定を手前に、グラフの画面は奥 |
| 理由 | 「どんな研究の画像も、入れるだけで、自動で。」と 4 項目（現行） | ピペットの写真を全面に敷き、4 項目をガラスの面に |
| 患者 | 現行のまま | 全面の深緑。最初の画面の線を受けて、患者へ届く線 |
| 誘い | 現行の文 | 冒頭と同じ実写映像で閉じる（`LandingClosingFilm`） |
| ダウンロード、FAQ | 構造名（核小体や細胞）を外す。到達点を「結論と考察」に | 書体と部品を揃える |

動きを減らす設定、WebGL 2 のない環境、幅 1024 px 未満では、同じ 4 章を、デモの画面をガラスの板に重ねた静止の構成で見せる（`data-mode="plates"`）。3D のときも、板の画像は代替テキストとともにページに残す。

## 5. 手段ごとの実装

| 手段 | 実装 |
|---|---|
| 実写素材 | 採用済みのヒーロー映像を冒頭と結びに、ピペットの写真を理由の節の全面に。誘いのぼかした面（`lp-atmosphere.webp`）は外した |
| Three.js | `apps/web/src/components/experience-scene.ts`。9 枚の板（画面 3、要部 6）を角丸のガラスと柔らかい影で描き、6 つのショットの間をカメラが補間する。板の色は管理せずそのまま出す（UI が撮影どおりに読める）。画面外では描画を止める |
| シェーダー | `LightField.tsx`（使命の地）と、3D 空間の奥の光（要約と考察で暖まる） |
| 動き | スクロールに同期したカメラ、使命の文の出現、章の文の出現、結論のカードの浮上。動きを減らす設定ではすべて止める |
| タイポグラフィ | 主張の文に Noto Serif JP、英字の見出しと数値に Instrument Serif、章のラベルに IBM Plex Mono。いずれも OFL。LP の文字だけに絞って配布する（`scripts/build_lp_fonts.py`、`apps/web/public/fonts/lp/`）。本文は従来の Inter と Noto Sans JP |
| 色、部品 | 実験室の白と淡い灰、深緑、培地の桃色。ヘッダーは浮いた丸い帯で、明るい節と暗い節で切り替わる（`LandingHeaderTone`）。ボタンはすべて丸 |
| 撮影の仕組み | 製品の画面は `apps/web/scripts/capture-lp-evidence.mjs` で公開デモから撮る。デモが更新されたら撮り直す |

各章の「デモで開く」は、その場面のその画面へつなぐ。ワークスペース ID は `apps/web/public/showcase/snapshot/scenes.json` からビルド時に引く（`apps/web/src/lib/showcase/scene-links.ts`）。

```bash
cd apps/web && node scripts/capture-lp-evidence.mjs --base https://cytellect.app
python3 scripts/build_lp_fonts.py
```

LP の文言を変えたら、`build_lp_fonts.py` と、Noto Sans JP の部分書体（`scripts/build_marketing_media.py --fonts-only`）を作り直す。`tests/test_web_font_subset.py` が両方を確かめる。

## 6. 判定をお願いしたい点
