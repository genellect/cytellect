# LP の刷新：確定要件と実装

作成：2026-11-13。状態：実装済み、オーナーの判定待ち。2026-11-13 のオーナーの指摘と、その日の議論で確定した要件を記録し、それに沿って実装した内容をまとめる。LP の見た目と素材の正本は [LP の美術方針](../../lp-art-direction.md)で、この刷新で加わった判定はその §11 に記録した。

判定は、Vercel のプレビューでオーナーが行う。マージと本番への反映は、オーナーが指示した場合だけ行う。

## 1. 確定要件

### オーナーが示した課題

| 番号 | 課題 |
|---|---|
| (1) | 新機能との乖離。解析結果の要約や考察まで含めた、研究者 UX に特化した機能を訴求できていない。測れるパラメータが限定的に見える |
| (2) | 掲載画像が古い。現行の UI のスクリーンショットではない |
| (その他) | デザインが世界一流の LP の水準に届いていない |

### 要件

| 区分 | 要件 |
|---|---|
| 内容 | 製品の LP として、製品が何をどこまでできるかを、仕様まで説明する。会社の LP のように志だけを語らない |
| 内容 | 結果の要約と考察を訴求する。考察は価値が高いので、最も良い場所に置く |
| 内容 | 測れるものを特定の項目に固定しない。限定的に見せない |
| 内容 | 機能はできる前提で書く。評価を下げる表現、留保、注記を置かない |
| 文章 | 場面ごとに、短く言い切る主張 1 文と、その証拠。主語は研究者の利用価値（美術方針 §5・§11） |
| 素材 | 製品の画面は、現行デモの UI と解析結果から取る。顕微鏡画像を素材にしない |
| 素材 | 画面をそのまま貼らず、機能ごとに価値が伝わる見せ方を選ぶ。弱い部分を大きく見せない |
| 素材 | 役割を説明できない画像を足さない。公開デモは作り直さない |
| デザイン | LP は、色、タイポグラフィ、レイアウト、見せ方、3D、グラデーション、実写を組み合わせて、ページ全体で設計する。一部だけを差し替えない |
| デザイン | 素材は、証拠ではなく、デザインの技術と素材として選ぶ。組み立て方以上に、その選び方が重要 |
| デザイン | 参照サイト（美術方針 §4）から倣うのはデザインだけ。文章と内容は倣わない |
| デザイン | 変更には理由を付ける。文字は理由なく大きくしない |
| 進め方 | PR を作り、プレビューで判定を受ける |

## 2. 設計

参照 5 サイトを 1440×900 で開いて確かめ、美術方針 §4 が「取り入れること」としている点を、ページ全体に入れた。

| 要素 | 現行 | 刷新 | 理由 |
|---|---|---|---|
| 色 | 地は黄みのベージュ。差し色はミントと桃色 | 地は実験室の白と淡い灰。差し色は培地の桃色 1 色 | 美術方針 §6 の清潔感の基準（白、淡い灰、ガラス、アクセント 1 色）を、映像だけでなくページにも当てる |
| タイポグラフィ | 見出しはどれも最大 52 px、太さ 500 | 使命・患者・誘いの 3 文を最大 64 px、太さ 400 に。ほかの見出しは大きさを保ち、太さを 450 に | 参照サイトの声明は 56〜64 px、太さ 200〜400。「文字の少なさと大きさ」（Lila）。声明だけを大きくし、ほかは大きくしない |
| レイアウト | どの節も同じ幅の箱。写真と暗い面は角丸の枠の中 | 節の余白を広げる。写真と患者の面は左右いっぱいに。理由の節は左右に割る | 「余白の間合い」（Lila）。実写を挿絵にしない |
| 見せ方 | 縮小した全画面を、文の横に | 主張と説明を上、大きな 1 枚を下に。1 枚の中は、画面全体を奥、要の部分を手前の 2 層 | 何の画面かが分かり、読ませたい部分だけが読める。グラフは奥に下がる |
| 3D | なし | 製品の画面を奥行きのある配置に。使命の節に、ガラスと光の立体（`optical-poster.webp`） | 「明るいトーンのままの上質さ」（Isomorphic）。立体は象徴ではなく、雰囲気として使う |
| グラデーション | 暗い面の中だけ | 使命、製品の舞台、誘いの地に、光と培地の色の淡いグラデーション | 無地の地をやめ、ヒーローの映像の世界を下まで延ばす |
| 実写 | ヒーロー映像と、枠に入ったピペットの写真 | ヒーロー映像は維持。ピペットの写真を全面にして、上下を地へ溶かす。誘いの地に、培養プレートのコマをぼかした面 | 「実写でありながら抽象的な質感」（Altos）。新しい素材は足さず、採用済みの実写から作る |
| 動き | ヒーロー映像 | 使命の 2 文が、スクロールに合わせて現れる | 動きは 1 か所だけ。動きを減らす設定では出さない |

## 3. 実装

### 構成

| 節 | 変更 |
|---|---|
| ヒーロー | なし |
| 使命 | 画面いっぱいの高さ。右にガラスと光、左に 2 文。リードは「測定・統計から、結論と考察、論文の図まで」 |
| 実写の帯 | 左右いっぱい。上下を地へ溶かす |
| できること | 5 つのタブ（下の表）。主張と説明を上、舞台を下に |
| 理由（どんな研究の画像も） | 文は現行のまま。左に主張、右に 4 項目を 2 列で |
| 患者 | 深緑の面を左右いっぱいに。文は現行のまま |
| 誘い | 明るい面に。地は培地の色の質感。リードは結論と考察を含む文に |
| ダウンロードと FAQ | 無料版と研究室のクラウドの説明を、結論と考察を含む文に |

### 「できること」の 5 つのタブ

一度に 1 つだけ表示する形（2026-10-23 の「長すぎる」への対応）を保つ。最初に見えるのは「要約と考察」。

| タブ | 主張 | 舞台（公開デモの画面） |
|---|---|---|
| 要約と考察 | 結果を読み解く時間を、次の実験を考える時間に。 | 奥に統計の画面。手前に結論の一文と、考察 |
| 解析の流れ | 画像を入れるだけ。検出から論文の図まで、一つの画面で。（現行の文） | 統計の画面全体。流れは「結論と考察」を加えた 5 段 |
| 検出と測定 | 測りたい値が、細胞ひとつひとつに並びます。 | 核ごとの表（1 つの核の行に 13 列） |
| AIによる設定 | やりたいことを一文で。解析の設定は、AIが組み立てます。（現行の文） | 奥に AI のパネルを開いた画面。手前に指示の一文と応答 |
| 統計と論文の図 | 統計の検定も、論文に載せる図も、クリックだけで。（現行の文） | 奥にグラフの画面。手前に図の幅・レイアウト・寸法の設定 |

各タブの「デモで開く」は、その場面のその画面へつなぐ。ワークスペース ID は、`apps/web/public/showcase/snapshot/scenes.json` からビルド時に場面の ID で引く（`apps/web/src/lib/showcase/scene-links.ts`）。デモの側は変えていない。

## 4. 製品の画面を古くしない

製品の画面は、スクリプトが公開デモから撮る。デモが更新されたら、撮り直す。

```bash
cd apps/web && node scripts/capture-lp-evidence.mjs --base https://cytellect.app
```

- 場面と画面、撮る範囲はスクリプトに書いてある。画面の内容と値には手を加えない。
- 素材ごとに、場面の ID、画面、範囲、デモの生成コミット、SHA-256 を `lp-evidence.json` に残し、許可リストを更新する。

## 5. 判定をお願いしたい点

| 番号 | 判定 |
|---|---|
| 1 | ページ全体の設計（[§2](#2-設計)）。色、文字、余白、舞台、グラデーション |
| 2 | 使命の節のガラスと光の立体。2026-10-23 に LP から外した 3D の背景の静止画（`optical-poster.webp`）を、象徴ではなく雰囲気として使っている |
| 3 | 誘いの面を、深緑から明るい面に変えたこと。患者の面と続けて暗くならないようにした |
| 4 | 5 つのタブの主張の文と、舞台の見せ方 |
