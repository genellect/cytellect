# 画像の測定ビュー：要件定義書（案）

作成：2026-11-11。**2026-11-11 にオーナーが承認し、[§7](#7-オーナーの判断が必要な点) の 3 点を推奨のとおりに決めた。** 実装の手順は[実装案](implementation.md)にある。

## 1. 位置づけ

### 目的

[プロダクトの使命](../../development-principles.md#プロダクトの使命)の「画像解析に詳しくない Wet 研究者が、何を対象に何を測っているかを理解し、明確な導線のもとで迷わず修正と判断を行い、統計と編集可能な論文の図まで同じ作業の中で完了できる」を、画像の画面で満たす。

### 解決する問題

2026-11-11 にオーナーが指摘し、公開デモ（本番と同じ画面）をブラウザで操作して確かめた。画像の画面から、何ができるのかが分からない。核ごとの表、区画への分配、チャンネルによる陽性・陰性の分類（#189、#190）を加えても、画面の見た目はほとんど変わらなかった。

| 観察 | 原因 |
|---|---|
| 表が何を、どの染色で測った値か分からない | 2 画面の表に見出しがない。1 画面でも列名に染色が出ない |
| 解析の入口が見つからない | 画像の上の 1 行に、移動・見え方・解析・配置の 13 個の操作が同じ見た目で並ぶ。「区画への分配」は表示の切り替えと見分けがつかない |
| 陽性・陰性の分類が見つからない | 「設定 › 画像解析」の折りたたみの中にある。研究者は「設定」を開かない |
| 核ごとの表が見つからない | 領域が「核」のときだけ、表の見出しの切り替えとして現れる |
| 分類しても画像の上で見えない | 2 画面には判定の色を渡していない。再読み込みで分類の表示が消える |

### 解決の方向

**画像の見え方を、そのまま測定の入口にする。** 研究者は画像を見て考える（どの核が陽性か、信号が核小体に偏っているか）。画像の「色分け」を選ぶと、画像の塗り分けと、その下の表と、次に進む先がそろって変わる。機能の一覧や作業の手順を文章で並べることはしない。

[ワークスペースの再設計](../../workspace-redesign.md)の規則はそのまま保つ。

- 画像は、指標が測る構造を示す。
- 右の領域は、いま選んでいるものの操作だけを置く。
- 画像・領域の操作・設定・測定値を見た目で区別する。
- 次にできる操作を、長い説明なしに示す。

### 範囲

| 含む | 含まない |
|---|---|
| 画像の画面（1 画面・2 画面）の色分け、表、操作の配置、次の一手 | 検出、測定、統計、作図の計算の変更 |
| 本番とデモ（同じ部品） | 新しい指標、新しい API の契約 |
| 画像の画面から統計の画面へ移る操作 | 統計・グラフの画面の再設計 |

### 既存の要件との関係

- [要件](../../requirements.md)の M22（`channel-gate/1.0.0`）と M23（`region-partition-table/1.0.0`）の科学的な約束は変えない。色分けは、それらが保存した結果を描くだけである。
- [群間比較の要件定義書](../group-comparison/requirements.md)の V-01〜V-04（2 画面の表示と表）と N-06（保存した表の列）を保つ。この要件は V-04 の「各画面の測定値の表」に見出しと色分けを加える。
- [公開デモ](../../showcase.md)の「現行機能を本番と同じ UI でエラーなく再現する」を保つ。デモだけの画面は作らない。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 色分け | 画像の上の領域の塗り分け方。輪郭／陽性・陰性／核小体と核質のいずれか |
| 表示中の表 | 画像の横または下の表。いまの色分けと領域で、画像に見えている物の値を示す |
| 次の一手 | 表の見出しの右に置く 1 つの操作。いまの色分けで群を比べる統計へ進む |
| 判定の記録 | `channel-gate/1.0.0` が保存した核ごとの判定（陽性・陰性・未判定・除外・対照）と、方法・撮影日ごとのしきい値 |

## 3. 要件

### 色分け

**MV-01** 各画像の右上の操作に「色分け」を置く。選べるのは次の 3 つ。2 画面では、両方の画像に同じ色分けを使う。

| 色分け | 選べる条件 | 画像 |
|---|---|---|
| 輪郭（既定） | いつでも | 今と同じ輪郭 |
| 陽性・陰性 | 採用した核の結果があり、判定できる染色がある | 核を判定で塗り分ける（MV-03） |
| 核小体と核質 | その視野に、採用した核小体と核質の結果がある | 核ごとに核小体と核質を塗り分ける（MV-05） |

選べない色分けは、選択肢に残したうえで選べない状態にし、足りないものを示す（例：「核小体の結果が必要」）。

**MV-02** 色分けの状態は、ワークスペースの表示の状態として保つ。視野の切り替え、1 画面と 2 画面の切り替え、タブの移動で失わない。

### 陽性・陰性

**MV-03** 陽性・陰性では、判定の記録にある 5 つの状態を、それぞれ見分けられる色と線で描く。陽性、陰性、未判定、除外、対照の 5 つで、未判定・除外・対照を陰性と同じ見た目にしない。凡例に状態ごとの核の数を、画像ごとに示す。選択中の核も、判定の色を保ったまま選択が分かるようにする。

**MV-04** 判定の操作は右の領域（画像解析）に置く。

- 陽性・陰性を選んだとき、判定の記録がなければ、右の領域を開いて「チャンネルによる核の分類」を先頭に出す。記録があれば、そのまま塗る。
- 右の領域には、撮影日ごとの判定値の分布としきい値を、小さな図で示す。核を選ぶと、その核の値としきい値を示す。研究者がしきい値の妥当性を判断できるようにするためである。
- 本番では、陰性対照による判定を先頭の選択肢にする。手動と Otsu は「探索的」と明記する。公開デモは、記録した撮影日ごとの Otsu だけを示す（[公開デモ](../../showcase.md)の既存の規則）。
- 「設定 › 画像解析」の検出の項目の下にある、今の分類の折りたたみはなくす。分類の操作は、陽性・陰性の色分けから開く 1 か所だけにする。

### 核小体と核質

**MV-05** 核小体と核質では、各核の中の核小体と核質を、別の色で塗る。表示中の表は、選んだ染色の区画への分配表（M23）になる。

- 対象と参照は、MV-07 の既定で読み込み、表の見出しで替えられる。API への要求は、これまでどおり対象・参照・測定チャンネルを明示する。
- 「分配表を表示」を押す手順と、上部の「区画への分配」ボタンはなくす。分配は、この色分けの中で行う。
- 2 画面のまま、各画像の視野について読み込む。1 画面に切り替えない。

### 表示中の表

**MV-06** 表の見出しは、常に「何ごと · どの染色」と、値の種類を示す。

| 例 | 場面 |
|---|---|
| 「核小体ごと · 5-EU（原値・背景補正）」 | 輪郭、領域が核小体 |
| 「核ごと · 5-EU で判定（撮影日ごとの Otsu・探索的）」 | 陽性・陰性 |
| 「核ごと · 核質 ÷ 核小体 · 5-EU」 | 核小体と核質 |

1 画面と 2 画面の両方の表に見出しを出す。2 画面の表には今は見出しがない。

**MV-07** 表の中身は色分けで決まる。

- **輪郭**：領域が核なら核ごとの表（全染色と核小体の要約）。核小体・核質なら、選んだ染色の領域ごとの測定値。
- **陽性・陰性**：核ごとの表に、判定・判定値・しきい値の列を加える。
- **核小体と核質**：分配表。分配の向きは [§7](#7-オーナーの判断が必要な点) の判断 1 に従う。

表の行と画像の領域は、今と同じく互いに選べる（V-04）。

### 操作の配置

**MV-08** 画像の上の操作を 2 種類に分ける。

- 左「何を見るか」：領域・染色・色分け。文字の選択欄で置く。
- 右「並べ方」：1・2 画面、拡大を連動、共通の表示範囲、実験回。アイコンにし、名前を添える。

「染色対応」は、使う頻度が低いので「⋯（画像の設定）」へ移す。解析の入口を、表示の切り替えと同じ見た目で並べない。390 px 幅でも、操作が画面の外にはみ出さない。

### 次の一手

**MV-09** 表の見出しの右に、いまの色分けで群を比べる操作を 1 つだけ置く。2 群の実験の形がない場合は置かない。

| 色分け | 操作 | 統計の画面で開くもの |
|---|---|---|
| 輪郭 | 「〈指標〉を群で比べる」 | 同じ領域・染色・指標 |
| 陽性・陰性 | 「陽性率を群で比べる」 | 陽性率。同じ判定の規則を、比べる視野に当てる |
| 核小体と核質 | 「〈分配の指標〉を群で比べる」 | 判断 1 で決めた向きの分配の指標 |

陽性・陰性では、比べる視野への判定のやり直しを、この操作の中で行う。押す前に、操作の名前と短い説明でそのことを示す。M22 の「入力が変わったら明示的に判定し直す」を、この操作で満たす。

### 状態の保持

**MV-10** 判定の記録は、ワークスペースを開き直しても画像の色分けに戻る（GFP の判定と同じ）。保存した記録と入力（視野の版、メタデータ、チャンネル）が合わない場合は塗らず、判定し直しが必要なことを示す。

## 4. 科学的な約束

| 約束 | 要件 |
|---|---|
| 塗り分けと表は、API が保存した判定の記録・分配表・測定値だけから描く。ブラウザで判定・比・しきい値を計算しない | MV-03、MV-05、MV-07 |
| 対照で決めていないしきい値（手動・Otsu）による分類は、画像・表・統計のどこでも「探索的」と示す。陽性率の比較は記述にとどめる（M22） | MV-04、MV-06、MV-09 |
| 未判定・除外・対照を陰性として描かない。陽性率の分母に入れない | MV-03 |
| 分配では、対象と参照を常に名前で示す。核質は、親核から核小体の和集合を除いた領域とする（[研究パラメータの拡張計画](../research-measurements/plan.md) §4.1） | MV-05、MV-06 |
| 選択に使った染色を、選んだ核で測る場合の循環を警告する（M22） | MV-07、MV-09 |
| 「値の強さ」で領域を塗る表示は、この版では加えない（判断 2） | — |

## 6. 根拠

- 2026-11-11 のブラウザでの操作と、画面ごとの操作の数え上げ。画像の画面の最初の表示で、押せる要素は 129 個、文字は約 2,000 字あった。
- 同日のデザインレビュー。重大 3 件は、表が何を測っているか不明、操作の見た目が同じ、分類が設定の奥にあること。
- オーナーの指摘（同日）：何ができるのかが画面から分からない。新機能の目印や、作業の流れを文章で並べることは求めない。

## 7. オーナーの判断が必要な点

2026-11-11、オーナーは 3 点とも推奨のとおりに決めた。

| # | 判断すること | 推奨（決定） | 理由 |
|---|---|---|---|
| 1 | 分配の向きを、画像の表と統計の指標でどちらに揃えるか | 両方を「核質 ÷ 核小体」にする | 統計の既存の指標 `log2_nucleoplasm_over_nucleolus` と保存済みの結果を変えずに済む。今の分配表の既定（核小体 ÷ 核質）と逆向きのまま並べると、同じ問いで符号が逆になる |
| 2 | 「値の強さ」の色分けを加えるか | 加えない | 原値の明るさの色は、飽和や背景の影響を見誤りやすく、目でしきい値を決めることにつながる。生物学的な妥当性を優先する |
| 3 | 領域が「核」のとき、核ごとの表を既定の表にするか | する | 全染色と核小体の要約が 1 行にまとまる。今の「このチャンネル」の表は、領域が核小体・核質のときと、候補を採用する前の確認に残す |
