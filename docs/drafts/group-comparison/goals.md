# 群間比較の UX 改善：目標定義書（案）

作成：2026-10-25。**オーナー承認前の案です。** 実装案（画面の設計や API の変更）はまだ扱いません。上位の目標・範囲・完了条件を決め、残る判断を [§7](#7-判断が必要な事項) にまとめています。要件の詳細は [要件定義書](requirements.md) にあります。

## 1. 依頼の分解

依頼者の言葉を、目的・解釈・確認が必要な点に分けました。

| 依頼者の言葉 | 解釈 | 確認が必要な点 |
|---|---|---|
| デモと本番画面の UX/UI 改善 | 公開デモ（`/demo`）とローカル版のワークスペースを、同じ画面のまま改善する。デモ専用の画面は作らない（[公開デモ](../../showcase.md)は本番と同じ画面を使う） | ― |
| 実際に行いたい解析（WT 群や薬剤処理群との同時比較、群間比較）ができない | 計算そのものは実装済みである（[解析機能の概要](../../implementation-overview.ja.md)）。足りないのは、実験の構造（群・実験回）を研究者の考える順序で入力し、群を並べて見比べ、比較を一続きで終える導線 | ― |
| 必要な解析機能に過不足がある、統計・グラフに過不足がある | 生命科学で一般に見る指標（細胞数、陽性細胞の割合、細胞質の面積など）が欠けている。一方、研究者が判断に使わない内部の値が画面に多く出ている | どの指標を最初に揃えるか（[要件定義書 §3](requirements.md#3-指標の一覧)） |
| 使い方が直感的に理解できない／統計解析画面が何を示しているのかわからない | 結果が「何を、どの単位の n で比べ、どちらにどれだけ変わったか」という文で示されず、表と p 値が並ぶだけになっている | ― |
| 最初に 1 画面制または 2 画面制を選べる | 1 画面：1 つの群の記述（分布）。2 画面：2 つの群を並べて比較する。選んだ形が、画面の分割と統計の設計の両方を決める | 解釈が正しいか。3 群以上を最初から扱うか（Q1、Q2） |
| 群 1 で実験日を選択（固定）し、実験条件ごとに n 数を比較、統計検定できる | 実験日を独立した実験の繰り返し（n の単位）とし、同じ日に行った群どうしを対にして比べる | 実験日 = 独立反復、同日の群 = 対、という理解でよいか（Q3） |
| 1 つの群に複数の染色条件の視野（DAPI 5 視野、GFP 5 視野、NCL 5 視野、CellMask 5 視野など）。サーバー側は微調整でよい | 群の中に「染色セット」（同じ組み合わせで染めた視野の集まり）を複数持てる | 染色セットは別の視野（別のカバーガラス）か、同じ視野の別チャンネルか。各セットに核染色が入るか（Q4） |
| 測りたい指標を迷わず選べ、妥当な群間比較のグラフが出る | 「何を知りたいか」から指標を選び、指標ごとに妥当な集計・検定・図が決まる | ― |
| 細胞が正確に確認でき、一般に見たい比較条件が揃った公開データを探す | 論文化され、再配布できる公開画像で、対照と処理が同じ実験の中にあるものを、デモと検証の共通データにする | ― |
| デモで、薬剤処理群で核が明確に縮小していることなどが初心者にも直感的にわかる | 表現型は出典の論文が報告しているものを使う。デモはその変化を、画像の並置と、測定から作った一文と図で示す | 優先する表現型（核の縮小・細胞数・核小体）（Q7） |

## 3. 上位目標

**G0：画像解析に詳しくない Wet 研究者が、自分の実験（対照と処理、複数回の独立した実験）を、その構造のまま入力し、知りたい変化に合う指標を迷わず選び、何を・どの n で比べ・どちらにどれだけ変わったかを理解したうえで、論文に使える群間比較の図と統計を得られる。**

これは[プロダクトの使命](../../development-principles.md#プロダクトの使命)の「何を対象に何を測っているかを理解し、明確な導線のもとで迷わず修正と判断を行い、統計と編集可能な論文の図まで同じ作業の中で完了できる」を、群間比較について具体化したものです。

## 4. 下位目標

| ID | 目標 | 達成した状態 |
|---|---|---|
| G1 | 実験の構造を最初に伝えられる | 群（例：WT、薬剤処理）、実験回（実験日）、染色セットを、研究者が普段の言葉で、画像を追加する流れの中で入力できる。視野ごとの表に後から書き込む必要がない |
| G2 | 群を並べて見比べられる | 2 つの群の画像を同じ表示条件で並べ、同じ場所・同じチャンネルを同時に見られる。検出した輪郭と測定値も並べて確認・修正できる |
| G3 | 知りたい変化から指標を選べる | 「細胞が減ったか」「陽性細胞が増えたか」「核・細胞質・核小体が小さくなったか」などの問いから選ぶと、必要な染色、領域、集計、検定、図が決まる。必要な染色がなければ、その理由が分かる |
| G4 | 結果が何を示すか分かる | 結果の先頭に「〈指標〉は〈対照〉に比べ〈処理〉で〈差〉（〈%〉、95% 信頼区間）、独立した実験 n =〈回数〉、〈検定〉p =〈値〉」という文が出る。図の点が細胞・視野・実験回のどれかが分かる |
| G5 | 論文に使える図になる | 実験回を n とする妥当な形（SuperPlot など）を既定とし、論文でよく使う形も、妥当な範囲で選べる。編集可能な SVG・PDF と元データ・Methods が一緒に出る |
| G6 | デモで初見の人に価値が伝わる | `/demo` を開くと、対照と処理の 2 群が並び、出典の論文が報告する変化が、画像と一文と図で分かる。図の点から元の細胞へ戻れる |
| G7 | 公開データでデモと検証をつなぐ | デモに使う公開画像一式を、結合テストと検証のデータとしても登録し、出典・染色・ライセンス・ハッシュと、視野の選び方を測定の前に記録する |

## 5. 範囲

**含む**：群・実験回・染色セットの入力、群の並置表示、指標の一覧と選び方、結果の文と図、公開デモのデータと構成、それに必要なサーバー側の調整（指標の追加、入力の上限の見直し）。

**含まない**：検出モデルの新規学習、3 次元・タイムラプス、斑点（foci）の検出、混合効果モデル、ホスト型での研究画像の受け付け、LP の変更。必要になった場合は別の変更として提案します。

**変えない約束**：原画像の画素値を変えない。測定値と統計は API と解析パッケージの共通実装だけが作る。n は独立した実験の繰り返しで、細胞数や視野数で n を増やさない。有意差を得るための視野・しきい値・手法の選び直しをしない。

## 6. 完了条件

確認の方法を、自動検証（CI・ブラウザ試験）、目視（コーディネーターの画面確認）、研究者による評価、出典との照合に分けます。自動検証と目視は、研究者が使えることの証拠にはしません。

| ID | 完了条件 | 確認の方法 |
|---|---|---|
| C1 | 2 群 × 実験回 3 × 染色セット複数 × 各 5 視野の実験を、視野ごとの表に戻らずに入力し、統計まで進める | 自動検証：公開データでブラウザ試験 |
| C2 | 2 つの群の画像が、同じ表示範囲・同じ拡大位置で並び、表示範囲が統一されていることが画面に示される | 自動検証、目視 |
| C3 | [要件定義書 §3](requirements.md#3-指標の一覧) の第一段階の指標が、問いから選べ、必要な染色がない場合は選べない理由が出る | 自動検証 |
| C4 | 結果の先頭の文の数値が、保存した統計の値と一致する。文は保存した結果から作り、手書きの数値を使わない | 自動検証（数値の照合） |
| C5 | 群間比較の既定の図が実験回を n として描かれ、細胞・視野・実験回の区別が凡例と元データ CSV に残る | 自動検証、目視 |
| C6 | `/demo` を開くと、追加の操作なしに 2 群の並置、結果の文、図が出る。エラー表示がない | 自動検証（既存の受入テストの拡張） |
| C7 | デモの表現型の向きと大きさが、出典の論文の報告と矛盾しない。矛盾する場合は、その事実を記録し、表現型を作り替えない | 出典との照合（記録を残す） |
| C8 | デモと検証のデータの出典・ライセンス・染色・ハッシュ・視野の選び方が、測定の前の日付で記録されている | 自動検証（fixture の照合）、記録 |
| C9 | 初めて使う研究者が、デモの結果について「何を比べたか」「n は何か」「どちらに変わったか」を説明できる | 研究者による評価（[評価課題](../../usability-tasks.ja.md) に課題を追加。3 名以上が望ましい） |
| C10 | 研究者が自分の実験の形で、2 群の比較を図の書き出しまで支援なしで終えられる | 研究者による評価 |

C1–C8 はエージェントの作業で満たせます。C9・C10 は人の評価が必要で、満たすまで [roadmap](../../roadmap.md) の未完了の受入条件に残します。

## 7. 判断が必要な事項

オーナーの判断が必要な点です。回答を得てから要件を確定し、実装案に進みます。

| ID | 質問 | 提案 |
|---|---|---|
| Q1 | 「1 画面制／2 画面制」は、(a) 1 群の記述と 2 群の比較という解析の形、(b) 画面の分割、のどちらを指すか | 両方。選んだ形が統計の設計と画面の分割の両方を決める |
| Q2 | 3 群以上（例：WT、変異、変異 ＋ 薬剤）を最初から扱うか | 最初は 2 群を完成させ、3 群以上は同じ設計で後から追加できるようにする。3 群以上の対応のある比較は統計が未実装 |
| Q3 | 「実験日を固定」は、実験日を独立した反復（n の単位）とし、同じ日の群どうしを対にする意味か | そのように扱う。同じ日に 2 回の独立実験を行う場合のために、実験回は日付と別に名前を付けられるようにする |
| Q4 | 「DAPI 5 視野、GFP 5 視野、NCL 5 視野、CellMask 5 視野」は別々の視野か、同じ視野の別チャンネルか。別々の場合、各視野に核染色が入るか | 別々の視野（染色セット）として扱い、各セットに核染色が入ることを前提にする。核染色がないセットでは細胞単位の指標を出さない |
| Q5 | 画像の追加の前に設定を出さないという決定（U01）を改め、最初に 1 画面／2 画面を選ばせるか | 画像の追加は最初の操作のまま残し、追加の画面の中で「1 群／2 群」と群の名前を選ぶ。どちらでも始められる |
| Q6 | 入力の上限（100 視野、3 チャンネル）を引き上げるか | 2 群 × 3 回 × 4 セット × 5 視野 = 120 視野で上限を超える。ローカル版の上限を見直す。4 チャンネル以上は、メモリの測定の後に判断する |
| Q7 | デモで最初に見せる変化はどれか：核の縮小、細胞数の減少、核小体の変化 | 現在のデータ（ActD）で根拠があるのは核小体の変化。核の大きさや細胞数は、Cell Painting Gallery（CC0）の陽性対照を確認してから決める（[要件定義書 §6](requirements.md#6-公開データ)） |
| Q8 | デモの視野数と容量の上限 | 現在は 6 視野・約 40 MB。2 群 × 3 回 × 各 3 視野以上を目標に、切り出しの大きさで調整する |
| Q9 | 平均 ± SD の棒グラフなど、論文でよく使う形を選べるようにするか | 実験回の平均の棒と各回の点、SD を示す形は選べるようにする。細胞を n とする棒グラフは作らない |

## 8. 進め方

1. **定義の承認**：この文書と要件定義書を、Q1–Q9 の回答で確定する。
2. **公開データの選定と登録**：[要件定義書 §6](requirements.md#6-公開データ) の基準で候補を確認し、視野の選び方を測定の前に記録して fixture にする。
3. **実装案**：画面の設計（群の入力、並置、結果の文）と、API・解析パッケージの変更点を決める。
4. **実装**：画面、指標、デモの順に、目的ごとに PR を分ける。
5. **検証**：C1–C8 を自動検証・目視・出典との照合で確認し、C9・C10 を研究者の評価で確認する。
