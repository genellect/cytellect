# 群間比較の UX 改善：目標定義書（案）

作成：2026-10-25。改訂：2026-10-25（オーナーの回答を反映）。**独立レビュー前の案です。実装はまだ行いません。** この文書は上位の目標・範囲・完了条件を定めます。画面の設計や API の変更（実装案）は扱いません。要件の詳細は [要件定義書](requirements.md) にあります。

## 1. 決定事項

オーナーが 2026-10-25 に回答した内容です。

| ID | 質問 | 回答 | この文書での扱い |
|---|---|---|---|
| Q1 | 「1 画面制／2 画面制」は、解析の形と画面の分割の両方を指すか | はい | 1 画面 = 1 群の記述、2 画面 = 2 群の比較。選んだ形が、画面の分割と統計の設計の両方を決める |
| Q3 | 「実験日を固定」は、実験日を n の単位にし、同じ日の群どうしを対にして比べる意味か | はい | 実験日を独立した実験の繰り返しとし、同じ日の 2 群を対にする |
| Q4 | 「DAPI 5 視野、GFP 5 視野…」は別々の視野か、同じ視野の別チャンネルか | 同じ視野・同じカバーガラスを意図する | 1 つの視野を複数の染色（DAPI、GFP、NCL、CellMask など）のチャンネルで撮影した画像として扱う。例は「1 群 5 視野、各視野 4 チャンネル」 |
| Q5 | 画像の追加の前に設定を出さないという要件 U01 を見直すか | 合意 | 最初に 1 画面／2 画面を選び、画面（群）ごとに画像を追加する |
| Q6 | 入力の上限（100 視野、3 チャンネル）を引き上げるか | 合意 | 1 視野 4 チャンネル以上を受け付ける。具体的な値は、メモリと時間を測ってから決める |
| Q7 | デモで最初に見せる変化はどれか | 核の縮小。ただし、細胞数・核小体の変化もデモで一通り再現できるようにする | 既定の表示は核の縮小。細胞数の変化と核小体の変化も、デモの中で切り替えて確かめられるようにする |

未回答の Q2、Q8、Q9 は [§8](#8-判断が必要な事項) に残しています。

## 2. 依頼の分解

| 依頼者の言葉 | 解釈 |
|---|---|
| デモと本番画面の UX/UI 改善 | 公開デモ（`/demo`）とローカル版のワークスペースを、同じ画面のまま改善する。デモ専用の画面は作らない（[公開デモ](../../showcase.md)は本番と同じ画面を使う） |
| 実際に行いたい解析（WT 群や薬剤処理群との同時比較、群間比較）ができない | 検定の計算は実装済み（[解析機能の概要](../../implementation-overview.ja.md)）。足りないのは、群と実験日を研究者の考える順序で入力し、群を並べて見比べ、比較を一続きで終える導線 |
| 必要な解析機能、統計・グラフに過不足がある | 生命科学で一般に見る指標（細胞数、陽性細胞の割合、細胞質の面積など）が欠けている。研究者の判断に使わない内部の値が、画面に多く出ている |
| 使い方が直感的に理解できない／統計解析画面が何を示しているのかわからない | 結果が「何を、どの n で比べ、どちらにどれだけ変わったか」という文で示されず、図・表・p 値が並ぶだけになっている |
| 最初に 1 画面制または 2 画面制を選ぶ | 1 画面：1 つの群の記述。2 画面：2 つの群を並べて比較する（Q1） |
| 群 1・群 2 で実験日を選択（固定）し、n 数を比較、統計検定する | 実験日ごとに、同じ日の 2 群を対にして比べる。n は実験日の数（Q3） |
| 1 つの群に複数の染色条件の視野を同時にアップロードできる。サーバー側は微調整 | 1 つの視野を複数の染色で撮影した画像を、群ごとにまとめて追加する。現在の視野とチャンネルの仕組みを使い、チャンネル数の上限を引き上げる（Q4、Q6） |
| 測りたい指標を迷わず選べ、妥当な群間比較のグラフを出力できる | 「何を知りたいか」から指標を選び、指標ごとに妥当な集計・検定・図が決まる |
| 公開データを探し、テスト・検証用データにする | 論文化され再配布できる公開画像で、対照と処理が同じ実験の中にあるものを、デモと検証の共通データにする |
| デモで、薬剤処理群で核が明確に縮小していることが、初心者にも直感的にわかる | 出典の論文が報告している核の縮小を、2 群の画像の並置、測定から作った一文、図で示す。細胞数と核小体の変化も、同じ形で確かめられる（Q7） |

## 4. 上位目標

**G0：画像解析に詳しくない Wet 研究者が、自分の実験（対照と処理、複数の実験日）をその構造のまま入力し、知りたい変化に合う指標を迷わず選び、何を・どの n で比べ・どちらにどれだけ変わったかを理解したうえで、論文に使える群間比較の図と統計を得られる。**

これは[プロダクトの使命](../../development-principles.md#プロダクトの使命)の「何を対象に何を測っているかを理解し、明確な導線のもとで迷わず修正と判断を行い、統計と編集可能な論文の図まで同じ作業の中で完了できる」を、群間比較について具体化したものです。

## 5. 下位目標

| ID | 目標 | 達成した状態 |
|---|---|---|
| G1 | 実験の形を最初に選べる | 最初に「1 画面（1 群の記述）」か「2 画面（2 群の比較）」を選ぶ。画面ごとに群の名前を付け、実験日ごとに、複数の染色で撮影した視野をまとめて追加できる。視野ごとの表に後から書き込む必要がない |
| G2 | 群を並べて見比べられる | 実験日を 1 つ選ぶと、2 つの画面にその日の 2 群の視野が、同じチャンネル・同じ表示範囲・同じ拡大位置で並ぶ。検出した輪郭と測定値も並べて確認・修正できる |
| G3 | 知りたい変化から指標を選べる | 「細胞が減ったか」「陽性細胞が増えたか」「核・細胞質・核小体が小さくなったか」などの問いから選ぶと、必要な染色・領域・集計・検定・図が決まる。必要な染色がなければ、その理由が分かる |
| G4 | 結果が何を示すか分かる | 結果の先頭に「〈指標〉は〈対照〉に比べ〈処理〉で〈差〉（〈%〉、95% 信頼区間）。実験日 n =〈数〉、〈検定〉p =〈値〉」という文が出る。各実験日の変化の向きと、図の点が細胞・視野・実験日のどれかが分かる |
| G5 | 論文に使える図になる | 実験日を n とする妥当な形（SuperPlot など）を既定とし、論文でよく使う形も、妥当な範囲で選べる。編集可能な SVG・PDF、元データ、Methods が一緒に出る |
| G6 | デモで初見の人に価値が伝わる | `/demo` を開くと、対照と処理の 2 画面が並び、核の縮小が画像・一文・図で分かる。細胞数の変化と核小体の変化にも切り替えられる。どの変化も出典の論文が報告しており、図の点から元の細胞へ戻れる |
| G7 | 公開データでデモと検証をつなぐ | デモに使う公開画像一式を、結合テストと検証のデータとしても登録する。出典・染色・ライセンス・ハッシュと、視野の選び方を、測定の前に記録する |

## 6. 範囲

**含む**：最初の 1 画面／2 画面の選択、群・実験日・視野の入力、群の並置表示、指標の一覧と選び方、結果の文と図、公開デモのデータと構成、それに必要なサーバー側の調整（指標の追加、入力の上限の引き上げ）。

**含まない**：検出モデルの新規学習、3 次元・タイムラプス、斑点（foci）の検出、混合効果モデル、ホスト型での研究画像の受け付け、LP の変更。必要になった場合は、別の変更として提案します。

**変えない約束**：原画像の画素値を変えない。測定値と統計は、API と解析パッケージの共通実装だけが作る。n は独立した実験の繰り返しで、細胞数や視野数で n を増やさない。有意差を得るための視野・しきい値・手法の選び直しや、結果に応じた対象の除外をしない。

## 7. 完了条件

確認の方法を、自動検証（CI・ブラウザ試験）、目視（コーディネーターの画面確認）、出典との照合、研究者による評価に分けます。自動検証と目視は、研究者が使えることの証拠にはしません。

| ID | 完了条件 | 確認の方法 |
|---|---|---|
| C1 | 最初に 2 画面を選び、2 群 × 実験日 3 × 各 5 視野（各視野 4 チャンネル）を、視野ごとの表に戻らずに入力し、統計まで進める | 自動検証：公開データでブラウザ試験 |
| C2 | 実験日を選ぶと、2 つの画面に同じ日の 2 群が、同じ表示範囲・同じ拡大位置で並び、表示範囲を統一していることが画面に示される | 自動検証、目視 |
| C3 | [要件定義書 §3](requirements.md#3-指標の一覧) の第一段階の指標を問いから選べ、必要な染色がない場合は選べない理由が出る | 自動検証 |
| C4 | 結果の先頭の文の数値が、保存した統計の値と一致する。文は保存した結果から作り、手書きの数値を使わない | 自動検証（数値の照合） |
| C5 | 群間比較の既定の図が実験日を n として描かれ、細胞・視野・実験日の区別が、凡例と元データ CSV に残る | 自動検証、目視 |
| C6 | `/demo` を開くと、追加の操作なしに、核の縮小を示す 2 画面の並置・結果の文・図が出る。細胞数の変化と核小体の変化にも切り替えられ、どの場面でもエラー表示がない | 自動検証（既存の受入テストの拡張） |
| C7 | デモの 3 つの変化の向きと大きさが、それぞれ出典の論文の報告と矛盾しない。矛盾する場合は、その事実を記録し、表現型を作り替えない | 出典との照合（記録を残す） |
| C8 | デモと検証のデータの出典・ライセンス・染色・ハッシュ・視野の選び方・除外の規則が、測定より前の日付で記録されている | 自動検証（fixture の照合）、記録 |
| C9 | 初めて使う研究者が、デモの結果について「何を比べたか」「n は何か」「どちらに変わったか」を説明できる | 研究者による評価（[評価課題](../../usability-tasks.ja.md)に課題を追加。3 名以上が望ましい） |
| C10 | 研究者が自分の実験の形で、2 群の比較を図の書き出しまで、支援なしで終えられる | 研究者による評価 |

C1–C8 は、エージェントの作業で満たせます。C9・C10 は人の評価が必要で、満たすまで [roadmap](../../roadmap.md) の未完了の受入条件に残します。

## 8. 判断が必要な事項

| ID | 質問 | 提案 |
|---|---|---|
| Q2 | 3 群以上（例：WT、変異、変異 ＋ 薬剤）を最初から扱うか | 最初は 1 画面と 2 画面を完成させ、3 群以上は同じ設計で後から追加できるようにする。3 群以上の対応のある比較は、統計が未実装 |
| Q8 | デモの視野数と容量の上限 | 現在は 6 視野、seed 約 40 MB。3 つの場面のそれぞれで、2 群 × 実験日 3 × 各 3 視野以上を目標にし、切り出しの大きさで容量を調整する |
| Q9 | 平均 ± SD の棒グラフなど、論文でよく使う形を選べるようにするか | 実験日の平均の棒と各日の点（SD または 95% 信頼区間）は選べるようにする。細胞を n とする棒グラフは作らない |
| Q10 | 核の縮小を示す公開データが、出典・ライセンス・反復の条件を満たさない場合、どうするか | 条件を満たすデータが見つかるまで、核の縮小の場面を公開しない。報告のない変化を、別の変化の代わりに見せない |

## 9. 進め方

1. **定義の承認**：この文書と要件定義書を確定する（2026-10-25 に Q1、Q3–Q7 を回答済み）。
2. **独立レビュー**：Codex が、作成者と別の立場で、§10 の観点から両文書をレビューする。指摘を反映するまで、実装に進まない。
3. **公開データの選定と登録**：[要件定義書 §6](requirements.md#6-公開データ) の基準で候補を確かめ、視野の選び方と除外の規則を測定の前に記録して、fixture にする。
4. **実装案**：画面の設計（最初の選択、群の入力、並置、結果の文）と、API・解析パッケージの変更点を決める。
5. **実装**：画面、指標、入力の上限、デモの順に、目的ごとに PR を分ける。Claude Code を主担当、Codex を補助とし、分担・衝突の防ぎ方・相互レビューは[開発体制（案）](development.md)に従う。
6. **検証**：C1–C8 を自動検証・目視・出典との照合で確認し、C9・C10 を研究者の評価で確認する。

## 10. 独立レビューの観点

レビューでは、特に次の点を確かめてください。

- 依頼の解釈（§1、§2）に、依頼者の意図からのずれや抜けがないか。
- 完了条件（§7）が、確かめられる形で書かれ、目標（§5）を漏れなく覆っているか。
- 要件が、既存の科学的な約束（[要件](../../requirements.md)、[開発の原則](../../development-principles.md)）と矛盾しないか。特に、実験日を対にする比較、陽性の判定、核の縮小を測るときの除外の扱い。
- 生物学的な妥当性：選ぶ指標と表現型が、細胞生物学の一般的な解釈と合っているか。
- 公開データの基準（[要件定義書 §6](requirements.md#6-公開データ)）が、ライセンス・反復の独立性・結果を見た選び直しの防止に十分か。
- 現状の記述（§3）が、コードとデモの実際と一致しているか。
- [開発体制（案）](development.md)の分担・衝突の防ぎ方・相互レビューが、並行実装で機能するか。
