# 未確定の核小体を含む視野の統計：設計判断メモ

作成：2026-10-26（JST）。調査した主担当ブランチは `claude/tender-ritchie-0a078r`、基準コミットは **`e5514b69ec874892d5b6ea989c43e3250d37f805`**。取得時点の main は `11eb24419f2d8af5a3eec706e23985a038cc7f1d` で、基準の祖先である。

これはオーナー判断のための提案であり、承認済み仕様を変更しない。変更対象はこの文書だけ。検出・マスク・測定・統計・公開デモは変更せず、画像による検出性能の評価も行っていない。

## 結論

**(a) 未確定核を欠測として保持する方式を基本とし、対象と欠測の内訳を研究者が確認してから計算する方式を推奨する。(b) 理由付き除外は、技術的に不適切な対象への別の判断として併設する。** どちらも核マスクの削除を統計の通行条件にしない。

ただし、ガードを単に外して残った値を平均する案ではない。破損した来歴、古い親マスク、未解決の処理失敗、実験回全体の値の欠落などは引き続き止める。欠測を認めた結果は「核小体を確定できた核についての値」であり、全核の値や処理効果の不偏推定と同一視しない。核小体を確定できた割合と欠測理由を群・実験回ごとに併記する。

現状のガードは、不明な対象が統計から黙って消えることを防ぐ点で妥当である。一方、すべての核を `candidate` にするか、核または視野を取り除かないと進めない設計は、核小体の変化そのものを調べる実験に不向きであり、デモでは実際に核の削除を促している。研究者の確認を必須にする意図を、全件確定ではなく「証拠・欠測・除外の判断を保存すること」に移す。

## 1. 現状の挙動と根拠

以下の「確認した事実」は基準コミットの静的読解と公開 JSON の照合による。コードの実行で再現した結果とは区別する。

### 1.1 下位の計算はすでに欠測を表せる

- `derive_compartment_masks` は、各親核の状態を保存し、`candidate` の親だけについて完全な核小体の和集合と核質を作る。候補がないことから「核小体の信号は 0」「核全体が核質」とは推定しない。核は来歴に残り、`missing_parent_count`、理由、対象核 ID が残る。
- compartment protocol 1.1.0 では `review_required` の親に属する有効な個別候補を表示・測定用に残せる場合がある。しかし親の核小体の総量・補集合が完全であることにはならない。
- `prepare_compartment_observations` は保存済み summary の `no_nucleolus`、`no_nucleoplasm`、`nonpositive_signal` 等を欠測として扱う。数・面積でも候補なしを統計上の 0 にしない。ただし、この summary の理由だけでは元の `no_candidate` と `indeterminate` 等を区別し切れず、提案する台帳には親の状態との結合が必要。

根拠：[compartment_engine.py](../../../packages/analysis/src/cytellect_analysis/compartment_engine.py) の `derive_compartment_masks` / `nucleoplasm_from_adopted_nucleoli`、[compartment_observations.py](../../../packages/analysis/src/cytellect_analysis/compartment_observations.py) の `prepare_compartment_observations`、[計算仕様](../../methods.md) の Per-nucleus compartment-summary selection / Group comparison contracts。

### 1.2 上位の受付は「選択された視野がすべて完全」であることを求める

`assert_complete_compartments` の条件は、単に `candidate` 以外の有無だけではない。

| 条件 | 現在の判定 |
|---|---|
| recipe.source が `fiji_nuclear_compartment` 以外 | このガードの対象外 |
| 視野全体の明示的除外（`region_id is None`） | 検査対象から外す |
| `nucleolar_states` が辞書でない、または `missing_parent_count` が整数 0 でない | 拒否 |
| 選択視野に `candidate` 以外が一つでもある | 拒否 |
| 核質で `nucleoplasm_missing_reasons` が空でない | 拒否 |
| 核単位の既存の region exclusion | このガード自体は免除条件として読まない |

根拠：[compartment_review.py](../../../packages/analysis/src/cytellect_analysis/compartment_review.py) の全体、[test_compartment_review.py](../../../tests/test_compartment_review.py) の既存試験。これはガードの条件表であり、ガード単体が来歴の全整合性を証明するという意味ではない。親と状態の全件対応・マスクのハッシュ等は他の処理にも依存する。

呼び出しは、[API app.py](../../../services/api/src/cytellect_api/app.py) の `/review`、[region_cohorts.py](../../../services/api/src/cytellect_api/region_cohorts.py) の cohort 構築、[API common_statistics.py](../../../services/api/src/cytellect_api/common_statistics.py)、[worker common_statistics.py](../../../services/worker/src/cytellect_worker/common_statistics.py) にある。cohort では例外を HTTP 409 `cohort_compartments_unresolved` に置き換える。1 視野の未確定が、複数視野をまとめた cohort 要求全体を止めうる。

「すべて計算できない」の範囲にも注意する。独立した核の revision の核面積・輝度等まで、このガードで禁止しているわけではない。個別マスクや診断用の測定表も存在できる。基準の descriptive API は同じガードを直接呼ばないが、通常の確定版の記述統計は `reviewed` を必要とし、その `/review` が止まる。未確認の descriptive-preview は別経路であり、それを正式統計の解決策にはしない。PR #107 の追加実装は基準に未統合なので、現状の根拠に混ぜない。

### 1.3 確認を必須にしている意図と、残る問題

モジュールの目的は未分類の核区画が推論から消えることを防ぐこと、cohort のコメントは何が統計を妨げているかを研究者が確認することを明示する。[nucleolar-compartments.md](../../nucleolar-compartments.md) も、一括承認を未確定核の解決の代わりにしてはいけないとする。

この意図には賛成する。ただし `candidate` は検出・採用状態であって、生物学的正しさの証明ではない。また「全件が確定するまで止める」は「研究者が理解して判断する」と同義ではない。確認後にも核小体を決められない核はあり得る。その場合に核を消して条件を満たすことは、未確定がなくなったように見えても問題を解決していない。

要件 [M-08、Q-01–Q-04、X-04、N-07](requirements.md) は、欠測と 0 の区別、全核・対象核・欠測数、除外の事前規則と前後比較、止める理由の明示、旧結果の再生を求める。下位の欠測表現と上位の一律停止の間を、これらの要件に沿って設計し直す必要がある。

## 2. DS6a の fragment_review の評価

### 2.1 実際に行う処理

[build.py](../../../services/showcase/src/cytellect_showcase/build.py) の `review_fragments` は、核小体検出の後に次を行う。

1. `nucleolar_states != candidate` の親核だけを抽出する。
2. 各視野の核面積の中央値を計算し、抽出核がすべてその `0.6` 倍未満か調べる。一つでも以上なら build を停止する。
3. 条件を満たす親核を通常 API の `region-edits`、`operation=delete` で核マスクから削除し、その revision を採用する。
4. 核小体を再検出し、核質を計算し直す。削除 ID、面積、視野内中央値を manifest に保存する。

すなわち全体の選別条件は **「未確定」かつ「小面積」** である。面積判定部分だけを指して「規則は面積だけ」と書くと、検出結果に依存する前段が伝わらない。コードは端への接触を判定していない。

[公開 manifest](../../../apps/web/public/showcase/manifest.json) の DS6a 場面 `scenario.fragment_review` を、同じ snapshot の [region-fields 応答](../../../apps/web/public/showcase/snapshot/1b9aa10054a3478977b9af38.json) と ID で結合すると次の 3 物体である。

| 視野 ID | 条件・記録上の反復 | 親核 ID | 面積 px² | 視野中央値 px² | 比（概数） |
|---|---|---:|---:|---:|---:|
| 91163bc0-1ad2-4517-9863-110f19cf595e | Untreated・Rep2 | 6 | 2079 | 4205 | 0.494 |
| feff3021-e978-4190-a824-e1ff7094b204 | Untreated・Rep2 | 3 | 3222 | 5550 | 0.581 |
| ec8df691-469c-49ec-9754-f09c792fccb0 | ActD 1 µM・Rep3 | 9 | 152 | 5470 | 0.028 |

この反復ラベルから実験の独立性は推定しない。[場面定義](../../../services/showcase/datasets/zenodo-6643470-nucleolar.json) の `derivation_amendment` は、初回の解析後に切り出しを変更し、再実行後にこの断片除去を適用した経緯を記す。「核小体・5-EU の値を見る前」「3 物体とも切り出し端」との説明もあるが、これは作成側の記録である。本レビューでは原画像上の 3 物体を独立に判定しておらず、核断片・誤検出だとは確定しない。

### 2.2 評価

**良い点（事実）**：独自のマスク処理で API を迂回せず、通常の編集と依存領域の再計算を使う。大きい未確定核は無断で落とさず止める。削除の一覧と変更経緯を公開している。数値や原画素を直接書き換える処理ではない。

**問題（設計上の評価）**：それでも採用する母集団と核マスクを変えている。0.6 倍という条件だけでは真の小核、切断された核、誤検出を識別できない。視野内中央値による閾値は同じ式でも各視野で変わる。さらに「核小体を検出できない」という条件を先に用いるため、核小体の変化に関係する細胞を選別する可能性がある。値を見る前であっても、検出結果を見た後の選別であることは変わらない。

Schmidt らの [原著 Fig. 5A–B](https://pmc.ncbi.nlm.nih.gov/articles/PMC9749789/) は、U2OS の薬剤処理における核小体の 5-EU と形の比較を扱う。このような比較で「確定できないこと」が処理の影響と関連する可能性を無視できない、というのが本メモの推論である。この論文が Cytellect の 0.6 倍規則や今回の 3 物体の削除を検証したわけではない。

Q-03 / X-04 の流用禁止は特に核数・核の大きさの場面を対象にするので、これだけを根拠に核小体場面への適用を一律違反とは断定しない。しかし Q-01 の事前規則と、変更後に何を対象としているかの説明は核小体にも必要である。自動処理を「研究者が断片と確認した」と同一視しない。manifest に履歴があることと、削除の科学的妥当性は別の評価である。

**提案**：新しい公開デモでは fragment_review を統計の停止解除のために自動適用しない。旧記録は修正・抹消せず、その定義のまま再生可能にする。将来の新規結果は元の核を保持した新 revision で作り、以下の欠測方針を適用する。3 物体の妥当な判定と、除去による結論の変化は未検証であり、「影響は小さい」とは述べない。

## 3. 三つの案の比較

| 案 | 科学的な妥当性・限界 | 研究者の操作 | 保存結果の互換 | 版の扱い |
|---|---|---|---|---|
| **(a) 未確定核を欠測として残す** | 真の 0 と不明を分け、親核・分母を保持できる。確定できた核の値には選択の偏りが残り得る。欠測台帳は偏りの補正ではない | 画像へ戻れる欠測一覧と群・実験回別の内訳を確認し、対象となる核の定義を了承して計算。全核を個別修正することは強制しない | 旧要求の既定は現行の全件確定。新方針は明示的選択、新 revision / 結果として保存。旧結果の再計算・上書きをしない | 受付・観測対象が変わるため、欠測の採用方針を独立した版付き契約にする。結果の台帳・Methods・export/replay の対応も版管理。既存の欠測数式だけを理由に無版変更しない |
| **(b) 親核ごとの理由付き除外** | 事前規則に基づく技術的な対象外を区別できる。除外で偏りが消えるわけではない。核小体が見えないことだけを除外理由にすると表現型を捨て得る | 画像上の親核を指定し理由を選ぶ。適用する指標の範囲を示し、取消可能にする。一括操作も各核の判断記録を残す | 核マスクを保持し、親 revision + field + nucleus ID に結びついた除外台帳を追加。既存 child region ID と混同しない。元結果は保持 | 親核を対象とする除外契約とガード・集約規則の版が必要。既存の region exclusion を追加するだけでは現行ガードを解除できない |
| **(c) 現状維持** | 未確定が黙って消えることは防ぐ。ただし、困難な核・視野を削除して進む誘因が残る。全件 candidate でも正解とは限らない | 再検出、根拠のある輪郭修正、または明示的な視野除外が必要。完遂できない実験が残る | 最も単純。既存結果・受付の挙動をそのまま保つ | 新しい計算方針の版は不要。案内文だけを直すなら数値の版は維持。ただしデモの削除を正当化する根拠にはならない |

(a) と (b) は排他的ではない。未確定は測定上の状態、除外は研究者の判断として別軸に保存する。理由なしの「すべて了承」で candidate に書き換えたり、欠測を除外に付け替えたりしない。

## 4. 推奨案の具体的な境界

### 4.1 状態と対象指標を分ける

以下は提案であり、現在のコードの許可表ではない。

| 状態・事情 | 推奨する扱い |
|---|---|
| `candidate` と整合した採用マスク | 指標ごとの品質条件を満たす値を使用。独立した研究者の確認は維持 |
| `no_candidate`、`indeterminate` | 核は保持。未確定の核小体・核質の指標を欠測として記録し、範囲を確認して (a) で進める。生物学的不在とは呼ばない |
| `review_required` | 保存候補を表示して確認。親の和集合・核質・親単位の統計には未確定を残す。確認済みでも決められなければ理由を伴う欠測。古い親マスクへの依存なら停止して再作成 |
| `processing_failed` | 成功した検出と同一視しない。再試行・手修正、または (b) の明示的理由付き除外まで正式解析を止める。診断表は読めるようにする |
| 状態表なし、`unclassified`、壊れた親 ID / ハッシュ | 欠測承認で通さず、来歴・入力の整合性を直すまで停止 |
| `not_measured_recipe` | 指標が対象外。欠測許可で未実装の測定を利用可能にしない |
| `legacy_candidate`、`none_after_edit` | 旧経路の定義を保持し、新方針へ暗黙に正規化しない |
| `empty_after_subtraction`、信号が非正、形が退化 | 指標別の欠測。核質が空でも核小体面積まで無効とは限らないが、現行の核質経由 summary の結合条件を壊さない新しい適格性検査が必要 |
| 研究者が「不在を確認」 | 検出の候補なしと別の証拠付き判断。今回の案では既存 count / area の欠測を 0 に変更しない。全核を母集団とする真の 0 を扱う指標は別定義・別版で判断 |

この変更には `/review`、cohort、共通統計 API/worker、記述統計、export/replay の一貫した変更が必要。一か所だけでガードを無効化しない。未確定核を親単位で欠測にする処理と、残った核小体を物体単位で扱う処理を混ぜない。

### 4.2 台帳・結果・画面

- 全親核の ID、親/核小体 revision・mask hash、元の検出状態、採用判断、理由、適用指標、判断者・時刻・方針版を結びつける。画素やマスクは欠測・除外操作で変更しない。
- 群・実験回・視野ごとに、全親核、明示的除外、対象核、そのうち値がある核と欠測核を表示する。相互排他的な主集計で件数が一致し、元の理由は重複を許す補助台帳に残す。分母を「対象核」だけに縮めず、除外前の全核も示す。
- 核小体を持たない核にも親 ID がある。核質の測定行が存在しないから除外できない、という設計にしない。核の全般的な対象外と「この核小体指標だけ対象外」を区別し、核数・核面積へ自動波及させない。
- 図・結果の文・CSV・Methods に同じ対象と内訳を保存する。文例：「採用した核小体を確定できた核について比較しています。群別・実験回別の対象核数と欠測を下に示します。」説明を閉じても対象が分かるようにする。
- 閾値・群差・p 値を見て採用判断を変えることを勧めない。判断変更は新しい結果として残し、旧方針との違いを示す。任意の欠測率を自動合格の閾値としてここでは設定しない。

### 4.3 実験単位と推論を守る

親核が欠測でも実験日・視野は台帳から消さない。現行 [region-comparisons.md](../../region-comparisons.md) の、未解決の視野失敗や未除外の実験単位に値が一つもない場合は停止する方針、対の片側だけを黙って除去しない方針を維持する。全核欠測の視野を「核数 0」とも「値 0」とも扱わない。

同一実験単位の他視野に値がある場合の集約は既存の階層を用いるが、欠測視野と各単位が何視野に基づくかを残す。欠測の認識は独立性の確認とは別であり、DS6a の独立性を推定したり、記述比較から検定へ自動切替したりしない。

記述でも推論でも対象は「確定できた核に条件づけた値」である。群で欠測の理由・割合が違う場合、全核に一般化した主張を控え、測定法・対象定義を見直す。除外前との比較で値が存在しない部分に補完値を作らず、「算出不能」と台帳の差を示す。欠測率を新しい生物学的エンドポイントとする場合も、別途定義・検証する。

### 4.4 保存互換と統合順序

1. 主担当が欠測方針・親核判断の契約と版を割り当てる。概念上は「現行の全件確定」と「確認した欠測を保持」を区別し、旧要求で項目がない場合は前者とする。新しい既定値を旧 JSON に追加して保存バイト列を変えない。
2. 単なる画面警告の追加と、対象選択・集約の変更を分ける。数式が同じでも結果の母集団が変わるため、後者は版付き方針を結果・source fingerprint・export に含める。summary に理由の情報を追加するなら、その保存形式にも対応する版を設ける。
3. 旧 recipe / selection / 結果は旧解釈で再生し、削除済みの核を旧結果へ勝手に戻さない。新しい対象を計算するときは元画像・編集前の親 revision と来歴が揃うことを確認し、新 revision を作る。足りなければ再計算不能と明記する。
4. 親核を再編集したときは判断を ID だけで新マスクへ流用しない。依存する核小体・核質・統計・図を無効化し、再確認する。
5. 契約 → 共通解析と受付 → 画面・出力・再生 → 公開デモの順に統合する。PR #107 の記述統計拡張とも接続方針を合わせるが、このメモは同 PR のマージを前提としない。

## 5. 実装前に決める受入条件

今後の実装で検証すべき項目であり、今回合格した試験ではない。

- 登録済みの公開実画像と保存済みマスクで、候補あり・候補なし・判定不能・処理失敗・レビュー待ちを区別する。検出の精度を改善したという評価には使わない。
- 一部の核が欠測の視野では、有効な核の保存測定値を変えずに図を作れ、全親核と理由を台帳で照合できる。未確定核の核数や核面積が削除されない。
- 全親核が欠測の視野、実験単位全体に値がない場合、対の片側がない場合、完全な視野除外、親核の除外取消を別々に扱う。独立性未確認では検定を生成しない。
- summary の短い理由だけに潰さず、親の元状態と指標別欠測が追跡できる。処理失敗や来歴の破損を通常の欠測として通さない。
- 旧要求・保存 JSON・旧版で再生する結果が不変。新結果は API/worker/export/replay で同じ方針・台帳・数値になり、未対応版は明示的に拒否する。
- DS6a は fragment_review なしの新 revision でも未確定を表示できる。削除前後の値が算出可能な範囲だけで感度を比較し、算出不能部分も残す。原画素・既存公開記録を書き換えない。

## 6. オーナーに判断を求める事項

1. **対象の定義**：(a) を基本とし、「核小体を確定できた核の記述・比較」を許可するか。全核についての効果とは区別することを承認できるか。
2. **確認の単位**：画像へ戻れる理由別・群別の一覧を必須確認とし、核ごとの全件クリックは要求しない案でよいか。(b) の明示的除外には核ごとの理由記録を求める。
3. **停止する状態**：処理失敗・来歴破損は引き続き停止する案、実験単位に値がない場合や不完全な対を自動で落とさない案でよいか。欠測率による一律の閾値は今回は設けない。
4. **DS6a の扱い**：今後の新しいデモでは通行条件としての fragment_review を使わず、旧版は来歴付きで保持するか。既存 3 物体を本当に対象外とするなら、誰がどの事前規則・画像根拠で判断するか。今回のメモだけで削除を追認しない。
5. **確認された不在**：今回の変更に真の 0 を扱う新指標まで含めるか。推奨は別課題とし、現在の count / area / shape の定義を維持する。
