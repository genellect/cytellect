# 群間比較の実画面 UX レビュー

対象コミット: `40a6a0b9d0579c41d528cfd837e1d16733b74f4f`。Windows、実 API・worker・Fiji、同コミットの Web を使用。研究者による C9/C10 の代替ではない。

## 方法と限界

操作の説明書・使い方ガイドを開かず、実際のラベルから操作した。要件・実装を読む独立整合レビューも並行しているため、完全な初見研究者とは称しない。画面操作はブラウザ経由。公開実画像だけを使い、検出設定・しきい値・モデルは変更しない。

JUMP の登録 fixture は `fixtures/public/jump-plk1/files.json`。指定取得スクリプトで144ファイル、398,721,024 bytesを取得・SHA-256照合した。入力課題は各群・Run1–3のF001–005、4ch（DNA/RNA/ER/AGP）、計120ファイル。現実の染色に合わせて明示的に対応を設定する。

Web直接依存は固定版と一致。共有依存の推移的依存には Sharp 0.35.5/基準0.35.4、Vite 8.3.3/基準8.3.2の差がある。完全に同じlock環境の検証とはしない。別の公開BBBC039結合試験はPR #103に分離する。

## 指摘

### 重大

1. **JUMPの原ファイル名で4チャンネルを1視野にできない（E-04/C1）。** Run1/A02/F001–005 の20ファイルを実験表の「画像を追加」から入れると20視野になる。A01/A02/A03/A04が視野キーに残る。5視野の確認・訂正を挟まず登録が完了するため、研究者は撮影位置とチャンネルの違いを取り違えたまま進める。改善案: 登録前の組分け一覧に撮影位置・4ch・染色未確定を示し、JUMPの明示メタデータ/ファイル名規則を扱えるようにする。原画像の改名を利用者の必須作業にしない。

2. **追加視野に染色対応が反映されたか分からず一括測定が失敗する。** 最初の5視野で染色対応を設定し、その後25視野を追加。画面には4染色と核検出c1が表示されるが、測定runは成功4・再利用1・失敗25（analysis_run_settings_invalid）となった。公開テスト専用storeを読み取り確認すると、失敗runのassignments_snapshotはversion1・適用5視野だった。同じ染色対応を保存し直すとversion2・適用30視野になり、後続視野も処理が進んだ。チャンネル対応だけの再保存であり検出モデル/しきい値は変えていない。use-workspace-runtime.ts:438–443のsaveAssignmentsは既存登録群にだけfield_idsを指定し、後から追加した視野の未確定状態が画面で分からない。改善案: 各セルに「チャンネル対応済み/未確定」を表示し、追加時の明示適用と、実行前に対象全視野の不整合をまとめて知らせる。設定済みに見えるまま数分後の汎用エラーにしない。候補採用ボタンも「現在の条件に一致する候補がありません」となったため、採用可能な対象だけに限定する。

3. **承認した2場面が実際のデモ記録にない（X-01/X-02）。** 初回は旧DS6a画像と領域表。核数JUMP・核小体DS6aの切替も比較の一文もない。新指標を選択できるため、記録済みと誤解しやすい。改善案: 初回を「対照/処理の画像→どの違いか→実験回点と一文」にし、利用可能な場面/指標だけを先に示す。旧デモの再生成功と新デモ完成は分けて表示する。

4. **選択中の問いと保存結果が別なのに同時に表示される。** 左は「視野あたりの核数」、図は「NPM1: Mean intensity」、右は「核・平均輝度・npm1」。画面状態として実測。記録外計算を案内した後にも旧結果が残る。改善案: 旧結果に「前の解析：NPM1平均輝度」と見出しを付けるか、選択と結果の領域を分離し、新規計算前は結果が更新されていないことを明示する。

重大の追加指摘: **新しい核数指標の記述が実行できない。** 全30視野を採用しても「核数→分布→計算」は `invalid_request_parameters`。ConnectedResults.tsx:190は分布を既存descriptive APIへ送り、descriptive_contracts.pyのselectionには新しいfield-summaryの契約がない。群の独立性を確認済みにすることで解消すべき問題ではない。核数の分布・群ごとの記述・各回の観測差を共通解析に接続し、検定/信頼区間の前提確認と切り分ける。

重大の追加指摘: **並置の実験回を切り替えても測定対象の表示が切り替わらない。** 左右をRun2に変えても、上部はRun1-A02-f002、測定値は同視野の候補299のまま。PairStage.tsx:42,51は上位選択を更新せず、ConnectedWorkspace.tsx:219の「選択視野」の測定は上位field.idを使う。実際に誤対象を再測定したという主張ではないが、表示から意図した視野を測ったと誤解しうる。各側に対象選択を明示し、選択視野・候補・測定ボタンを同期する必要がある。

### 中

5. **1画面に対応比較の警告が出る（E-01/T-05/N-06）。** 空の1群実験で「対にできません」と表示する。改善案: 1画面では記述に必要な不足だけを示し、独立性の確認は比較に広げた時点で案内する。

6. **結果より先に長い台帳が来る（S-01/S-07）。** コードConnectedResults.tsx:271–273では開いた実験情報表が一文より前。今回30視野の一文までの実操作は未到達だが、並びはコードで確定する。結果→n/注意→実験回点/値→図→畳んだ詳細の順を提案する。小nでは各回値を畳まない。

7. **390 pxでは表の日本語見出しが1文字ずつ折れ、上下に複数のスクロール領域ができる。** 公開デモの統計表で確認。比較表はDOM実測で幅約1358px・高さ約4013px、JSONを含む1データ行が約3731pxで、スクロール中はほぼ空白に見える。少数の主要列をカードにして技術的な詳細表を畳み、長いJSONをセルに流し込まない。図は縮小されるが、長い指標説明・パネル・AI入力が画面を占め、全体と凡例を一度に読めない。スマートフォンで論文図を編集する完成度は未達。

8. **旧結果の詳細に内部列名がそのまま現れる。** 公開デモの統計表にstatistic、degrees_of_freedom、standard_error、method_settingsとJSON、n_a/n_b/n_unitを表示した。Methods用の技術情報は「計算の詳細」に畳み、主要表示を実験回数・差・CI・検定名にする。単純にn_aを「核数」と訳さない。

新しい30視野の面積記述図も、横軸がField 1等、凡例がObservation/Field median、4ページに分かれ、群・実験回は図上で読めない。表の視野名と群名を探す必要がある。対照と処理を並べ、各回・各視野と観測領域数の階層を示す記述表示を提案する。観測数を独立なnに読み替えない。

9. **表示注記の保証が強すぎる（V-03）。** PairStage.tsx:72の「同じ明るさは同じ保存値」は、previewのクリップ/量子化と変換失敗fallbackを含めて保証できない。画面では値域と露光差の注意が読めた点は良い。「範囲内で共通変換、範囲外と量子化の差は比較不可」に限定し、失敗時の注記を変える。

### 軽微・良かった点

- 問い別の指標分類「数が増えた・減ったか」「大きさが変わったか」は研究目的から選びやすい。校正不足のµm²と密度が理由付きで無効な点も良い。
- 並置に対照バッジ、実験回、左右の視野名がある。同じ細胞の前後像だと明示的に誤記していない。
- 公開デモの未記録操作は説明文となり、クラッシュやAPIエラー表示ではなかった。SVG保存の範囲とWindows版のZIPの違いも案内できた。
- 「保存した図」が「群間比較 · 1」だけでは指標が分からない。核数/核面積/染色・実験回数を短く含めると旧結果の選び間違いを減らせる。

## アクセシビリティと検証範囲

- Tabで「グラフ」から「設定パネル」へ移り、青色2pxの可視フォーカスを確認。主要select/inputはlabelで包まれ、AI入力にはaria-labelがある。ラベルにoption全内容が含まれるため、正確な短い名前で探す代理操作は失敗したが、これは直ちにラベル欠落とは判定しない。
- 図の対照/処理は丸と四角も使い、色だけに依存しない。全ての点・編集・ダイアログのキーボード完遂は未実施。
- 案内文の計算済みCSSはrgb(102,113,127)、14px、白背景上。WCAGの輝度式で約4.96:1（通常文字4.5:1以上）。この1組の確認を全画面のAA適合とは呼ばない。無効ボタン、hover、全図色、全状態のコントラストは未確認。
- 390 pxは公開デモで確認。並置は1440 pxで確認した。実ローカル版の全画面390 pxとスクリーンリーダーの読み上げは未確認。

## 未確認・次の確認

初回接続の入力失敗と日付入力の戻りは、代理操作起因を排除できていないため製品不具合とは断定しない。Run1–3は出典のbatch対応だが、日付欄に残った試験時の既定日は取得日を意味せず、実験日の根拠として使わない。独立性は未確認のままにし、根拠なく確認チェックを付けない。新しい30視野の比較の一文・n・図まで未到達の部分を、別のBBBC039試験や旧デモで合格に置き換えない。

実行: API/worker/Webをローカル起動、JUMP取得/ハッシュ照合、Web production build（APIなし）、`python scripts/check_docs.py`、`python scripts/check_public_tree.py`、`git diff --check`。実画面は上表。production buildは成功したがstandaloneの外部共有依存trace警告27件があり、配布パッケージの検証ではない。非公開画像・有料実行・本番公開は行っていない。

## オーナー判断

採用済みデータ・検出設定の再承認は不要。独立性は画面操作で変えられる性質ではなく、未確認のまま記録する。実画面で確認した推測統計の停止を、場面不採用の理由にはしない。未確認でも群ごとの記述と各回の差を見せる設計と、推測統計の前提を分ける。C9/C10の研究者評価と、統合したWindows版のC11受入は別途必要。
