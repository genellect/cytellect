# 群間比較の実画面 UX レビュー

対象コミット: `40a6a0b9d0579c41d528cfd837e1d16733b74f4f`。Windows、実 API・worker・Fiji、同コミットの Web を使用。研究者による C9/C10 の代替ではない。

## 方法と限界

操作の説明書・使い方ガイドを開かず、実際のラベルから操作した。要件・実装を読む独立整合レビューも並行しているため、完全な初見研究者とは称しない。画面操作はブラウザ経由。公開実画像だけを使い、検出設定・しきい値・モデルは変更しない。

JUMP の登録 fixture は `fixtures/public/jump-plk1/files.json`。指定取得スクリプトで144ファイル、398,721,024 bytesを取得・SHA-256照合した。入力課題は各群・Run1–3のF001–005、4ch（DNA/RNA/ER/AGP）、計120ファイル。現実の染色に合わせて明示的に対応を設定する。

Web直接依存は固定版と一致。共有依存の推移的依存には Sharp 0.35.5/基準0.35.4、Vite 8.3.3/基準8.3.2の差がある。完全に同じlock環境の検証とはしない。別の公開BBBC039結合試験はPR #103に分離する。

## 指摘

### 重大

1. **JUMPの原ファイル名で4チャンネルを1視野にできない（E-04/C1）。** Run1/A02/F001–005 の20ファイルを実験表の「画像を追加」から入れると20視野になる。A01/A02/A03/A04が視野キーに残る。5視野の確認・訂正を挟まず登録が完了するため、研究者は撮影位置とチャンネルの違いを取り違えたまま進める。改善案: 登録前の組分け一覧に撮影位置・4ch・染色未確定を示し、JUMPの明示メタデータ/ファイル名規則を扱えるようにする。原画像の改名を利用者の必須作業にしない。

### 中

2. **1画面に対応比較の警告が出る（E-01/T-05/N-06）。** 空の1群実験で「対にできません」と表示する。改善案: 1画面では記述に必要な不足だけを示し、独立性の確認は比較に広げた時点で案内する。

## 未確認・次の確認

390 px、キーボード、コントラスト、比較の一文と図、公開デモの記録外操作を継続確認する。初回接続の入力失敗と日付入力の戻りは、代理操作起因を排除できていないため製品不具合とは断定しない。

## オーナー判断

採用済みデータ・検出設定の再承認は不要。C9/C10の研究者評価と、統合したWindows版のC11受入は別途必要。
