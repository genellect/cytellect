# Windows 版のかんたん導入と利用者の認証：要件・実装案・完了条件（案）

作成：2026-10-29。改訂：2026-10-29（Codex のレビューを反映：起動時の警告、承認待ち、失敗からの復帰、完了条件、実装の順序）。状態：**オーナーの判断待ち**（[§9](#9-オーナーが決めること)）。承認後は、内容を[要件](../../requirements.md)、[Windows 版のインストール](../../install-windows.ja.md)、[クラウド GPU](../../cloud-gpu.ja.md)、[解析提案](../../proposal-service.md)、[データ保護](../../security.md)、[ロードマップ](../../roadmap.md)に反映する。

## 1. 目的

> IT に詳しくない初回の利用者が、対応する Windows PC で、手順書・口頭の支援・コマンド入力・管理者権限・セキュリティ設定の変更なしにインストールを完了し、画面の案内だけで最初の解析を始められる。途中で中断・失敗しても、次に行う操作が分かり、再開できる。
>
> 有料サービス（GPU 推論と解析提案）は、オーナーが許可した利用者だけが、ログインの操作 1 回で使える。

## 2. 背景（0.1.0-local.20 の課題）

| 課題 | 現状 |
|---|---|
| 導入 | ZIP を保存し、短いパスに展開して `Cytellect Setup.cmd` を実行する。署名がなく「PC が保護されました」が出る。初回は 8 つの取得先から約 1 GB を取得し、5〜20 分かかる。Smart App Control に止められた PC がある |
| GPU 推論 | 管理者が Modal の接続用トークンを作り、ID と Secret をつないで研究者に渡す。研究者はセットアップ画面に貼る。変えるにはセットアップをやり直す。最初の 1 視野は GPU の起動待ちで、経過が出ない |
| 解析提案 | 管理者が招待を発行し、研究者側で `POST /v1/devices` を送って端末用トークンを得て、環境変数に設定する。画面がない |

## 3. 利用の流れ

### 3.1 導入（全員）

1. 公開サイトの「Windows 版をダウンロード」を押す。ボタンの近くに、対応する Windows、必要なメモリと空き容量、ファイルの大きさを示す。
2. ダウンロードしたインストーラーを開く。警告やセキュリティ設定の変更なしに進む（[§4.1](#41-導入i) I1）。
3. 終わると作業画面が自動で開き、「インストールが完了しました」と表示する。次の 2 つを選べる。
   - **このPCで解析を始める**：公開の練習画像を開き、核の検出・測定・統計・図をすぐ試せる。ログインは不要。
   - **クラウド機能を有効にする**：GPU 推論（核小体・細胞の検出）と解析提案を使うためのログインへ進む。

### 3.2 クラウド機能を有効にする

| 利用者の状態 | 画面の流れ |
|---|---|
| オーナーが許可済み | メールアドレスを入れる → 6 桁のコードがメールで届く → 入れる → 「クラウド機能が使えます」 |
| 未許可 | メールアドレスを入れる → 「オーナーに利用を申請しました。承認されるとメールでお知らせします。それまでも、このPCでの解析は使えます」→ 承認されると、作業画面の表示が「承認されました。ログインを続ける」に変わり、メールでも知らせる |
| 取り消し・期限切れ | 「クラウド機能を使うには、もう一度ログインしてください」または「利用が停止されています。オーナーにお問い合わせください」 |

インストールの完了と、クラウド機能の承認は別の出来事として表示する。承認を待つ間も、ローカルの解析を止めない。

### 3.3 オーナー

- 管理ページで、メールアドレスを許可する。研究者の申請は、届いたメールの「承認」を 1 回押して許可する。
- 管理ページで、利用者ごとの利用量の確認、上限の変更、許可の取り消しを行う。

## 4. 要件

### 4.1 導入（I）

| ID | 要件 |
|---|---|
| I1 | **対応する PC で、セキュリティ設定を変えずに、導入と起動ができる。** SmartScreen と Smart App Control を別々に満たす。署名しても SmartScreen の警告が必ず消えるわけではなく、Smart App Control には特定のアプリだけを許可する操作がないため、配布の方式（署名・Microsoft Store など）を実機で確かめてから決める（[§6](#6-段階と目安) 段階 0）。止められるとアプリの中の案内は表示できないため、画面での案内は I1 の代わりにならない |
| I2 | 配布物はインストーラー 1 つ。管理者権限、コマンド、展開、インストール先の選択を求めない（インストール先は `%LOCALAPPDATA%\Cytellect`） |
| I3 | Python・ライブラリ・Fiji を同梱し、初回の外部取得をなくす。配布の大きさ、導入に必要な空き容量、対応する PC の条件を決め、ダウンロード画面に示す |
| I4 | インストーラーは、開始前に OS・CPU（x64）・メモリ・空き容量を確かめ、満たさないときは理由と対処を日本語で示して、何も変えずに終わる |
| I5 | インストーラーをもう一度実行しても壊れない（途中で止めた場合も、同じ操作で続きから終える）。すでに起動中なら、そのことを示して作業画面を開く |
| I6 | 導入が終わると作業画面がブラウザで開き、デスクトップとスタートメニューにショートカットができる |
| I7 | 更新は作業画面の「更新があります」から 1 回の操作で行い、研究データと設定を引き継ぐ。更新に失敗したら元の版がそのまま使える。0.1.0-local.20 以前の保存先からも引き継ぐ |
| I8 | アンインストールは Windows の「アプリ」から行える。研究データを消すかは確認してから決める |

### 4.2 認証と許可（A）

| ID | 要件 |
|---|---|
| A1 | ログインはメールアドレスと 6 桁のコードで行う。パスワードは使わない |
| A2 | オーナーが許可したメールアドレスだけがログインできる。未許可の宛先にはコードを送らず、申請として受け付ける（[§3.2](#32-クラウド機能を有効にする)） |
| A3 | 申請はオーナーにメールで届き、「承認」の 1 回の操作で許可できる。承認すると、研究者にメールで知らせ、作業画面の表示も変わる |
| A4 | ログインは端末ごとに保持し、90 日使わなければ失効する（[§9](#9-オーナーが決めること) D3）。作業画面からログアウトできる |
| A5 | オーナーが許可を取り消すと、1 分以内にその利用者のすべての端末で GPU と解析提案が止まる。ローカルの解析はログインなしでも使える |
| A6 | 管理ページはオーナーだけが開ける（オーナーのメールアドレスでの同じコード認証） |

### 4.3 GPU 推論と解析提案（C）

| ID | 要件 |
|---|---|
| C1 | ログインした端末は、追加の設定なしで GPU 推論と解析提案を使える。接続先・接続キーの入力はなくす |
| C2 | Modal と OpenAI の鍵は中継サーバー（Cloudflare Worker）だけが持ち、PC・配布物・ログに置かない |
| C3 | 利用者ごとと全体に月の上限（GPU の秒数、解析提案の費用）を設ける。上限に達したら、理由と再開の時期を示す。Modal の Spend limit 0 ドルは維持する |
| C4 | Cellpose を選んだ時点で GPU の起動を始める。起動中は経過を表示し、503 は決めた時間まで自動で再試行する |
| C5 | 送るデータは今と同じ（検出に使う 1 チャンネル、核のマスク、検出条件）。中継サーバーは画像と結果を保存・記録しない |
| C6 | GPU の結果は、今と同じく runner・モデル・依存パッケージのハッシュを照合し、記録に GPU の種類を残す |

### 4.4 状態の表示と、失敗からの復帰（R）

どの段階でも、**いま何が起きているか**と**次に押すもの**を画面に出す。利用者が「待てばよいのか、押し直してよいのか」を判断しなくて済むようにする。

| 段階 | 表示する状態 | 失敗・中断のときの表示と次の操作 |
|---|---|---|
| ダウンロード | ファイル名と大きさ | 途中で止まった：「もう一度ダウンロード」 |
| インストール | 「準備しています（約 N 分）」と進み具合 | 容量不足：必要な空き容量と「空きを作ってからもう一度開く」。非対応の PC：理由。途中で閉じた：もう一度開くと続きから |
| 初回起動 | 起動・停止の小さな画面に「起動の準備中」→「作業画面を開いています」 | ブラウザが開かない：「作業画面を開く」ボタン。ポートが使用中・起動の失敗：理由と「再起動する」 |
| ログイン | 「コードを送りました（宛先）」 | 届かない：「迷惑メールを確認」「コードを再送」（60 秒後に有効）「メールアドレスを修正」。期限切れ・誤り：残りの回数と「コードを再送」 |
| 承認待ち | 「承認待ち（申請日時）」。作業画面の上部に常に表示 | 承認されたら自動で表示を切り替える（定期的に確認）。「ローカルの解析を続ける」 |
| GPU 推論 | 「GPU を起動しています」→「検出しています」 | 起動が時間内に終わらない：「もう一度試す」（自動の再試行の後）。上限：再開の時期。通信の失敗：「ネットワークを確認してもう一度試す」 |
| 更新 | 「更新しています」 | 失敗：「元の版で起動しました。あとでもう一度更新してください」 |

文言は、[UX の原則](../../development-principles.md)に沿って、専門用語やエラーコードを主にしない。エラーコードは「詳細」に入れる。

## 5. 実装案

### 5.1 構成

```
研究者の PC（Cytellect）
  ├─ ローカル解析（Fiji、測定、統計、図）……ログイン不要
  └─ 端末トークン ──HTTPS──▶ Cloudflare Worker（既存の解析提案の中継を拡張）
                                 ├─ 認証：メールのコード、許可リスト、申請と承認、端末トークン、管理ページ
                                 ├─ 上限：利用者ごと・全体の月額
                                 ├─ /v1/cellpose/* ──鍵を付けて転送──▶ Modal（GPU）
                                 └─ /v1/proposals ──────────────────▶ OpenAI
メール送信サービス ◀── コード・申請・承認のメール
```

### 5.2 配布とインストーラー

- **配布の方式**は段階 0 の実機の結果で決める。候補は次の 3 つ。
  - コード署名した `.exe`（Inno Setup、利用者単位の導入 `PrivilegesRequired=lowest`）
  - Microsoft Store での配布（Microsoft が署名する）
  - 署名なしの `.exe`。I1 を満たさないため、比較の基準としてだけ使う
- Python・ライブラリ・Fiji は CI で用意して同梱し、ハッシュを照合する。いまの `local-release.yml` の受入（新規導入・更新・ブラウザ試験・数値の再現）は、新しいインストーラーに置き換えて続ける。
- 起動・停止の小さな画面に、状態と「作業画面を開く」を置く（R の初回起動）。
- 更新は、新しい版を別の場所に用意して確認が終わってから切り替え、失敗したら元の版で起動する（I7）。

### 5.3 中継サーバー（`services/proposal-worker` を拡張）

- **データ**（D1）：`users`（正規化したメールアドレス、状態 `pending`／`allowed`／`revoked`、月の上限、申請日時）、`login_codes`（コードのハッシュ、期限 10 分、試行回数）、`devices` を利用者に結びつける、`gpu_usage`（利用者・月・秒数）。画像・目的の文・結果は保存しない。
- **認証の API**：`POST /v1/auth/code`（許可済みならコードを送り、未許可なら申請として記録してオーナーに知らせる）、`POST /v1/auth/verify`（コード → 端末トークン）、`GET /v1/auth/status`（承認待ちの確認）、`POST /v1/auth/logout`。コードは 6 桁、10 分で失効、5 回の誤りで無効。メールアドレスと IP ごとに送信回数を制限する。
- **管理ページ**：`/admin`。オーナーのメールアドレスでログインし、許可・取り消し・上限・利用量を操作する。承認メールのリンクは、1 回だけ使える署名付きの URL にする。
- **GPU の転送**：端末トークンと上限を確かめてから、Worker が持つ Modal の接続キーを付けて転送する。Cloudflare Workers は、クライアントが接続している間は実行時間の上限がない（[Workers の制限](https://developers.cloudflare.com/workers/platform/limits)）。約 5 MB・推論 50 秒の要求が通るかは、段階 2 の最初に確かめる。
- **既存の招待方式**（`/v1/admin/invitations`）は、移行期間の後に外す。

### 5.4 Windows 版の画面とローカル API

- **初回の画面**：「インストールが完了しました」と、「このPCで解析を始める」「クラウド機能を有効にする」の 2 つの選択肢（[§3.1](#31-導入全員)）。
- **ログイン画面**：メールアドレスとコードの 2 段階。状態は R のログイン・承認待ちのとおり。ログイン中は、アドレスと「GPU・解析提案：利用可」を表示する。
- **ローカル API**：`/v1/account/*` を追加し、端末トークンを保存先の設定ファイル（その利用者だけが読める権限）に置く。Cellpose と解析提案の接続先は、配布物に組み込んだ Worker の URL に固定する。
- **GPU の待ち**：Cellpose を選んだ時点で `/v1/cellpose/health` を呼び、起動中の表示と自動の再試行を行う（C4）。

### 5.5 メール送信と独自ドメイン

コード・申請・承認のメールを確実に届けるため、送信元に独自ドメインを使う。

| 案 | 費用 | 注意 |
|---|---|---|
| Resend と独自ドメイン（推奨） | 無料枠は月 3,000 通・1 日 100 通（[料金](https://resend.com/pricing)）。ドメインの費用は [§9](#9-オーナーが決めること) D1 | ドメインの DNS に送信の設定（SPF・DKIM）が要る。将来の SaaS でも同じ仕組みを使える |
| Firebase Authentication のメールリンク | 無料枠で足りる見込み（未確認） | ドメインは不要。コードではなくリンクでのログインになる。別の端末でメールを開いた場合は、メールアドレスを入れ直せば認証できる（[公式資料](https://firebase.google.com/docs/auth/web/email-link-auth)）。ただし元の Windows PC はログイン済みにならず、PC へ戻る導線を別に設計する必要がある |

## 6. 段階と目安

最も大きな不確実性は、「研究室の PC で、利用者が自分で導入できるか」である。この点を最初に確かめる。

| 段階 | 内容 | 版 | 目安 |
|---|---|---|---|
| 0 | **配布の実機検証。** 最小構成のインストーラーで、ダウンロード → インストール → 自動起動 → 公開の練習画像を開く、までを研究室の PC（Smart App Control が有効な PC を含む）で確かめる。署名あり・なし・Microsoft Store を比べ、I1 を満たす方式を決める | — | 3〜5 日（署名の準備しだい） |
| 1 | **導入の完成。** 同梱、事前の確認（I4）、再実行と再開（I5）、初回の画面（§3.1）、状態と復帰の表示（R の導入・初回起動・更新）、アプリ内の更新 | local.21 | 1〜2 週間 |
| 2 | **認証とクラウド機能。** 中継サーバーの認証・申請と承認・管理ページ・上限・GPU の転送。ログイン画面と承認待ちの表示（R のログイン・承認待ち・GPU 推論） | local.22 | 約 1〜2 週間 |
| 3 | **研究室での PoC。** [§7.2](#72-実環境での受入) の E1〜E5 | — | 段階 2 の後 |

## 7. 完了条件

### 7.1 自動の試験（CI）

| ID | 条件 |
|---|---|
| T1 | インストーラー：Windows の CI で、無人導入 → 起動 → 作業画面 → 公開画像の解析 → 更新 → データの引き継ぎ（いまの 27 件の受入）。容量不足・途中で止めた後の再実行・更新の失敗で元の版が起動すること |
| T2 | 中継サーバー：コードの発行・照合・失効・試行回数の制限、未許可の宛先への非送信、申請と承認、取り消し後の拒否、利用者ごと・全体の上限、GPU の転送（Modal の代わりのテスト用サーバー）、画像と本文を保存しないこと |
| T3 | ローカル API とブラウザ：初回の画面、ログイン・ログアウト、承認待ちの表示と切り替え、ログインなしでのローカル解析、ログイン後の Cellpose と解析提案、上限・取り消し・GPU 起動中の表示 |
| T4 | 配布物・導入先・記録に、Modal と OpenAI の鍵がないこと |

### 7.2 実環境での受入

対象は、**初めて Cytellect を使う、IT に詳しくない研究者**。開発者は口頭で支援せず、横で見て記録するだけにする。手順書は渡さない。

| ID | 条件 |
|---|---|
| E1 | 段階 0：研究室の PC（Smart App Control が有効な PC を含む）で、セキュリティ設定を変えずに導入・起動できる |
| E2 | 次の 3 つの区切りを、それぞれ別に、所要時間・成功したか・支援を求めた回数として記録する。**導入の完了**（ダウンロードから「インストールが完了しました」まで）、**ローカル解析の開始**（練習画像で核の検出まで）、**クラウド利用の開始**（許可済みの利用者が、ログインから GPU の検出まで）。目標は、3 人以上で支援 0 回のまま 3 つとも完了すること。時間の目安は、ダウンロードの時間を除いて、導入 10 分以内、ローカル解析の開始 5 分以内、クラウド利用の開始 5 分以内（GPU の起動待ちを含む） |
| E3 | 異常の場面を試す：未許可のメールアドレス（申請 → 承認待ち → 承認 → ログイン）、メールが届かない（再送・宛先の修正）、インストールの途中で閉じて再開、ブラウザが開かない、更新の失敗。どの場面でも、利用者が支援なしで次の操作に進めること |
| E4 | オーナーが取り消すと、1 分以内に GPU と解析提案が止まり、ローカル解析は続けて使える |
| E5 | 0.1.0-local.20 から更新し、作業データが残る |

研究室の実画像での科学的な妥当性と、研究者による評価（C9・C10）は、この完了条件に含めない。E2 の後に続けて行う。

## 8. データ保護の変更点

- 検出に使う画像が Cloudflare Worker を通るようになる。Worker は転送するだけで、保存・記録しない。この点を[データ保護](../../security.md)に明記する。
- 中継サーバーに保存するのは、メールアドレス、端末トークンのハッシュ、申請と承認の記録、利用量だけ。
- 鍵は Worker の secret にだけ置く。端末トークンが漏れた場合は、管理ページで取り消す。

## 9. オーナーが決めること

| ID | 判断 | 案 |
|---|---|---|
| D1 | 独自ドメインとメールの送信方法 | **ドメインは `cytellect.app` に決定（2026-10-29、オーナー）。** Cloudflare Registrar で取得する（初年 8.20 ドル、更新 14.20 ドルの見込み）。送信は Resend（推奨、未決定） |
