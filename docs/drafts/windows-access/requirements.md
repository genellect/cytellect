# Windows 版のかんたん導入と利用者の認証：要件・実装案・完了条件（案）

作成：2026-10-29。状態：**オーナーの判断待ち**（[§8](#8-オーナーが決めること)）。承認後は、内容を[要件](../../requirements.md)、[Windows 版のインストール](../../install-windows.ja.md)、[クラウド GPU](../../cloud-gpu.ja.md)、[解析提案](../../proposal-service.md)、[データ保護](../../security.md)、[ロードマップ](../../roadmap.md)に反映する。

## 1. 目的と背景

研究室の Windows PC で PoC を進める。いまの Windows 版は、研究者が自分で導入して、すべての機能を使い始められる状態になっていない。

| 課題 | 現状（0.1.0-local.20） |
|---|---|
| 導入 | ZIP を保存し、短いパスに展開して `Cytellect Setup.cmd` を実行する。署名がないため「PC が保護されました」で「詳細情報 → 実行」を押す。初回は 8 つの取得先から約 1 GB を取得し、5〜20 分かかる。Smart App Control で止まった PC がある |
| GPU 推論 | 管理者が Modal の画面で接続用トークンを作り、ID と Secret をピリオドでつないで研究者に渡す。研究者はセットアップ画面に貼る。変えるにはセットアップをやり直す。最初の 1 視野は GPU の起動待ちで、画面に経過が出ない |
| 解析提案（LLM） | 管理者が管理用トークンで招待を発行し、研究者側で `POST /v1/devices` を送って端末用トークンを得て、環境変数に設定する。画面がなく、研究者には実質できない |

有料サービス（Modal の GPU、OpenAI）は、オーナーが許可した利用者だけが使えるようにする。誰でも使える状態にはしない。

## 2. 目標とする利用の流れ

**研究者（初回）**

1. 公開サイトの「ダウンロード」を押す。
2. ダウンロードした `Cytellect-Setup.exe` を開く。作業画面が自動で開く。
3. 作業画面の「ログイン」にメールアドレスを入れ、届いた 6 桁のコードを入れる。

これで、核の検出・測定・統計・図に加えて、GPU 推論と解析提案を追加の設定なしで使える。2 回目以降は、ショートカットを開くだけで使える（ログインは保持される）。

**オーナー**

- 管理ページで、研究者のメールアドレスを許可する。または、研究者の「利用を申請」に届いたメールの「承認」を押す。
- 管理ページで、利用者ごとの利用量の確認と、許可の取り消しを行う。

## 3. 要件

### 3.1 導入（I）

| ID | 要件 |
|---|---|
| I1 | 配布物は `.exe` 1 つ。管理者権限、コマンド、展開、パスの選択を求めない（インストール先は `%LOCALAPPDATA%\Cytellect`） |
| I2 | 解析に必要な Python・ライブラリ・Fiji を同梱し、初回の外部取得をなくす。外部への通信は、ログイン・GPU 推論・解析提案・更新の確認だけにする |
| I3 | 導入が終わると、作業画面がブラウザで開き、デスクトップとスタートメニューにショートカットができる |
| I4 | 更新は作業画面の「更新があります」から 1 回の操作で行い、研究データと設定を引き継ぐ。0.1.0-local.20 以前の保存先からも引き継ぐ |
| I5 | アンインストールは Windows の「アプリ」から行える。研究データを消すかは確認してから決める |
| I6 | コード署名をする場合、「PC が保護されました」と Smart App Control の警告が出ないこと。署名しない場合は、警告が出たときの操作を画面で案内する（[§8](#8-オーナーが決めること) D4） |

### 3.2 認証と許可（A）

| ID | 要件 |
|---|---|
| A1 | ログインはメールアドレスと 6 桁のコードで行う。パスワードは使わない |
| A2 | オーナーが許可したメールアドレスだけがログインできる。許可のないアドレスには、コードを送らず「利用を申請」を案内する |
| A3 | 申請はオーナーにメールで届き、メールの「承認」から 1 回の操作で許可できる。承認すると、研究者に「利用できるようになりました」と届く |
| A4 | ログインは端末ごとに保持し、90 日使わなければ失効する（[§8](#8-オーナーが決めること) D3）。研究者は作業画面からログアウトできる |
| A5 | オーナーが許可を取り消すと、1 分以内にその利用者のすべての端末で GPU と解析提案が使えなくなる。核の検出・測定・統計・図は、ログインなしでも使える |
| A6 | 管理ページはオーナーだけが開ける（オーナーのメールアドレスでの同じコード認証） |

### 3.3 GPU 推論と解析提案（C）

| ID | 要件 |
|---|---|
| C1 | ログインした端末は、追加の設定なしで GPU 推論と解析提案を使える。接続先・接続キーの入力はなくす |
| C2 | Modal と OpenAI の鍵は中継サーバー（Cloudflare Worker）だけが持ち、PC・配布物・ログに置かない |
| C3 | 利用者ごとに月の上限（GPU の秒数、解析提案の費用）を設け、全体の月額上限も設ける。上限に達したら、理由と再開の時期を画面に示す。Modal の Spend limit 0 ドルは維持する |
| C4 | Cellpose を選んだ時点で GPU の起動を始め、起動中は「GPU を起動しています」と経過を表示する。503 は決めた時間まで自動で再試行する |
| C5 | 送るデータは今と同じ（検出に使う 1 チャンネル、核のマスク、検出条件）。中継サーバーは画像と結果を保存・記録しない |
| C6 | GPU の結果は、今と同じく runner・モデル・依存パッケージのハッシュを照合し、記録に GPU の種類を残す |

## 4. 実装案

### 4.1 構成

```
研究者の PC（Cytellect）
  ├─ ローカル解析（Fiji、測定、統計、図）……ログイン不要
  └─ 端末トークン ──HTTPS──▶ Cloudflare Worker（既存の解析提案の中継を拡張）
                                 ├─ 認証：メールのコード、許可リスト、端末トークン、管理ページ
                                 ├─ 上限：利用者ごと・全体の月額
                                 ├─ /v1/cellpose/* ──鍵を付けて転送──▶ Modal（GPU）
                                 └─ /v1/proposals ──────────────────▶ OpenAI
メール送信サービス ◀── コード・申請・承認のメール
```

### 4.2 中継サーバー（`services/proposal-worker` を拡張）

- **データ**（D1）：`users`（メールアドレスの正規化した値、状態 `pending`／`allowed`／`revoked`、月の上限）、`login_codes`（コードのハッシュ、期限 10 分、試行回数）、`devices` に利用者を結びつける、`gpu_usage`（利用者・月・秒数）。画像・目的の文・結果は保存しない。
- **認証の API**：`POST /v1/auth/code`（メールアドレス → 許可済みならコードを送る、なければ申請を受け付ける）、`POST /v1/auth/verify`（コード → 端末トークン）、`POST /v1/auth/logout`。コードは 6 桁、10 分で失効、5 回の誤りで無効。メールアドレスと IP ごとに送信回数を制限する。
- **管理ページ**：`/admin`。オーナーのメールアドレスでログインし、許可・取り消し・上限・利用量を操作する。承認メールのリンクは、1 回だけ使える署名付きの URL にする。
- **GPU の転送**：`/v1/cellpose/health` と推論の要求を、端末トークンと上限を確かめてから、Worker が持つ Modal の接続キーを付けて Modal に転送する。応答の受け渡しにかかった秒数を利用量に加える。
- **既存の招待方式**（`/v1/admin/invitations`）は、移行期間の後に外す。

### 4.3 Windows 版

- **ログイン画面**：作業画面の右上に「ログイン」。メールアドレスとコードの 2 段階。ログイン中は、アドレスと「GPU・解析提案：利用可」を表示する。
- **ローカル API**：`/v1/account/*` を追加し、端末トークンを保存先の設定ファイル（その利用者だけが読める権限）に置く。Cellpose と解析提案の接続先は、配布物に組み込んだ Worker の URL に固定する。
- **GPU の待ち**：Cellpose を選んだ時点で `/v1/cellpose/health` を呼び、起動中の表示と自動の再試行を行う（C4）。
- **インストーラー**：Inno Setup で、利用者単位の `.exe` を作る（`PrivilegesRequired=lowest`）。Python・ライブラリ・Fiji は CI で用意して同梱し、ハッシュを照合する。いまの `local-release.yml` の受入（新規導入・更新・ブラウザ試験・数値の再現）を、`.exe` に置き換えて続ける。
- **更新**：起動時に GitHub の最新リリースを確かめ、作業画面で「更新があります」を示す。押すと新しい `.exe` を取得し、ハッシュを確かめてから上書き導入する。

### 4.4 メール送信

送信サービスの選択（[§8](#8-オーナーが決めること) D1）が必要。

| 案 | 費用 | 注意 |
|---|---|---|
| Resend（独自ドメイン） | 無料枠は月 3,000 通・1 日 100 通。ドメインは年 1,500〜2,000 円程度（未確認） | ドメインの取得と DNS の設定が要る。将来の SaaS でも使える |
| Firebase Authentication のメールリンク | 無料枠で足りる見込み（未確認） | ドメインは不要。コードではなくリンクでのログインになり、PC と別の端末でメールを開くと使えない |

## 5. 段階と目安

| 段階 | 内容 | 版 | 目安 |
|---|---|---|---|
| 0 | 判断（[§8](#8-オーナーが決めること)）と、最初の検証：Worker 経由の GPU 推論（約 5 MB の画像、推論 50 秒）が通るか、メールが届くか | — | 1〜2 日 |
| 1 | 中継サーバーの認証・許可・管理ページ・上限・GPU の転送。Windows 版のログイン画面と GPU の待ちの表示。配布は今の ZIP のまま | local.21 | 約 1 週間 |
| 2 | `.exe` のインストーラー、同梱、アプリ内の更新、（決めた場合は）署名 | local.22 | 1〜2 週間 |
| 3 | 研究室の PC 2〜3 台での PoC（[§6](#6-完了条件) の E1〜E3） | — | 段階 2 の後 |

段階 1 だけで、GPU と解析提案の設定作業はなくなる。段階 2 で導入の手順が 3 つになる。

## 6. 完了条件

### 6.1 自動の試験（CI）

| ID | 条件 |
|---|---|
| T1 | 中継サーバー：コードの発行・照合・失効・試行回数の制限、許可のない宛先への非送信、申請と承認、取り消し後の拒否、利用者ごと・全体の上限、GPU の転送（Modal の代わりのテスト用サーバー）、画像と本文を保存しないこと |
| T2 | ローカル API とブラウザ：ログイン・ログアウト、ログインなしでのローカル解析、ログイン後の Cellpose と解析提案、上限・取り消し・GPU 起動中の表示 |
| T3 | Windows の CI で、`.exe` の無人導入 → 起動 → 作業画面 → 公開画像の解析 → 更新 → データの引き継ぎ（いまの 27 件の受入を `.exe` で通す） |
| T4 | 配布物・導入先・記録に、Modal と OpenAI の鍵がないこと |

### 6.2 実環境での受入

| ID | 条件 |
|---|---|
| E1 | 未導入の Windows 11 PC で、ダウンロード → `.exe` → ログイン → 公開画像（BBBC013）で GPU の検出 → 解析提案 → 図の書き出しまでを、コマンド入力・管理者権限・接続先の入力なしで、15 分以内に終える |
| E2 | 許可のないメールアドレスではコードが届かず、オーナーが承認した後にログインできる。オーナーが取り消すと、1 分以内に GPU と解析提案が止まり、ローカル解析は続けて使える |
| E3 | 研究室の PC 2〜3 台で E1 を通し、研究者が手順書を見ずに完了できる。詰まった箇所を記録する |
| E4 | 0.1.0-local.20 から更新し、作業データが残る |

研究室の実画像での科学的な妥当性と、研究者による評価（C9・C10）は、この完了条件に含めない。E3 の後に続けて行う。

## 7. データ保護の変更点

- 検出に使う画像が Cloudflare Worker を通るようになる。Worker は転送するだけで、保存・記録しない。この点を[データ保護](../../security.md)に明記する。
- 中継サーバーに保存するのは、メールアドレス、端末トークンのハッシュ、利用量だけ。
- 鍵は Worker の secret にだけ置く。端末トークンが漏れた場合は、管理ページで取り消す。

## 8. オーナーが決めること

| ID | 判断 | 案 |
|---|---|---|
| D1 | メールの送信方法 | Resend と独自ドメイン（推奨）、または Firebase のメールリンク |
| D2 | 利用者ごとの月の上限と全体の上限 | 例：GPU は 1 人あたり月 60 分、解析提案は 1 人あたり月 5 ドル、全体は Modal の無料枠（月 30 ドル）と解析提案の月額上限の範囲 |
| D3 | ログインの保持期間 | 90 日使わなければ失効 |
| D4 | コード署名（有料） | Microsoft の Artifact Signing は日本から使えない可能性がある（未確認）。その場合は認証局の証明書、または署名なしで警告の操作を案内する |
| D5 | 許可の方法 | オーナーの事前登録と、研究者の申請 → オーナーの承認の両方 |
