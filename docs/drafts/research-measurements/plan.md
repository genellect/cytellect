# 研究パラメータの拡張計画

状態：Claude の設計レビューを反映し、2026-11-09 にオーナーが §8 の 4 方針を採用した計画。分担は §9 の機能ごとの縦割りで確定し、M1 の核ごとの統合表（`nucleus-table/1.0.0`）から実装を始めた。ほかの契約は各機能の最初の PR で固定する。承認済みの要件・Methods・受入条件を、この文書だけで置き換えない。新規学習・既定モデル変更は未開始。未公開の画像・資料名・構成・ファイルパス・測定値・研究結果はこの文書に含めない。

## 1. プロダクトの方向

Cytellect は、生命科学研究者が、研究で必要なパラメータを定義に沿って計算し、元の画像で確認・修正して、統計と編集可能な論文の図まで進められる解析基盤を目指す。現行の方針は [開発の原則](../../development-principles.md) と [研究ワークフロー](../../research-workflow.md) に従う。

この拡張で最優先するのは、研究で必要なのに現在不足している測定の実装である。速度・UI・追加学習は、その測定を正しく、少ない修正で利用できるようにするために改善する。必要な指標や科学的な確認を省いて解析時間だけを短縮しない。

最初の研究領域は核小体と核内構造とする。「同じ核の形態と状態」「定義用マーカーと測定分子の分離」「複数の区画」を共通解析パッケージで扱い、他の蛍光対象にも利用できる設計にする。領域間関係と profile は解像の確認を経て加える。近いうちの画像以外の範囲は、検証済み数値表を試料・実験回で関連付ける機能に限る。特定の研究の実験一覧を指標 registry に移さない。

研究者の入口は「どの区画にどれだけあるか」「状態別に形態がどう異なるか」「内部構造の配置が変わるか」といった問いにする。画像、採用した領域、測定表、実験回の比較、図を同じワークスペースで結び付ける。外部の数値表は実際の対応単位を示し、画像への対応がない行に画像へのリンクを作らない。専門的な設定は確認できる形で保持する。

計算は `packages/analysis` の共通実装が担う。ローカル版と将来のホスト型解析で別の測定式を作らない。将来の Web アプリ化の方針を維持しつつ、非公開の教師・評価データとそれに由来する重みは、別途許可するまでローカルだけで扱う。コードの公開と研究データの公開は別の判断である。

## 2. 現行機能との差

基準はこのブランチの分岐元にある [要件](../../requirements.md)、[Methods](../../methods.md)、実装ソース。保存済みレシピの意味は保持する。

| 分野 | 既存の基盤 | 今回必要な拡張 |
|---|---|---|
| 領域の定量 | 核・核小体和集合・核質、任意領域の面積・輝度、手修正、元画素座標 | 複数のマーカー定義領域を保持し、任意の測定チャンネルとの測定行列を計算 |
| 局在 | NCL の核質／核小体比、区画 summary | 任意分子の分配係数・積算量の分配と、原値／補正値を下流まで一貫して扱う契約 |
| 核小体の形態 | 個数・面積・占有率・離心率の経路 | 最大物体割合、他の形状指標、区画ごとの数・面積と研究出力 |
| 空間構造 | 採用済みマスクと親核の対応 | foci の数・密度、領域間距離・重なり、line／radial profile |
| 陽性判定と分類 | チャンネル ID、手動／Otsu、原値／補正値、陽性／陰性を持つ既存 GFP ゲートと、陽性率の計算契約 | チャンネルに依存しない新版へ一般化し、同じ判定記録から層別と陽性率を接続 |
| 核ごとの統合 | 核・子領域の ID と各測定 | 核小体の形態、核面積、DNA 染色の積算、任意チャンネル強度を同一核の表へ接続 |
| 実験計画 | `experiment_design.py` は `single`／`pair`、最大 2 群。下流の比較契約は最大 30 条件と多群の検定経路を持つ | 入力・保存・比較の接続と因子・層の扱いを M0 で決める。多群の契約があることを多因子解析の完成としない |
| 外部測定 | 既測定値の数値取込 | 検証済み数値表を、同一細胞／試料／実験回という対応単位と出典行で関連付ける |
| 検出と学習 | 固定 StarDist、Cellpose-SAM、採用済みマスク | 測定対象別の教師・独立評価と、必要指標の誤差・修正負担によるモデル採用 |

計算契約が存在すること、画面から利用できること、保存・統計・出力・replay がつながること、科学的な受入を満たすことを別に記録する。たとえば比較 UI の `comparison-adapter.ts` は陽性率を未接続と記載している。自動背景による補正 summary にも比較・出力側の制限がある。既存の式を重複実装する前に、このような未接続を確定する。

## 3. 対象の定義

核小体全体、GC・DFC・FC 関連領域、NCL 陽性領域、光学的に解像できる foci は別の対象とする。NPM1・DKC1・RPA194 などの区画対応には一次文献の根拠があるが、マーカーの陽性画素が全条件で構造の真の境界を示すとは仮定しない [1–4]。核小体の区画は相分離した複数の液相として振る舞い、条件で組成と境界が変わりうる [14, 15]。

- 定義用マーカーと測定する分子を分離する。再分布を測る分子自身で領域を定義する場合は、その依存関係を保存・表示する [4]。
- 「陽性画素の集合」と「外周で囲んだ構造」を区別する。穴埋めや円形化で両者を混ぜない。
- 異なるマーカーの領域間では重なりを許す。各区画を一枚の排他的なラベル画像に押し込めない。
- 親核との対応を保持する。GC 関連領域から外へ移った FC／DFC 関連候補を黙って切り捨てない。
- 対応不能、判読不能、検出ゼロ、処理失敗、測定しなかった場合を区別する。個数が決まらない融合領域へ推定個数を割り当てない。
- DAPI の低輝度域、独立マーカー、研究者の判読を照合できるようにする。手法の変更は別 revision とし、都合のよい結論を得るために選択しない。

## 4. 計算するパラメータ

以下は指標の候補と定義。採否と最初に提供する範囲はレビューで固定する。N は親核、R は採用した対象領域、B は比較する参照領域、c は測定チャンネル、I は原画素、b はそのチャンネルの背景、sx・sy は確認済みの画素寸法を表す。

### 4.1 区画別測定と局在

| 指標 | 定義 | 単位・成立条件 |
|---|---|---|
| 面積 | 画素数 × sx × sy | µm²。未校正なら px² |
| 個数・サイズ分布 | 親核に対応した、個別に判別できる物体 | 物体表と親核ごとの集約を両方保持 |
| 形状 | 周長、円形度 4πA／P²、solidity A／凸包面積、長短軸比 | 境界の推定法・校正・端切れを固定。2D 形状を体積や球形度へ読み替えない |
| 面積占有率・最大物体割合 | 対象面積／親核面積、最大物体面積／対象和集合面積 | 分母と対象定義を固定。空・未確定は区別 |
| 平均・中央値・総量 | mean(Ic \| R)、median(Ic \| R)、Σ(Ic \| R) | 原値と補正値は別。補正は測定用背景に従う |
| 補正積算 | ΣIp − 画素数 × b | 負値を勝手にゼロへ切り詰めない |
| 分配係数 | Kc,R,B = mean(Ic−bc \| R) / mean(Ic−bc \| B) | 同じ分子の対象／参照。両平均が正の場合。逆向きの既存比と区別 |
| 区画内信号分配 | Σ(Ic−bc \| R) / Σ(Ic−bc \| N) | 背景・分母の妥当性が必要。signed 補正値の比を自動で物理的な 0–1 割合としない |
| 区画間の面積比 | 全対象の面積比、内側の交差面積、外側にある面積を別に保存 | 分配・移動による境界外の対象を消さない |
| 核内陽性率 | 陽性核／判定可能核 | 陰性対照と判定規則、判定不能の分母を記録 |

M1 の核ごとの統合表は、ワークスペース・視野・核マスク revision・核 ID で対応させる。子領域は記録した親核へ結び付け、行順や近い位置で結合しない。核小体の絶対面積・核面積で正規化した面積割合・個数と、核面積、DNA 染色（DAPI 等）の原値／補正積算、任意チャンネルの原値／補正強度を同じ核の行で確認できるようにする。変更後のマスクと旧測定を混在させない。

DNA 染色の積算は、染色・線形範囲・飽和・撮影条件が確認できる場合の相対 DNA 信号として扱う。校正なしに DNA 量や倍数性を確定しない。核面積・DNA 信号は分布と関連の確認に必須だが、すべての測定を自動的にそれらで割ったり、正規化後だけを残したりしない。対象・分母の科学的な意味を保持する。

核質を参照 B にする場合は、親核から採用した核小体全体の和集合を除く。FC・DFC の一領域 R だけを除いた N∖R は、他の核小体区画を含むため核質とは呼ばない。区画間の比では対象・参照の両方を明示する。

複数の核小体の平均は和集合の全画素から計算し、各物体平均の単純平均にしない。異なる抗体・蛍光体のチャンネル間輝度比を、校正なしに分子数比や酵素／基質比と呼ばない [16]。絶対面積と占有率、平均と総量は別の問いとして出す。

### 4.2 任意チャンネルの陽性判定と分類

`gfp_selection.py` と既存の gate 計算・ID 対応・欠測処理を再利用する。一般化では、契約と保存結果のチャンネル名・ラベル・stain、Methods、警告、図の説明をそろえて新版にする。別染色を `gfp_channel_id` として受け渡す暫定実装や、Methods を GFP としたままの利用は行わない。旧 GFP レシピとその replay は従来の意味で保持し、黙って新版へ変換しない。

- 手動・対照に基づく判定・Otsu の適用範囲を区別し、対照のない探索的分類を生物学的な陽性判定の確立としない。
- 同じ判定記録（チャンネル、値の種類、対象、対照、日付別閾値、比較演算、版）を、陽性／陰性の選択と陽性率へ使う。
- 閾値の規則は結果を見る前に（陰性対照などから）決め、比べる群のすべてに同じ規則を当てる。画像ごとの Otsu は探索用で、条件間の陽性率の比較には使わない。日付別の閾値は、同じ日の対照から同じ規則で決める場合に限る。
- 陽性／陰性は核の分類で、§5 の層（試料・時点などで分けた視野の単位）とは別の概念として扱う。同じ視野の陽性核と陰性核を独立した群として比べない。判定に使ったチャンネルを、分類した核の結果として測る場合は、選別による循環（同じ値で選んで同じ値を比べる）を Methods に明記する。
- 陽性率はゲートで選別する前の評価対象から `陽性 / (陽性 + 陰性)` を計算する。判定不能・対照・除外の数と理由を併記し、陽性だけに絞った後の分母から計算しない。
- 補正値が欠ける場合は原値へ置き換えず、未分類を陰性にしない。選ばれなかった核も台帳に残す。
- 核・視野・試料・独立単位のどこで集約するかを固定し、比較、図、Methods、CSV、保存・replay まで接続する。

### 4.3 区画の関係と profile（M2 の条件付き範囲）

| 指標 | 計算・出力 | 注意点 |
|---|---|---|
| foci 数・密度 | 対応する親領域ごとの数、親領域面積あたりの数 | 解像可能な foci に限定。転写単位数・rDNA コピー数へ読み替えない |
| 重なり・包含 | 対象方向ごとの面積・信号・個数の割合 | 方向、閾値、分母を明示 |
| 距離 | 中心間、最近接、境界までの符号付き距離 | 校正、中心定義、色ずれ、対応不能を保存 |
| line profile | 指定帯域内の原画素のチャンネル別信号と位置 | 線、幅、単位、背景、端切れを保存 |
| radial profile | 採用した中心からの距離 bin 別平均と画素数 | 中心、角度、bin 幅、正規化、欠測を保存 |
| peak 位置差・FWHM 等 | 解像可能な profile の形状を要約 | 光学分解能や投影の限界を超える厚さ・nm 精度を主張しない |
| 共局在 | 指定 ROI 内の Pearson、方向別 Manders 等 | 結合の証明にはしない。配置の違いを一値へ先に潰さない [5] |

多角度の profile とピーク間距離には一次研究の実例がある [2,3]。その測定条件を、異なる光学系や表示画像へ無条件に移植しない。

M2 の開始前に、元画像の軸・画素寸法・対物レンズ・NA・取得／処理条件を確認し、測る構造を原像で分離・同定できることを研究者が確認する。画素寸法や NA だけで解像を保証しない。表示 RGB や拡大パネルだけを FC／DFC 境界の正解にしない。確認できない対象の foci 数・厚さは提供せず、判読可能な領域の面積等へ範囲を限定する。公開画像でも同じ開始条件を満たす必要がある。

### 4.4 検証済み数値表との関連付け（M3）

近いうちの範囲は、既存の数値取込を用い、値・単位・正規化・試料・独立した実験回・条件・時点・元表の行 ID と hash を保持して、画像測定と並べる一機能に限る。対象・測定物質の同定が未確認なら、専用指標を作らない。試薬として使った物質は実験因子、測定標識はチャンネルとして記録し、略語や表示色から決めない。

同一細胞の直接対応、同一試料、同じ条件の別試料を区別する。たとえば明視野の発色測定と別ウェルの蛍光像は試料単位にとどめ、同一細胞の連続撮影・位置登録・ID が証明できる場合だけ同じ細胞の表へ結合する。バルク値を各細胞へ複製して n や関連を増やさない。入力が数値表だけなら戻り先は元表と試料記録であり、存在しない画像リンクを作らない。

FRAP fit・回復指標、バンド専用の比・AUC・反応速度、ゲル／WB の画像解析器は後続候補で、この計画の近いうちの実装から外す [6–8]。別計画では利用者の必要性、実時間・個体／平均・補正・反復・原画像等の入力、同定可能性、受入を確定する。式の演算照合は開発原則に合う最小の数値配列で行い、非公開のグラフ値を開発用 fixture や CI の根拠にしない。

## 5. 共通計算の構成案

新しい API 名・schema はレビュー後に決める。任意式を実行する仕組みは入れず、登録した計算とその版を使う。

指標 registry には、再利用できる画像測定の意味・入力・出力を登録する。試薬名・実験名・外部ファイルの一覧を指標 ID にしない。専用解析を増やす前に、複数の利用場面、既存計算で足りない理由、公開の検証先を確認する。

| 構成 | 保存・計算するもの | 所有箇所の案 |
|---|---|---|
| RegionSet の意味 | 定義マーカー、陽性画素／外周、親核、原座標、マスク hash、2D 断面／投影 | 既存領域契約を互換に拡張 |
| 区画とチャンネルの測定行列 | 採用領域 × 測定分子の原値・補正値、局在比 | 共通解析パッケージ |
| チャンネルに依存しない gate | 同じ判定規則と台帳から陽性／陰性の分類・陽性率、チャンネル名を含む Methods | 既存 GFP 計算を再利用する新版契約と共通解析 |
| 核ごとの統合表 | 核・親子・測定 revision の ID、形態、核面積、DNA 信号、各チャンネル強度 | 共通解析・保存・表・図 |
| 実験計画と層 | 試料属性・条件・時点、独立単位、対応、層と計画 ID | 実験計画 1.1.0 の版付きの層（因子・水準・層・各視野の所属）と、1 層だけを持つ集合（[Methods](../../methods.md#experiment-design-110-declared-strata-2026-11-09)） |
| RelationSpec | 対象、方向、包含・重なり・距離、対応規則 | 共通解析パッケージの新しい版付き契約 |
| ProfileSpec | 線／中心、帯域、距離 bin、角度、背景、正規化 | 共通解析と保存形状 |
| 外部測定の関連付け | 既存数値取込の値・単位・元表行、試料／細胞の対応、実験回、時点 | 既存取込を使う版付き関連契約。専用曲線計算は含めない |
| MetricSpec | 研究上の意味、式、必要入力、単位、成立条件、欠測理由、集約、文献 | 許可した指標の registry |
| 結果の接続 | selector、個体表、実験単位集約、統計、図、Methods、CSV、replay | API・contracts・Web・exports |

検出と計算を分離する。新しい自動検出の完成を待たず、採用済みの手描き・取込・修正マスクから研究指標を計算できるようにする。既存の核検出、親子関係、原画素の保持、版管理を使う。

原画像、表示、検出前処理、測定を分ける。核小体編集は依存する和集合・核質・測定へ、背景変更は補正値へ、実験 metadata 変更は集約・統計へ、色と軸の変更は図へ反映する。保存済みの旧レシピを新式へ黙って変換しない。

M1 は現行の 4 チャンネル上限内で設計する。上限拡張はこの範囲へ含めず、必要な利用場面が確認できたときに別途扱う。別染色を GFP／NCL として扱ったり、別細胞を同一細胞として結合したりして制限を迂回しない。

層別の 2 群比較から開始する。ここでいう層は、研究者が宣言した視野の単位（試料属性・時点など）で、§4.2 の陽性／陰性の分類とは別である。試料属性・時点等を明示した層ごとに比較対象と実験計画を分け、層・計画 ID、独立単位、同じ実験回や試料の対応を保持する。層をまたいだ自動合算、独立 n の水増し、層の差を因子の効果や交互作用として検定することはしない。保存は、版付きの層 metadata を実験計画に加える案（実験計画 1.1.0）に固定した。集合は保存した計画の hash に結び付いた 1 層だけを持ち、層のない集合・層をまたぐ元・計画が変わった後の集合を、API と共通解析が記述・比較で拒否する。多群・多因子を選ぶ場合は既存の比較処理を再利用できる範囲を確認し、入力・保存・統計・図の別の受入範囲を先に決める。

## 6. 学習データの利用

運用の境界とローカルの配置仕様は [ローカル研究データの利用](local-data.md) にまとめる。公開コード・公開実画像と、研究室内の非公開データを分離する。

最初に行うのは、研究者によるローカルでの原画像の棚卸しと、独立評価に使う実験回の確保（M4a）。原チャンネル、取得条件、元視野と派生、試料・実験回、既に開発に使った範囲を確認する。この作業は公開実画像での M1 開発と並行して進める。表示画像の保管や抽出だけで M4b の学習を始めず、原画像と用途に合う正解・split・loader の採用条件がそろってから接続する。

- マーカー定義領域、個々の核小体、DFC 関連領域、FC 関連 foci、全細胞外周を同じ正解へ混ぜない。
- 既存の閾値陽性領域は、その陽性領域定義の参照であり、構造全体のインスタンス正解ではない。
- 表示 RGB は出所と処理条件を持つ別ドメインとして扱い、未加工の単色蛍光原像へ読み替えない。
- crop 内を漏れなく注釈する。判断不能を背景へ落とさず、標準学習が ignore を扱えるとは仮定しない。
- 核小体関連インスタンスの基準は現行 Cellpose-SAM とする。点状候補や ring のすべてに同じモデルを強制せず、古典的候補検出と profile も比較する。
- train／development／final は実験・試料・撮影系列・同一視野の派生を共有しないように分離する。開発に使った資料を未知の最終試験へ戻さない。
- 重み、データ、対象定義、前後処理、推論条件を組にして版管理する。公開済み基盤モデルの既学習データとの重複も記録する。

Cellpose の公式開始例は AdamW、learning rate 1e-5、weight decay 0.1、batch 1、100 epochs。最適値として採用せず、固定版の実装と development で決める [9,10]。既定の `min_train_masks=5` は少数物体の親核 crop を学習から除くため、採用・除外一覧と設定を確認する。新たな教師を繰り返し既存 checkpoint だけへ追加し、過去データの重みを意図せず変える運用にしない。

## 7. 検証と受入

数学的な正しさ、対象の同定、測定誤差、研究者の作業完了を別に評価する [11,12]。

公開実画像の最初の検証先は、既に登録された Schmidt ら 2022 の **DS6a 5-EU Pulse（Zenodo 6643470、CC BY 4.0）** とする [17]。[登録済みデモの定義](../../../services/showcase/datasets/zenodo-6643470-nucleolar.json)は、核染色・NPM1・5-EU の 3 チャンネルを選択している。これを使って、定義マーカーと測定分子の分離、区画平均・積算・分配、核ごとの対応と表から画像への導線を確認する。新しい演算・比較は別の版として記録し、既存デモの計算定義や結果を黙って変えない。

FBL の DFC 関連領域を使う M2 の検証は、元 TIFF の軸・チャンネル数・順序・染色対応と、解像可能な対象の確認が済んでから行う。[群間比較の要件](../group-comparison/requirements.md)にある「4 チャンネル」の推定を、その確認の代わりにしない。必要チャンネルが選択済みデモにあるとは仮定せず、元の公開画像から適切な取得・登録・hash・校正を持つ別の検証版を用意する。

DS6a は既に開発とデモに使っており、未知の最終評価ではない。実験回の独立性も未確認なので、推測統計は行わず記述と演算照合に限る。任意チャンネル gate の接続を確認できても、別の染色の生物学的な陽性判定や分割精度の証明にはならない。対照による判定の受入には、該当する対照と条件が確認できる公開実画像を別に確保する。

層内比較と統計の経路は、DS6a では接続（記述・演算照合・合算の拒否）の確認にとどめる。推測統計の受入には、独立した実験回を出典で確認できる公開データを別に登録してから使う。対照付きの陽性判定の受入も、陰性対照を含む公開データを登録してから行う。どちらも未登録のあいだは、受入済みと扱わない。

1. **計算**：公開実画像と独立した Fiji 等の参照で原画素・領域・profile を照合する。式だけの検証は開発原則で許容される最小数値を使い、合成細胞像を精度の根拠にしない。
2. **対象の同定**：独立注釈と裁定を用い、precision／recall／F1、IoU、過分割・融合、親子の誤り、判断不能率を記録する。
3. **研究測定**：個数・面積・輝度・分配・陽性率と、開始条件を満たした profile の誤差を条件別・実験回別に測る。核面積・DNA 信号を同じ核の参照として保持する。文献と同じ p 値や方向を得る調整はしない。
4. **統計**：細胞・視野・試料・独立処理単位を区別し、欠測・除外・対応を保持する。独立性不明なら記述にとどめる [13]。
5. **接続**：必要入力から計算、比較、図、Methods、保存・replay まで成立する。画像由来の値は正しい元画像・領域へ、外部表の値は元表の行・試料記録へ戻れる。明視野と別ウェルの蛍光像等で同一細胞の対応が証明できない場合、核ごとの結合を拒否することを受入条件に含める。
6. **研究者評価**：通常の手法と同じ範囲の課題で、完了・誤判断・援助・修正負担・総時間を測る。推論速度や agent の試験で代用しない。

許容誤差・目標精度・対象条件・評価集合・checkpoint 選択の方法は final を見る前に固定する。目標値は注釈のばらつきと検出したい生物学的差から決める。既定モデル変更や公開は、この受入とは別にオーナーが判断する。

## 9. Claude レビューと並行実装

レビューでは次を判定する。

- 必要な研究パラメータが不足していないか。単なる指標追加でなく、研究上の問いへ対応しているか。
- 式、領域の意味、マーカー、単位、分母、背景、時間、欠測、集約が整合するか。
- 既存コードを再利用できる箇所と、未接続・新設する箇所が分かれているか。
- 原画素と旧レシピを保持し、新版 gate の名前・文言を含め API・型・保存・図・Methods・replay まで変更範囲がそろっているか。
- 実験計画の入口と既存の多群比較の差、層・独立単位・対応の保存、核面積・DNA 信号を含む同一核の表が定義されているか。
- ローカルデータをクラウド開発、公開 CI、Docker build context、デモ、外部 AI（隔離ローカル環境の指定した AI と送信先を除く）へ送る経路が生じないか。
- 公開実画像で採用した領域から計算する M1 と、原画像棚卸し・独立評価構築の M4a が並行し、学習を待たずに進められるか。
- M2 の解像確認、M3 の数値表への限定、専用解析の別計画化が守られているか。
- 並行作業で同じファイル・共有契約を競合して変更しないか。

Claude は問題点を重要度、根拠となる節・コード、修正案、判断が必要な事項に分けて返す。公開する場合は一般化した設計事項だけを使い、非公開資料やその背景・構成を添付しない。§8 の採用方針に従って M0 で共有契約と所有ファイルを固定し、その後に並行実装へ進む。追加学習は M4b の採用条件も満たす必要がある。

分担は機能ごとの縦割りとし、各担当が計算から API・保存・画面まで一貫して持つ（2026-11-09 に確定）。担当範囲は worktree とブランチを分けて進める。

`packages/contracts/openapi.json` と `apps/web/src/lib/generated.ts` は手編集せず生成し、後からマージする側が最新 `main` を取り込んで生成し直す。契約の追加は各機能の新しいモジュール・新しい版として加え、既存レシピの意味と replay を変えない。

隔離ローカル環境は、2026-11-09 のオーナーの判断で、非公開データを開発用 AI が扱ってよい例外とした。条件は [ローカル研究データの利用](local-data.md#隔離ローカル環境での-ai-の利用) にある。

実装 PR は、計算と薄い UI を一つずつつなぐ形で M1 から進める。二者が全機能を別々に実装して最後に結合する進め方にはしない。各担当の変更は他方が独立にレビューする。マージ・配備・配布は [チーム開発ルール](../../team-development.md) に従う。
