# 研究パラメータの拡張計画

状態：Claude による設計レビュー待ち。実装済み機能の説明や、既存の受入条件の置換ではない。レビュー後に計算契約と作業範囲を固定し、Codex と Claude の並行実装へ進む。未公開の画像・資料名・ファイルパス・測定値・研究結果はこの文書に含めない。

## 1. プロダクトの方向

Cytellect は、生命科学研究者が、研究で必要なパラメータを定義に沿って計算し、元の画像で確認・修正して、統計と編集可能な論文の図まで進められる解析基盤を目指す。現行の方針は [開発の原則](../../development-principles.md) と [研究ワークフロー](../../research-workflow.md) に従う。

この拡張で最優先するのは、研究で必要なのに現在不足している測定の実装である。速度・UI・追加学習は、その測定を正しく、少ない修正で利用できるようにするために改善する。必要な指標や科学的な確認を省いて解析時間だけを短縮しない。

最初の研究領域は核小体と核内構造とする。核小体研究に必要な「複数の区画」「区画同士の関係」「時間曲線」の計算を共通解析パッケージへ足し、他の蛍光対象にも利用できる設計にする。特定の研究の群名・薬剤・処理日・結論をコードへ埋め込まない。

研究者の入口は「どの区画にどれだけあるか」「内部構造の配置が変わるか」「回復の速さと回復量が変わるか」「前駆体が蓄積するか」といった問いにする。画像、採用した領域、profile・曲線、測定表、実験回の比較、図を同じワークスペースで結び付ける。専門的な設定は確認できる形で保持する。

計算は `packages/analysis` の共通実装が担う。ローカル版と将来のホスト型解析で別の測定式を作らない。将来の Web アプリ化の方針を維持しつつ、非公開の教師・評価データとそれに由来する重みは、別途許可するまでローカルだけで扱う。コードの公開と研究データの公開は別の判断である。

## 2. 現行機能との差

基準はこのブランチの分岐元にある [要件](../../requirements.md)、[Methods](../../methods.md)、実装ソース。保存済みレシピの意味は保持する。

| 分野 | 既存の基盤 | 今回必要な拡張 |
|---|---|---|
| 領域の定量 | 核・核小体和集合・核質、任意領域の面積・輝度、手修正、元画素座標 | 複数のマーカー定義領域を保持し、任意の測定チャンネルとの測定行列を計算 |
| 局在 | NCL の核質／核小体比、区画 summary | 任意分子の分配係数・積算量の分配と、原値／補正値を下流まで一貫して扱う契約 |
| 核小体の形態 | 個数・面積・占有率・離心率の経路 | 最大物体割合、他の形状指標、区画ごとの数・面積と研究出力 |
| 空間構造 | 採用済みマスクと親核の対応 | foci の数・密度、領域間距離・重なり、line／radial profile |
| 陽性率 | `positive_count`・`positive_fraction` の計算契約 | 比較 UI・選択・図・Methods への未接続を確認して完成させる |
| 曲線 | 既測定値の数値取込 | 個体／試料別の時系列、FRAP・観測区間 AUC・派生比の計算 |
| 検出と学習 | 固定 StarDist、Cellpose-SAM、採用済みマスク | 測定対象別の教師・独立評価と、必要指標の誤差・修正負担によるモデル採用 |

計算契約が存在すること、画面から利用できること、保存・統計・出力・replay がつながること、科学的な受入を満たすことを別に記録する。たとえば比較 UI の `comparison-adapter.ts` は陽性率を未接続と記載している。自動背景による補正 summary にも比較・出力側の制限がある。既存の式を重複実装する前に、このような未接続を確定する。

## 3. 対象の定義

核小体全体、GC・DFC・FC 関連領域、NCL 陽性領域、光学的に解像できる foci は別の対象とする。NPM1・DKC1・RPA194 などの区画対応には一次文献の根拠があるが、マーカーの陽性画素が全条件で構造の真の境界を示すとは仮定しない [1–4]。

- 定義用マーカーと測定する分子を分離する。再分布を測る分子自身で領域を定義する場合は、その依存関係を保存・表示する [4]。
- 「陽性画素の集合」と「外周で囲んだ構造」を区別する。穴埋めや円形化で両者を混ぜない。
- 異なるマーカーの領域間では重なりを許す。各区画を一枚の排他的なラベル画像に押し込めない。
- 親核との対応を保持する。GC 関連領域から外へ移った FC／DFC 関連候補を黙って切り捨てない。
- 対応不能、判読不能、検出ゼロ、処理失敗、測定しなかった場合を区別する。個数が決まらない融合領域へ推定個数を割り当てない。
- DAPI の低輝度域、独立マーカー、研究者の判読を照合できるようにする。手法の変更は別 revision とし、都合のよい結論を得るために選択しない。

## 4. 計算するパラメータ

以下は指標の候補と定義。採否と最初に提供する範囲はレビューで固定する。N は親核、R は採用した対象領域、B は比較する参照領域、c は測定チャンネル、I は原画素、b はそのチャンネルの背景、sx・sy は確認済みの画素寸法を表す。

### 4.1 区画別測定と局在

| 指標 | 定義 | 単位・成立条件 |
|---|---|---|
| 面積 | 画素数 × sx × sy | µm²。未校正なら px² |
| 個数・サイズ分布 | 親核に対応した、個別に判別できる物体 | 物体表と親核ごとの集約を両方保持 |
| 形状 | 周長、円形度 4πA／P²、solidity A／凸包面積、長短軸比 | 境界の推定法・校正・端切れを固定。2D 形状を体積や球形度へ読み替えない |
| 面積占有率・最大物体割合 | 対象面積／親核面積、最大物体面積／対象和集合面積 | 分母と対象定義を固定。空・未確定は区別 |
| 平均・中央値・総量 | mean(Ic \| R)、median(Ic \| R)、Σ(Ic \| R) | 原値と補正値は別。補正は測定用背景に従う |
| 補正積算 | ΣIp − 画素数 × b | 負値を勝手にゼロへ切り詰めない |
| 分配係数 | Kc,R,B = mean(Ic−bc \| R) / mean(Ic−bc \| B) | 同じ分子の対象／参照。両平均が正の場合。逆向きの既存比と区別 |
| 区画内信号分配 | Σ(Ic−bc \| R) / Σ(Ic−bc \| N) | 背景・分母の妥当性が必要。signed 補正値の比を自動で物理的な 0–1 割合としない |
| 区画間の面積比 | 全対象の面積比、内側の交差面積、外側にある面積を別に保存 | 分配・移動による境界外の対象を消さない |
| 核内陽性率 | 陽性核／判定可能核 | 陰性対照と判定規則、判定不能の分母を記録 |

核質を参照 B にする場合は、親核から採用した核小体全体の和集合を除く。FC・DFC の一領域 R だけを除いた N∖R は、他の核小体区画を含むため核質とは呼ばない。区画間の比では対象・参照の両方を明示する。

複数の核小体の平均は和集合の全画素から計算し、各物体平均の単純平均にしない。異なる抗体・蛍光体のチャンネル間輝度比を、校正なしに分子数比や酵素／基質比と呼ばない。絶対面積と占有率、平均と総量は別の問いとして出す。

### 4.2 区画の関係と profile

| 指標 | 計算・出力 | 注意点 |
|---|---|---|
| foci 数・密度 | 対応する親領域ごとの数、親領域面積あたりの数 | 解像可能な foci に限定。転写単位数・rDNA コピー数へ読み替えない |
| 重なり・包含 | 対象方向ごとの面積・信号・個数の割合 | 方向、閾値、分母を明示 |
| 距離 | 中心間、最近接、境界までの符号付き距離 | 校正、中心定義、色ずれ、対応不能を保存 |
| line profile | 指定帯域内の原画素のチャンネル別信号と位置 | 線、幅、単位、背景、端切れを保存 |
| radial profile | 採用した中心からの距離 bin 別平均と画素数 | 中心、角度、bin 幅、正規化、欠測を保存 |
| peak 位置差・FWHM 等 | 解像可能な profile の形状を要約 | 光学分解能や投影の限界を超える厚さ・nm 精度を主張しない |
| 共局在 | 指定 ROI 内の Pearson、方向別 Manders 等 | 結合の証明にはしない。配置の違いを一値へ先に潰さない [5] |

多角度の profile とピーク間距離には一次研究の実例がある [2,3]。その測定条件を、異なる光学系や表示画像へ無条件に移植しない。

### 4.3 新生 RNA、FRAP、rRNA 処理

新生 RNA は正式に同定した標識、pulse 時間、対照、独立した定義領域を記録し、その区画内の平均・総量・分配を計算する。標識強度を絶対的な rDNA 転写速度へ読み替えない。

FRAP は個体別曲線を入力とし、raw と既規格化を区別する。背景・参照 ROI、前漂白の範囲、漂白後の基準、実時間と単位を記録する。単一指数が妥当な場合の候補は次のとおり [6]。

```text
F(t) = F0 + (F∞ − F0) × (1 − exp(−k t))
t1/2 = ln(2) / k
mobile fraction = (F∞ − F0) / (Fpre − F0)
```

回復の速さと回復の上限を分ける。plateau を観測できなければ、固定時間／観測窓内の回復量を報告し、最終 mobile fraction と区別する。観測末尾を無条件に F∞ としない。t1/2 は回復振幅の半分までの時間であり、常に漂白前強度の半分へ戻る時間ではない。fit の残差、不確実性、同定不能・不成立理由を返す。FRAP の遅延や円形化だけで粘度・相分離・ゲル化を証明しない。

rRNA は確認したバンド、分母、投入量、pulse／chase、時点、試料を持たせる。前駆体／成熟体の信号比、時点間差、台形法 AUC を記述指標として計算する。閉じた組成の割合と絶対量を区別し、少数時点の組成だけから反応速度定数を確定しない [7]。

WB は検証した直線域・正規化を保持する。細胞あたり、核あたり、タンパク量あたりは異なる分母である [8]。初期段階では新しいゲル解析器を作らず、検証した数値表を試料・実験回で関連付ける。バルク値を各細胞へ複製して n や関連を増やさない。

## 5. 共通計算の構成案

新しい API 名・schema はレビュー後に決める。任意式を実行する仕組みは入れず、登録した計算とその版を使う。

| 構成 | 保存・計算するもの | 所有箇所の案 |
|---|---|---|
| RegionSet の意味 | 定義マーカー、陽性画素／外周、親核、原座標、マスク hash、2D 断面／投影 | 既存領域契約を互換に拡張 |
| 区画とチャンネルの測定行列 | 採用領域 × 測定分子の原値・補正値、局在比 | 共通解析パッケージ |
| RelationSpec | 対象、方向、包含・重なり・距離、対応規則 | 共通解析パッケージの新しい版付き契約 |
| ProfileSpec | 線／中心、帯域、距離 bin、角度、背景、正規化 | 共通解析と保存形状 |
| Curve | 実験・試料／細胞、条件、分子、時間と単位、補正、入力 hash | 数値取込と版付き曲線契約 |
| MetricSpec | 研究上の意味、式、必要入力、単位、成立条件、欠測理由、集約、文献 | 許可した指標の registry |
| 結果の接続 | selector、個体表、実験単位集約、統計、図、Methods、CSV、replay | API・contracts・Web・exports |

検出と計算を分離する。新しい自動検出の完成を待たず、採用済みの手描き・取込・修正マスクから研究指標を計算できるようにする。既存の核検出、親子関係、原画素の保持、版管理を使う。

原画像、表示、検出前処理、測定を分ける。核小体編集は依存する和集合・核質・測定へ、背景変更は補正値へ、実験 metadata 変更は集約・統計へ、色と軸の変更は図へ反映する。保存済みの旧レシピを新式へ黙って変換しない。

現在のチャンネル数制限を超える課題には、契約・メモリ・UI・出力の拡張が必要である。別染色を GFP／NCL として扱ったり、別細胞を同一細胞として結合したりして制限を迂回しない。

## 6. 学習データの利用

運用の境界とローカルの配置仕様は [ローカル研究データの利用](local-data.md) にまとめる。公開コード・公開実画像と、研究室内の非公開データを分離する。

- マーカー定義領域、個々の核小体、DFC 関連領域、FC 関連 foci、全細胞外周を同じ正解へ混ぜない。
- 既存の閾値陽性領域は、その陽性領域定義の参照であり、構造全体のインスタンス正解ではない。
- 表示 RGB は出所と処理条件を持つ別ドメインとして扱い、未加工の単色蛍光原像へ読み替えない。
- crop 内を漏れなく注釈する。判断不能を背景へ落とさず、標準学習が ignore を扱えるとは仮定しない。
- 核小体関連インスタンスの基準は現行 Cellpose-SAM とする。点状候補や ring のすべてに同じモデルを強制せず、古典的候補検出と profile も比較する。
- train／development／final は実験・試料・撮影系列・同一視野の派生を共有しないように分離する。開発に使った資料を未知の最終試験へ戻さない。
- 重み、データ、対象定義、前後処理、推論条件を組にして版管理する。公開済み基盤モデルの既学習データとの重複も記録する。

Cellpose の公式開始例は AdamW、learning rate 1e-5、weight decay 0.1、batch 1、100 epochs。最適値として採用せず、固定版の実装と development で決める [9,10]。既定の `min_train_masks=5` は少数物体の親核 crop を学習から除くため、採用・除外一覧と設定を確認する。新たな教師を繰り返し既存 checkpoint だけへ追加し、過去データの重みを意図せず変える運用にしない。

## 7. 検証と受入

数学的な正しさ、対象の同定、測定誤差、研究者の作業完了を別に評価する [11,12]。

1. **計算**：公開実画像と独立した Fiji 等の参照で原画素・領域・profile を照合する。式だけの検証は開発原則で許容される最小数値を使い、合成細胞像を精度の根拠にしない。
2. **対象の同定**：独立注釈と裁定を用い、precision／recall／F1、IoU、過分割・融合、親子の誤り、判断不能率を記録する。
3. **研究測定**：個数・面積・輝度・分配・profile・曲線指標の誤差を条件別・実験回別に測る。文献と同じ p 値や方向を得る調整はしない。
4. **統計**：細胞・視野・試料・独立処理単位を区別し、欠測・除外・対応を保持する。独立性不明なら記述にとどめる [13]。
5. **接続**：必要入力から計算、比較、図、Methods、保存・replay まで成立し、値から正しい元画像・領域・曲線へ戻れる。
6. **研究者評価**：通常の手法と同じ範囲の課題で、完了・誤判断・援助・修正負担・総時間を測る。推論速度や agent の試験で代用しない。

許容誤差・目標精度・対象条件・評価集合・checkpoint 選択の方法は final を見る前に固定する。目標値は注釈のばらつきと検出したい生物学的差から決める。既定モデル変更や公開は、この受入とは別にオーナーが判断する。

## 8. 実装順序

| 段階 | 完成させるもの | 依存と完了条件 |
|---|---|---|
| M0 設計確定 | 指標一覧、対象定義、式、前提、入力・欠測・集約・出力契約、公開／ローカル境界 | Claude レビューとオーナーの判断を反映。並行作業の境界を固定 |
| M1 区画測定 | 多区画・多チャンネル測定、任意分子の局在・分配、陽性率の未接続 | 手修正／取込領域から計算し、比較・図・Methods・replay まで通る |
| M2 空間測定 | foci の数・密度・関係、line／radial profile | マーカー意味、対応、校正、解像度、色ずれを保存。原像と数値が対応 |
| M3 曲線 | FRAP、観測窓の回復、AUC、バンド派生指標 | 実時間、個体／平均の区別、fit 不成立・plateau 不足を保存 |
| M4 学習・評価 | 対象別教師、現行モデルとの比較、必要指標の測定誤差 | ローカルの私的実験と独立した final。重みの外部公開は別判断 |
| M5 作業の改善 | 研究レシピの再利用、修正の短縮、必要箇所だけの再計算、処理の高速化 | 必要指標を削らず、取込から研究者の確認・図までの総時間が改善 |

数分での解析を目標として測るが、現在その水準に達しているとはしない。高速化は M1–M3 の科学的な計算を保持して評価する。既存のモデル保持等を新規成果として数えず、反復初期化・逐次処理・不要な再実行のどこが支配的かを実測してから変更する。

## 9. Claude レビューと並行実装

レビューでは次を判定する。

- 必要な研究パラメータが不足していないか。単なる指標追加でなく、研究上の問いへ対応しているか。
- 式、領域の意味、マーカー、単位、分母、背景、時間、欠測、集約が整合するか。
- 既存コードを再利用できる箇所と、未接続・新設する箇所が分かれているか。
- 原画素と旧レシピを保持し、API・型・保存・図・Methods・replay まで変更範囲がそろっているか。
- ローカルデータをクラウド開発、公開 CI、Docker build context、デモ、外部 AI へ送る経路が生じないか。
- 追加学習が先に必要な箇所と、採用した領域や曲線から今すぐ計算できる箇所が区別されているか。
- 並行作業で同じファイル・共有契約を競合して変更しないか。

Claude は問題点を重要度、根拠となる節・コード、修正案、判断が必要な事項に分けて PR へ返す。非公開資料をレビューへ添付しない。設計レビューが済むまで、この計画を根拠に機能実装・追加学習・モデル変更を開始しない。

レビュー後の分担案は次のとおり。担当範囲は開始時に worktree とブランチを分けて確定する。

| 担当 | 所有する変更 | 相互依存の扱い |
|---|---|---|
| Codex | 共通計算、指標 registry、領域間関係・profile・曲線、数値検証 | まず M0 の契約を小さい PR で固める。Web 生成型は手編集しない |
| Claude | 研究目的からの操作、ROI・profile・曲線の確認、指標 selector、比較・図の利用導線 | 確定契約を使用し、異なる計算をブラウザへ持たない |
| 契約の統合担当（開始時に一名を決める） | API、OpenAPI、generated 型、保存・出力・replay の接続 | Codex／Claude が同時編集しない。上流契約を先に取り込む |
| ローカルの研究者／管理者 | 非公開データの注釈、入力条件の確認、独立試験、研究者による評価 | private データを開発用 AI や公開 runner へ渡さず、許可された集計だけを共有 |

実装 PR は、計算と薄い UI を一つずつつなぐ形で M1 から進める。二者が全機能を別々に実装して最後に結合する進め方にはしない。各担当の変更は他方が独立にレビューする。マージ・配備・配布は [チーム開発ルール](../../team-development.md) に従う。
