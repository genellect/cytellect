# ローカル研究データの利用

この文書は [研究パラメータの拡張計画](plan.md) のデータ境界と、今後実装するローカル adapter の要件を示す。実データの manifest、配置パス、研究資料名・構成、測定値、注釈、学習ログ、重みを公開リポジトリへ置かない。現時点で製品の学習 loader がこの配置を利用できるという宣言ではない。

## 保存先と外部送信

- 研究室が管理するローカル専用領域を、すべての Git checkout、公開アプリのデータ領域、静的配信、CI artifact、Docker build context、クラウド同期先から分離する。`.gitignore` だけを隔離策にしない。
- 原資料の保全コピーと、そのまま抽出した画像・曲線、表示用派生、正解注釈、split、実行条件を分け、ファイルの hash で関連付ける。元資料を書き換えない。
- 初期状態は外部送信、クラウド学習、GPU proxy、LLM、遠隔ログ、公開・再配布を許可しない。モデルの取得は研究データを扱う工程から分離する。
- 公開開発環境は、出典・利用条件・hash を登録した公開実画像だけを使う。非公開 corpus を CI、開発用 AI、公開デモへ渡さない。
- 非公開の画像・資料から派生した曲線、マスク、埋め込み、特徴量、重み、研究結果も非公開のまま扱う。コードの OSS ライセンスをデータや重みの公開許可へ読み替えない。
- ローカル学習・評価の起動前に、保存済みアカウントや環境変数による自動的な remote inference も無効であることを確認する。環境変数を空にするだけで、製品の別の接続経路まで停止したとはしない。

この境界は既存の [研究データの扱い](../../team-development.md#6-研究データの扱い)、[開発の原則](../../development-principles.md#研究データと検証)、[データ保護](../../security.md) に従う。実際のパスと配備レシートはローカル管理記録にだけ保存する。

## ローカル corpus の役割

次は論理的な役割であり、製品の既存 schema 名ではない。

| 役割 | 保存する情報 | 使用可能な用途 |
|---|---|---|
| source | 保全コピー、原画素・形式・hash・取得条件 | 元の意味と provenance の確認 |
| extracted | 原資料から直接抽出した表示画像・曲線と元の対応 | 対象定義、曲線の演算照合、別ドメインでの形態注釈 |
| candidate | 対象・染色・独立単位・出所の確認状態 | 未確認候補。教師として自動採用しない |
| annotation | 画像座標の整数 ID、対象定義、注釈者・裁定、曖昧領域 | 承認した意味に一致する教師・評価参照 |
| split | source family、試料・実験回、train／development／final | 同じ元視野・別チャンネル・crop をまたがせない |
| reference | 入力曲線と定義を固定した演算参照 | 数値再現。独立な生物学的反復とは区別 |
| training output | 条件、入力 manifest、重み、hash、結果 | ローカルだけでの比較。別許可まで外部公開しない |

最初の作業は、ローカルの研究者が原チャンネル・取得条件・同一視野の派生・試料と独立実験回・既に開発に使った範囲を棚卸しし、評価専用の未使用実験回を確保すること。公開実画像を使う測定機能の開発とは並行する案とし、原像・対象別正解・独立 split を確認するまで学習へ接続しない。

この corpus の演算参照はローカル研究記録として扱い、公開開発の fixture や CI に移さない。開発では登録済みの公開実画像を使い、純粋な式の照合に限り開発原則を満たす最小の数値配列を使う。非公開の曲線値を使わなければ開発できない構成にしない。

画像は未加工の単色原像、表示 RGB、投影、crop、注釈を区別する。TIFF という拡張子だけでは定量用原像と認定しない。表示画像の LUT、バーや文字を本来の信号や教師へ混ぜない。

曲線は個体別／平均、実時刻／点番号、raw／既規格化、背景・参照、観測窓を区別する。カテゴリの点番号だけから秒を作らない。RNA バンドの同定に不一致があれば原記録で確定する。

## 学習・評価への採用条件

1. 使用目的・権利・保存場所・非公開状態が確認されている。
2. 画像と正解が同じ座標で対応し、対象定義・染色・校正・元の処理が確認されている。
3. crop 内の注釈漏れと曖昧領域の扱いを確認し、未確認を背景にしない。
4. 試料・実験回・撮影系列と、同じ元画像の派生が split をまたがない。
5. final はモデル・条件の選択に使用していない。
6. 学習 loader の採否一覧を確認し、少数物体の crop が既定値で脱落していない。
7. 実行の入力・重み・前後処理・環境を固定し、ローカルで記録する。

この条件がそろわない画像は `candidate` のまま保持する。空の注釈ディレクトリや保存済みの閾値領域を、学習可能な正解データが完成した証拠にしない。曲線の演算参照を、画像分割の教師として数えない。

## adapter を実装するときの拒否条件

ローカル adapter は、明示的に選んだ corpus だけを読み、Git／公開配信／build context 内の配置、外部 URL、pickle・任意コード、範囲外の参照や symlink、hash 不一致、未承認の教師、曖昧な split を拒否する。既存の API upload・公開 fixture・クラウド GPU への自動登録は行わない。

ラベルや実行の不備は理由を返す。存在しない原画像、未取得の媒体、未注釈・未承認の対象を補って実行可能に見せない。data-ready、annotation-ready、training-ready、scientifically-validated をそれぞれ区別する。

## 公開前の確認

公開する差分は許可したコード・文書だけを明示的に stage する。元資料・実値・私的パス・画像・manifest・注釈・重み・実行ログが差分、commit、PR、CI artifact、配布物へ含まれていないことを確認する。private なローカル記録の検査は、その内容をログへ列挙せずに行う。
